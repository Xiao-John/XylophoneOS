# 证据完整性契约：单一信任根与平铺根清单

2026-11-01。状态：契约生效；存量报告按第 5 节处理，新报告自本契约起强制。
本契约规定 `docs/reports/` 等证据目录的完整性核验结构，替代此前"回执互相内嵌
sha256"的嵌套引用（近似 DAG），后者在任何字节修订时引发级联哈希重算。

## 1. 单一信任根

工作区字节的完整性由 **git commit 树对象**内容寻址担保，是唯一信任根。
任何文档内的哈希字段都不是新的信任根，只是它的下级快照。

## 2. 三铁律

1. **叶子互不哈希**：报告内的文件（回执、日志、快照、profile、checksums 等）
   不得内嵌其他文件的 sha256。跨文件哈希引用一律废止；确需引用时引用
   路径与语义，不引用字节。
2. **每目录一个根清单**：`manifest.json` 结构为
   `{"version": 1, "files": {相对路径: sha256}}`，覆盖本目录其余全部文件。
   清单不记录自身（无自指、无循环）。
   gzip 等压缩件按压缩后字节哈希。
3. **修改只动两处**：目标文件 + 其所在目录的 `manifest.json`。不允许出现
   "改叶子必须先改兄弟"的顺序约束；出现即违反本契约。

## 3. 校验语义

- 清单校验：对清单中每项重算 sha256 并比较；多余文件与缺失文件分别报告。
  校验器：`tests/report_manifest_check.py`。
- 覆盖如实：没有 `manifest.json` 的目录登记为 `grandfathered`（第 5 节），
  不冒充已覆盖，也不阻塞历史证据的引用。
- 报告被带出 git（发行包、客体拷贝、离线复核）时，根清单随行即完成
  自校验；清单本身的可信度由携带它的 git commit 担保。

## 4. 生成与修订

- 生成/修订只用两步：重算目标文件 sha256 → 更新根清单对应条目。
  工具允许用一次性脚本完成，但产出必须满足第 3 节可校验。
- 证据内容的语义修订（区别于机械脱敏/改名）必须另有工作记录说明动机与
  影响；机械修订（如宿主路径脱敏、文件改名）在转换清单中记录
  旧 sha→新 sha 与规则，转换清单本身也是叶子。

## 5. 存量迁移：老人老办法，新人新办法

- 本契约生效日（2026-11-01）**之前**已存在的报告目录维持原有核验方式，
  冻结原样，**不因本契约强制迁移**；其因修订需要更新哈希清单时，按其
  原有清单结构更新即可（即仍允许原有的互哈希级联，属既有办法）。
- 本契约生效日**之后**新建的报告目录一律执行第 2 节三铁律：平铺
  `manifest.json`，叶子互不哈希。
- `tests/report_manifest_check.py` 对两类目录分别如实报告
  （`compliant` / `grandfathered`），不把 grandfathered 冒充为已覆盖。
- 旧 Dock 报告的 `manifest.json` 是契约生效前的历史格式；校验器只对该明确目录
  检查压缩包和逐成员哈希，结果仍列为 `grandfathered`，并标明不覆盖目录全部文件。
  未登记的新目录不能用旧格式冒充平铺清单。
- 早于本契约的 `issue37_path_hygiene` 旧索引按其原始索引字节精确识别并逐项
  校验；即使附加了平铺清单，仍标为 `grandfathered`。这一识别不豁免路径扫描。

## 6. 边界

- 本契约不替代 git 历史绑定（`docs/history/source_index.json` 以
  `git show <source_commit>:<path>` 校验历史对象，与工作区字节无关）。
- 本契约不授权改写证据的结论、数值与失败记录；它只约束完整性核验的
  拓扑结构。
