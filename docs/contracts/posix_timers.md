# glibc POSIX 定时器受限子集

此实现落实 [Issue #124 的 P1 裁决](https://github.com/Xiao-John/XylophoneOS/issues/124#issuecomment-7150986141)。
定时器是进程内 libc 对象；内核继续只提供已有的时钟、等待和线程生命周期机制。
没有新增 syscall、信号 ABI 或 newlib 私有依赖。冻结 newlib SDK 不因此获得新能力。

## 公共面与时间域

glibc 的 `timer_create`、`timer_settime`、`timer_gettime`、`timer_delete`、
`timer_getoverrun` 支持 `CLOCK_MONOTONIC` 和 `CLOCK_REALTIME`。应用使用标准的
`_POSIX_C_SOURCE=200809L`、`<time.h>`、`<signal.h>` 即可取得声明，不手写类型或常量。

`SIGEV_NONE` 不创建工作线程。`SIGEV_THREAD` 使用实际的 detached pthread 回调。
默认通知方式（空 `sigevent`）及 `SIGEV_SIGNAL` 明确失败为 `ENOTSUP`；
进程/线程 CPU 时间定时器同样不支持。不会因为这些入口存在就宣告完整
`_POSIX_TIMERS` 或信号支持，`sysconf` 的完整选项声明保持原边界。

相对计时使用统一的单调时间，包含相对 `CLOCK_REALTIME` 定时器；墙钟调整不会
改变其已经设定的经过时长。绝对 `CLOCK_REALTIME` 定时器保留墙钟截止点，
调度器在有界睡眠后重新取样。周期从原截止点推进，不从迟到的观察时刻重新起算。
`timer_gettime` 和 `timer_settime` 的旧值始终返回剩余时长。零初始时长解除计时；
过去的非零绝对时刻立即到期。纳秒字段、标志和有符号原生纳秒范围严格校验，
计算溢出报 `EOVERFLOW`，失败不发布输出或替换计时设置。

## 配额、身份与并发

默认每进程 32 个逻辑对象；构建时的私有 `XOS_TIMER_CAPACITY` 可以选择 1–255。
布局不是公共 ABI。句柄只含槽号和代际，不指向可释放的对象；删除后的句柄返回
`EINVAL`，即使该槽已被新定时器复用。代际耗尽的槽停止分配，不能绕回旧身份。
对象耗尽报 `EAGAIN`；删除可用对象后容量恢复。

一个进程最多保留一个调度线程和一个通知回调线程。调度线程使用
`wait_word/wake_word` 和单调绝对期限；重设、删除及回调完成会更新等待序列并唤醒。
回调默认栈为 256 KiB，显式合法尺寸沿用原生 64 KiB–2 MiB 约束；属性在创建时
复制，不保留调用者属性指针。自供栈、显式调度/进程范围、亲和或信号掩码等
原生 pthread 尚不支持的属性真实失败。

回调已提交后只使用复制出的函数和值；删除、重设和槽复用不会让它访问新对象。
因此回调可以删除自己的定时器，删除也不等待用户回调结束。尚未提交的通知在
删除或重设时清除。已经提交的回调可以完成，包括显式 `pthread_exit` 及其 TSD/TLS
清理；调度器确认其 detached TID 已由内核回收后才创建下一个回调。

这个确认使用既有 `sys_thread_detach`，只查询本实现已创建为 detached 的 TID：
活记录返回既有 invalid，回收后返回 not-found。不会改变活 detached 线程的属性，
不会读取已释放的 TCB。调度线程自己退出后的短暂回收窗口内，新建线程通知对象
可以返回 `EAGAIN`，不启动第二个调度线程。所有线程通知对象删除且回调回收后，
调度线程正常退出；单纯的 `SIGEV_NONE` 对象不阻止它退出。

## 通知合并与 overrun

每个线程通知定时器只保留一个待提交通知和饱和的到期次数。一个回调正在执行、
清理或因进程四线程额度不足而无法创建时，后续到期合并到待通知计数，
不丢弃、不无限创建工作线程。回调创建失败后以有界睡眠重试；槽间循环选择避免
单一高频定时器永远占据通知机会。

成功提交一个回调时，`timer_getoverrun` 更新为该通知包含的到期次数减一，
上限 `INT_MAX`。正在执行的回调所属通知与下一待提交通知分开计数。重设将计数
归零。`SIGEV_NONE` 没有异步通知，overrun 为零。这是本受限后端明确定义的线程
通知合并语义，不是假报始终为零，也不冒称已实现 POSIX 信号排队规则。

## 进程生命周期与资格

当前 fork 仍只接受原有单线程条件；子进程在用户 atfork 回调之前清除定时器，
保留代际以拒绝继承的父句柄。父对象不变。成功 exec 替换进程映像，正常 exit 和
强制进程终止沿用既有线程/页面回收规则。需要仅由应用线程决定结束的程序应在
最后应用线程调用 `pthread_exit` 前删除自己的线程通知定时器；内部调度线程
也是实际存活的线程，不会伪装成已退出。

生产核心的确定性宿主测试见 `tests/glibc_timers_host.py`，其中替换时钟和线程
平台调用以控制跳时、资源不足及 native reap 窗口；它不替代客体资格。
真实 SDK/客体矩阵由 `tests/glibc_timers_guest.py` 绑定实际 SDK、内核源码、镜像、
ELF 和两个 Shell 入口，记录执行结果及资源恢复。长时间随机压力、物理校时、
共享 libc 配置和冻结 newlib 兼容层不因静态 glibc 测试通过而自动获得资格。
