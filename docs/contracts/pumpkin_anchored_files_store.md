# Pumpkin 的 files 快照与独立代际接合

`anchored_files_store` 是 Pumpkin 进程内的存储适配器。它接收 [files 独占槽租约](pumpkin_files_client_probe.md) 的 `test_slot_io` 及独立 `generation_record_io`，复用 `snapshot_publication` 提供原有 `store_api`。调用方须一直持有同一安装域的受信代际端点及唯一 files 写入租约。两个输入各由实际授权者绑定，不能从账户数据、磁盘内容或请求名称推导。

## 提交和恢复

1. 从独立源读取当前的完整记录，按修订号定位槽，解析现有 `PUMTEST1` 框架并校验 P0 快照。没有合格活动槽时停止，禁止扫描另一个槽作为备选。空库只有在独立源明确返回已配置空记录时成立，启动流程仍需显式初始化。
2. 检查候选修订后，按原 files 约定写入非活动槽。files 对原始字节同步并回读，随后 `snapshot_publication` 重新读取候选槽以检查其 P0 长度、域、修订和摘要。独立源此时才可比较旧记录并发布新记录。
3. 仅在独立比较发布成功时更新进程内账户。结果未知或冲突会使核心停止，清空当前会话。重启从独立记录恢复。丢失回复不能作为重发提示。若只在非活动槽暂存或读回时失败，活动槽与独立记录不变，核心保留原账户和会话。files 租约失效仍由守护进程的后端存活检查处理。

共享槽框架只处理标识、长度、保留字段及零填充。Pumpkin 验证 P0 内容及其归属，独立源保存已提交版本，files 持有原始块状态。原可重启测试继续按本机双槽规则运行。新适配器需要实际独立源，当前可重启测试模式未选择它。

## 客体接入条件

sys81、sys84–86 认证客体内的通信参与者，现有接口不提供到宿主的端点。sys112 当前设备授权路径没有独立的客体到宿主记录设备。当前 COM1 是调试与终端设备，sys82 要求真实启动监督器把端口授予处于准备状态的直接子进程。授予会脱离原控制台，现有串口测试输入和 xsh 输出不能直接充当独立服务的认证通道。

下一阶段可以为显式 QEMU 配置接入独立字节流及用户态监督代理。启动授予需能区分真实代理和测试控制台，绑定唯一 Pumpkin 实例、当前 files 租约及安装域。守护进程的后端存活检查应同时跟踪 files 与代际端点，任一失效时停止服务。代理只转发独立记录的读与比较发布，交付后失去回复按结果未知处理。宿主端沿用 [独立代际提供者](pumpkin_host_generation_authority.md) 的私有根目录，位于 guest 盘和虚机快照范围外。共享设备分配或通信协议的实现另行评审。

[组合测试](../work_log/955ab8a3_pumpkin_independent_generation_files_store_adapt.md) 用实际 C++ 核心、适配器、实际宿主提供者和同步的一次性槽文件验证了新进程恢复、吊销、失去回复以及旧镜像拒绝。宿主测试的槽文件回调模拟 files 租约已取得后的读写语义。客体已授权的 files 服务与宿主独立源的端到端链路尚待运行。
