# Pumpkin 独立代际的无界面开发配置

`--pumpkin-anchored-probe` 绑定一次性 QEMU、不可变启动映像、专用 COM1 字节流和盘外宿主代际目录。真实 Pumpkin 守护进程通过 [独占 files 租约](pumpkin_files_client_probe.md) 写槽并经 [存储适配器](pumpkin_anchored_files_store.md) 使用独立记录。账号状态留在 Pumpkin，原始块操作留在 files，用户态代理独占串口。

## 受信启动与退出

1. 宿主测试器固定系统清单、代码和工件并创建新的 QEMU 子进程。QEMU 的串口仅连接该子进程的继承管道。监控句柄在独立私有目录，客体不安装网络设备。在该范围内，客体信任 QEMU 的物理串口另一端，宿主信任验证过哈希的内置客体启动链。每次启动创建新管道和 QEMU，使用相同盘外权威记录。该连接建立在本地受控拓扑和启动映像上。
2. 设备交接前，宿主测试器只向启动控制台发送 `run`。启动监督器先检查持久恢复门，在启动 UI、包安装和 shell 前进入专用流程。监督器从内置映像启动 `p2_anchor_proxy`，在子进程仍处于准备态时创建双向 sys81 私有通道并独占授予 COM1。内核交接成功后原调试路径不能访问 COM1。代理核对内核给出的实际授权者、双向通道的控制者、当前对端和收发方向，再以现有 16550 驱动绑定 IRQ4。就绪帧在交接完成后发出，宿主收到才进入代际协议。
3. 真实监督器为唯一的内置 Pumpkin 实例和代理创建第二对 sys81 通道。代理从与监督器配对的真实通道得知守护进程，守护进程从专用启动管道获得 files 租约和代理身份。守护进程仍核对内核认证的实际父进程及真实双向通道。端点失效阻止新的账户操作，结果未知停止服务并拒绝自动重发。注册端与普通身份客户端仍使用各自原有角色。
4. 守护进程退出并由监督器回收后，监督器才通过自己的端点报告测试结果。代理等待宿主确认，随后关闭 UART 中断。如协商失败或超时，测试失败。正常测试退出由宿主在核对结果后用 QMP 结束该 QEMU 实例。代际记录和测试盘已在确认提交前各自同步。

## 专用消息

本开发配置使用固定 144 字节 little-endian 帧。16 字节头由 `PKA1`、u16 版本 1、u8 操作、u8 结果、u64 序号构成，后接两个 64 字节代际记录。记录为 16 字节安装域、u64 修订、u64 长度及 32 字节摘要，空值全零。首次就绪序号为零，其余从 1 递增。客体每次串口收发和 IPC 使用六秒的绝对单调期限，宿主完整帧接收期限为十二秒。设备资料错误和无效帧停止代理。

操作为就绪、读取、比较并发布、结束。就绪回复指定三个预定测试阶段之一。读写只在已建立的专用线路内处理，比较依据完整旧记录。读不到明确空记录、当前槽无匹配摘要、端点丢失或提交不确定，均通过现有核心失败路径处理。结束标记来自真实监督器。线路只保存代际元数据，从不传凭据、账户数据或 shell 命令。

## 旧盘快照

守护进程先同步并读回修订 2 的槽。宿主持久提交独立代际后，通过 QMP `stop` 并核对状态为 `paused`。客体的单调时钟由定时中断递增，暂停期间的宿主复制和核对不消耗客体回复期限。宿主复制并同步完整工作盘，核对源盘与副本的摘要，再恢复运行并发送修订 2 回复。收到回复后客体才能开始导致修订 3 的吊销。`--slow-snapshot` 在暂停区间注入七秒宿主等待，仍要求三个启动阶段全部通过。

测试使用真实 sys63 生成一次性凭据，原始密钥仅在客体进程的私用 IPC 和测试内存流转。重启验证无需携带旧密钥，登记端查询确认相同账户已吊销。旧盘恢复只回滚工作盘，不复制宿主代际目录。该配置的范围是由宿主监督器保管盘外权威记录的本地开发测试。生产凭据和物理断电资格仍需验证。

在同一代际配置上，可显式启用独立持有者和读资源授权的 [原生凭据接入](pumpkin_native_login.md)。
