# Pumpkin 可重启守护进程测试

`--pumpkin-durable-probe` 在一次性工作盘上运行真实 Pumpkin 守护进程。受信监督器
只把 [files 独占槽租约](pumpkin_files_client_probe.md) 授予不可变引导映像中的守护
进程。Pumpkin 复用 P0 账户核心和 P1 IPC 服务。租约失效时服务停止。公开文件协议、
系统调用、默认镜像与生产安装入口沿用现有配置。

## 测试盘上的本地版本选择

每个 4608 字节槽包含 16 字节测试框架、P0 快照和零填充。框架前 8 字节为
`PUMTEST1`，其后为 little-endian u32 快照长度和保留 u32 零。P0 校验覆盖账户
库自己的头与记录。测试检查固定安装域、完整摘要、长度、槽位奇偶和版本。

只有明确初始化模式且两个槽全部为空时才配置新库。普通启动直接读取。只有一份
有效记录时须为版本 1。两个已用槽必须各自通过校验且版本连续。发现损坏、错误位置
或者缺少预期的上一版本时停止，保留介质供诊断。

变更先比较当前版本，写入并确认另一个槽同步和读回，再重新扫描两槽核对新记录。
任何不确定写入导致身份服务停服，客户端不能假定未执行。普通重启由实际观察到的
两槽结果恢复。版本与数据位于同一可替换介质，整盘旧拷贝会共同回滚。生产
[受保护代际发布器](pumpkin_snapshot_publication.md) 和独立防回滚来源保持单独验收。
本测试不承诺撕裂写入或物理断电下的原子提交。

## 凭据和双 Shell 验证

测试监督器在 xsh 启动并管理实际守护进程。登记端调用真实核心创建账户，凭据来自
sys63。守护进程只保存 P0 校验摘要。测试监督器把凭据保存在进程内，测试 dash 使用
其继承的私用标准输入管道获得凭据。进程参数、串口及测试盘的公共目录仅包含测试
入口、脚本和执行文件。测试客户端及监督器在使用后清理自己的明文缓冲。内核邮箱、
故障采集和生产凭据输入仍须独立审计。

xsh 路径覆盖创建、错误和正确认证、守护进程重启后仍能认证、吊销及旧会话失效，
再启动后保留吊销。dash 真正启动普通客户端，对恢复的账户执行正确认证和注销。
完整 QEMU 重启时不保存测试密钥，重新授予的登记端确认原账户依然吊销，且读回不
改变盘字节。完整客体重启后用同一密钥执行认证尚未运行。真实账户登记、分发、
轮换输入和恢复流程仍待部署资格。
