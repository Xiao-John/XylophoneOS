# Pumpkin 受信 files 客户端测试

`--files-private-client-probe` 使用 [files 私有槽](pumpkin_files_private_region.md)，
允许受信启动者向内置测试客户端授予读取或写入能力。沿用公共 FAT32 前缀校验。槽内
写入与读回由 files 实现，账号格式由 Pumpkin 测试客户端处理。该配置不填充前一轮
内部槽自检的固定字节，两种测试构建分别运行。

## 授予和撤销

- files 从 sys22 得到内核启动时的两端句柄，再核对 sys27 枚举中的真实启动监督器会话。
  授予请求必须由这对专用端点到达。一般文件会话维持原有请求语义。
- 测试监督器只启动内置 `p2_store_probe` 映像，并通过现有加载器的标准输入路由给它
  一端私用管道。监督器申请授予时提交真实启动得到的进程编号。files 在 sys27 核对
  该进程的父身份，再创建专用 sys84 端点，并核验两向对端。
- files 经真实启动控制端返回授予。监督器用独占的管道交付端点，客户端再次核验
  内核对端。直接启动同一程序缺少这个启动管道，立即拒绝。名称和请求中的 PID
  或句柄仅用于定位，普通启动不产生存储权利。
- 同时只允许一个读取或写入租约。读取租约只可读槽，写入租约还可暂存和提交。
  租约绑定到由 files 持有的端点。成功 exec、退出、断连、控制端失效或 30 秒
  到期时回收租约，并清空未提交暂存。files 退出时内核关闭对应通信对象。
  重启、相同 PID 的新映像或槽位复用都需新授予。

## 测试内部线路

编码为 little-endian，固定宽度字段在 `src/user/services/files_private_lease.hpp`。
启动控制授予请求 24 字节，回复 40 字节，含测试标识、版本 1 及目标进程。
读取为 1，写入为 2。保留字段须为零。授予控制消息只进已核验启动会话的分支。

专用端点请求 2336 字节，回复 2328 字节。版本为 1，序号从 1 连续递增。
操作 1 至 5 分别是读取、开始写入、顺序追加、提交、放弃。槽编号为 0 或 1，
每槽 4608 字节，每次读或追加最多 2304 字节。请求中未使用的字节为零。
坏帧、旧序号或关联端点失效使连接关闭。预算从回复入队后计算，槽在 500 毫秒后仍占用
时回收连接。普通文件头、公共操作号、内核和分发 SDK 均沿用现有契约。

开始和追加只修改租约内暂存。完整提交需要两段写入、块同步和完整读回一致，通过后才
返回成功。写入、同步或读回失败时返回结果未知。客户端送出请求却收不到核验回复时
也是结果未知，测试客户端退出，避免重新发送。租约退出后中断的暂存仍保持原槽。
files 不解释槽数据中的账户记录、位图、版本和凭据。

## 资格范围

客体序列使用一次性 FAT32 工作盘。直接启动测试客户端时，程序拒绝访问。通过监督器
取得权限后写入并读回合成 P0 快照。随后中断未提交暂存，再以只读授权校验快照。正常停止 QEMU 后从
同一盘重启，重新授予并再次读回。此项证明受控读取、写入和普通重启存留。独立持久
代际、提交中断或物理掉电资格由后续测试建立。合成快照只有吊销记录，尚未接入真实
凭据生成、发放、轮换或账户库恢复服务。
