# files 服务私有存储区域

本轮在隔离测试配置中为 files 实现两片无路径的固定存储槽。只有内核启动的 files
进程持有现有原始块读写权。文件服务管理介质和分区边界，Pumpkin 继续管理账户快照、
凭据和会话。[账户格式及授权](pumpkin_identity.md) 与 [发布器](pumpkin_snapshot_publication.md)
沿用各自契约。

## 介质与访问边界

`scripts/build.py --files-private-storage-probe` 产生须使用专用工作盘的测试系统。
布局从常规无分区 FAT32 工作盘扩展，原 FAT32 体积是可公开访问的前缀。追加的 19
扇区由一个布局扇区和两个各 9 扇区的对象槽组成。最小公开空间为 512 MiB，整个设备
须处于现有 ATA 支持范围。

布局扇区从设备几何计算位置。其前 24 字节依次为 `XOSPRIV1`、u32 版本 1、u32 槽扇区数
9、u64 公开扇区数，整数为 little-endian，其余字节为零。主、备 FAT32 启动扇区必须
均声明匹配的公开尺寸、512 字节扇区和无分区前缀。元数据缺失、重叠或几何超限时
拒绝挂载该测试映像，测试区域保持原字节。

FatFs 的 `disk_read`、`disk_write` 和 `GET_SECTOR_COUNT` 只看已验证的公开前缀。
公开 block benchmark 使用同一范围，也只返回字节计数。槽位没有公开路径，因此目录项
解析、短名或长名、普通打开、重命名和替换都不能指向它。普通路径和既有 file v2 协议
保持原用法。内核继续拒绝普通进程调用原始块读写。系统原有默认构建、工作盘创建命令和
文件布局保持兼容。

## 同步与资格

读取和写入按现有块调用最多八扇区分两段。写槽在两段均成功且显式块同步成功后返回。
sys25 经现有 ATA `FLUSH CACHE`（0xe7），驱动等待 BSY 清除并检查 ERR。更深的设备
缓存、物理断电和撕裂写入仍需硬件和故障注入验收。布局扇区、两片数据槽及 FAT 前缀
相互独立，整槽写入可以部分失败。调用方必须通过单独的写者租约、发布记录和读回校验
确定选中版本。

测试构建在受信 files 进程内写入两种固定测试数据，按启动次序验证保留和读回。普通
调用者没有控制接口。系统通过已有公开操作检查目录正常、普通文件可读写以及直接
块访问被拒。停机试验在来宾同步确认后强制结束 QEMU，随后以同一私有盘重新启动。
该条件包含完整的 VM 进程退出，宿主和设备缓存仍在。

生产配置还需要可信启动者绑定 Pumpkin 客户端实例，提供独占写者及确定性错误。
可离线替换工作盘时，发布代际要由独立受保护来源提供。槽本身不会防止持宿主盘权限的
操作者查看或回滚字节。本轮没有把账户库或关键凭据放入这两个测试槽。
