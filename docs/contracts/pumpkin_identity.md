# Pumpkin 原生身份服务 P0

基线为 `9f7a9a0f`。本文件定义用户态身份核心、账户库编码与受信适配器的边界。
P0 完成宿主运行和 x86-64 独立目标编译。[P1 客体测试 profile](pumpkin_daemon_p1.md)
记录实际 IPC 适配与当前资格。持久客体存储后端、正式登录程序和 Mobius 接入待实现。

## 身份与认证

- 一个安装域使用一个由受信初始化流程产生并保存的 128 位标识。账户身份由安装域和
  64 位账户序号组成。序号从 1 递增，账户吊销后保留其序号与名字。库的容量为 64 条
  记录，含吊销记录。容量耗尽时拒绝新账户。
- 登录名为区分大小写的 1–32 字节 ASCII，小写字母或数字开头，余下可含
  `.`、`_`、`-`。它只用于查找。同名账户处于活动或吊销状态均拒绝创建。
- 创建和凭据轮换由具备专用登记权限的连接发起。P0 仅支持服务通过受信熵源直接
  生成的 32 字节随机凭据。摘要为
  `SHA256("xos.pumpkin.enrollment.v1\0" || realm || LE64(account_number) || key)`。
  持久化仅保存校验摘要。写入确认提交后，生成的凭据才随本次操作返回一次。熵源失败、
  全零输出或轮换重复当前凭据均拒绝。登录时不存在、吊销和凭据错误返回同一个拒绝状态。
  各路径均执行摘要校验，账户查找时间没有常数时间保证。
  该凭据有原始字节长度约束，服务无需处理人工密码。人工密码接入前须单独冻结口令派生、
  限流、密钥更新及恢复规则。
- 受信登记端具备创建、按精确名称查询、轮换和吊销的能力。查询返回账户身份与吊销
  状态。轮换保留身份和所有权，成功后结束该账户全部会话。吊销同时把校验摘要清零、
  结束该账户全部会话，且该身份不再接受认证。登记端需要受控分发凭据，其权限也允许
  轮换后凭新凭据登录。凭据传递应走受保护输入和 IPC，日志、参数、故障包及诊断输出
  排除凭据和包含它们的缓冲区。

## IPC、会话与拒绝边界

内核认证的是进程主体和持有的通信对象权利。核心串行接收由受信适配器提供的连接
和单调时间。提供请求正文的是该连接的已认证内核对端，连接编号和角色由服务端保存。
自报 PID、名称、UID/GID、可见端点名和会话号单独均不授予权限。

计划用 [sys84–86 端点](ipc_endpoint_lifecycle.md) 接普通客户端。名称只用于发现，
客户端从受信启动链取得服务绑定并核验两个方向的对端，服务亦核验接受的两端属于
同一对端。登记端只走启动链预先配对的专用控制端点，服务端对固定端点绑定登记角色。
对端认证失败或专用端点缺失时拒绝相应操作。若改用 [sys88](ipc_v1.md)，要用受权
句柄与授权者设置的 badge 建立绑定，只转授客户端所需的 call 权，核验授权链并补齐
逐对端结束的通知或回收策略。PID、badge 和可发现的名称均不可替代受权对象。

连接、会话编号由服务分配，包含本次服务实例的 128 位随机代际与单调序号。同一连接
最多一个有效登录会话，登录成功后才能使用会话号，操作时同时校验连接绑定与会话代际。
普通客户端额度为 16，另保留一个受信登记连接。连接从接受起 30 分钟到期，其会话一并
回收。适配器应使用 sys46 单调时钟，在处理完整请求后采样，并定期推进到期清理。
时钟回退使核心停止提供服务。主动注销只结束本连接的当前会话，可以重新认证并取得
新编号。连接失效触发回收。成功 exec、退出或 fault 由实际端点关闭事件接入该路径，
失败 exec 保留原连接。fork 后的主体需另行接纳和认证。服务重启加载持久账户并分配新
代际，全部旧连接和会话均失效。

消息递交前取消与递交后的结果未知遵循原 IPC 契约。已接受的写账户操作可能在回复
前提交，客户端不得自动重发。适配器需绑定有限处理期限和回复预算，清理失效连接的
待回消息，请求及响应临时缓冲应尽量缩短凭据在内存中的驻留。P0 的核心直接清理自己
持有的生成凭据和认证摘要缓冲。端到端缓冲、寄存器和故障捕获路径仍需审计。

## 资源归属

P0 核心已实现所有者规则的交集判断。资源服务提供实际对象键、该连接可执行的操作，
以及同一对象的所有权记录与策略。对象键由资源注册域、对象序号和对象代际组成，
所有者记录包含完整 Pumpkin 账户身份。执行须同时满足以下各项：

1. 请求连接及会话当前有效，操作集合为已知非零子集。
2. 当前授权绑定该连接和目标对象，所有权记录绑定完全相同的对象代际。
3. 账户身份等于所有者，每一请求操作同时包含在对象权利和所有者策略中。

资源服务继续执行自己的命名空间、只读、后端及配额限制。交集检查应在实际资源操作的
授权点完成，不导出可以跨连接或在吊销后复用的许可。跨进程消费需要单独定义并验收可信
绑定与并发撤销边界。P0 实现不写磁盘上的资源归属，所有者记录必须由可信对象服务提供。

POSIX UID/GID 是将来的兼容投影，UID 0 不增加内核权利。当前核心没有 UID/GID 输入，
也没有 root 旁路。FAT 中的合成 UID/GID、大小写别名、路径、目录位置以及仅在一次
服务期间稳定的 inode 都不足以恢复持久归属。新后端只有在拥有跨重启稳定、删除后代际
不复用的对象键和受保护的归属元数据时才可写入原生所有权。迁移须先对每个对象和账户
验证旧键，原子地提交新键与归属或保持旧绑定。路径可用来定位迁移输入，不能独立配对。
xypm 的包文件归属属于安装事务，继续按其既有账本跟踪。

## 账户库和持久提交

内部快照格式 v1 全部整数为 little-endian，输出最大 4432 字节：

| 区段 | 格式 |
| --- | --- |
| 48 字节头 | `PUMPKIN\0` 8 字节、格式版本 u32、总长度 u32、安装域 16 字节、提交版本 u64、记录数 u32、保留 u32=0 |
| 每条 68 字节 | 名长 u8、吊销标识 u8（0 或 1）、保留 2 字节为零、32 字节零填充登录名、32 字节摘要（吊销后全零） |
| 32 字节尾 | 前面全部字节的 SHA-256，用于识别损坏 |

记录顺序定义账户序号。版本从 1 起，每次变更加 1。加载校验安装域、长度、格式、
版本、校验和、名字及唯一性。校验和属于完整性检查，存储访问控制和防回滚由后端提供。
首次配置必须由受信初始化者在明确空库上执行，已存在的库拒绝覆盖。缺失、损坏或
安装域不匹配均阻止启动。

后端须持有独占写权并实现按上一提交版本替换的原子操作。可选的具体实现是服务私有的
双快照槽和独立提交记录。先完整写入并同步非活动槽，再读回检查版本与摘要，随后
持久发布引用该槽、版本及摘要的提交记录。发布本身需要后端已验证的原子性与同步语义。
恢复只接纳有有效提交记录且完整匹配的快照。发现提交记录或其指向的快照无法解释时
停止服务，保留原件供离线恢复。存储配置若允许回滚或离线写入，须在受保护位置锚定
已提交版本与安装域后才能纳入部署资格。备份恢复须保持已发序号与吊销状态。旧快照
只能作为离线迁移输入，经归属核对后才可进入另一个安装域。

运行时仅在后端确认提交后发布内存状态并返回新凭据。已确认没有提交时保留原账户和
会话。版本冲突或结果未知时停止服务，清空连接及会话，等待恢复可信的已提交版本后
重新启动。登记端用查询确认曾发起的创建是否已提交；如果回复丢失，使用显式轮换
重发一份新凭据。账户库不由可写工作盘的 pathname、普通 chmod 或 xypm 维护租约
保护。基线的块设备授权为粗粒度，实际 FAT 及块同步行为也不足以直接声明满足此契约。

## 验收

宿主 fixture 调用生产核心，注入有界存储与熵源。验收覆盖账户创建与错误认证、连接
和对象隔离、会话失效、配额、账户库校验、写入失败、结果未知以及重新加载后的身份
稳定性。客体阶段还须验证真实端点的主体、成功/失败 exec、服务和客户端崩溃、磁盘
中断/满盘/损坏，确认凭据不会随诊断暴露。资源服务、安装和登录客户端接入后按各自
权限范围执行负向检查。可从 Shell 启动的工具分别记录 xsh 与 dash 证据。
