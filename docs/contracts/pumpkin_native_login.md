# Pumpkin 原生凭据接入

显式 `--pumpkin-anchored-probe --pumpkin-native-login` 在盘外代际开发配置中启用原生登记和独立持有者。启动者、files 私有槽、Pumpkin 及 COM1 代理的信任关系沿用现有开发配置。普通镜像的启动、SDK 及公开操作保持原规则。 [盘外代际](pumpkin_anchored_guest.md)

## 可信交付

1. 监督器在发布凭据之前从带完整回执的内置映像启动 `pumpkin_holder`。持有者没有继承标准输入、输出、错误输出或普通 shell。其启动参数只有程序名。
2. 持有者以现有 sys84 与真实父进程配对，通过临时会合名称交出该对的父方端点。持有者核对会合对端是内核认证的真实父方。监督器先核对会合对端，再将父方端点的两方向与实际启动所得进程核对。会合名称只用于发现。原始凭据从不在会合对传送。
3. 监督器使用真实 Pumpkin 的独占登记端创建账户。核心使用 sys63 生成凭据，在现有 files 独占槽与盘外代际都确认提交后才返回。启动器在已核验的私用端点传送一次固定大小的版本、账户身份、可信 daemon 对端、名称和凭据。持有者确认消费后，监督器以同尺寸无秘密帧覆盖发送槽，并用普通登记读回替换此前携带凭据的回复槽。持有者只用新连接的普通角色登录，在认证成功后立即用同尺寸的身份请求覆盖认证发送槽。
4. 私有控制每次交换使用五秒单调期限；未知、畸形或未收到的结果终止本次交付。调用方不自动重发凭据或登记。已承认登记后交付失败时，按既有登记查询核对持久版本，再显式轮换补发。用户态在正常返回与错误路径清理凭据工作缓冲。现有内核关闭端点会重置邮箱，丢失消费或覆盖结果时关闭相应端点。核心快照只保存校验摘要。代理串口只承载原有代际消息和本配置的无秘密结果码。

## 普通会话与资源交集

持有者通过命名服务连接 Pumpkin，并核对该普通端点的内核对端与私用交付提供的可信实例一致。登记角色只在启动时真实父方的专用端点接纳。普通持有者即使登录也不能读取登记接口。同账户在另一条连接上的有效认证无法复用前一条连接的会话或资源权利。

开发配置在原私用 daemon 消息中启用 `grant_login_resource` 与 `read_login_resource`。登记授权包含完整对象拥有者 identity、持有者及准确的 daemon 方初始普通端点对。该对通过实际内核对端验证。资源读取还需匹配授权端点、现有 `service_core` 绑定的活动会话和 `sealed_blob` 持有的所有者标签。拥有者在同一端点上的授权只适用于本次 daemon 实例的单个只读封存对象。使用真实 files 会话创建并封存对象，读取返回该对象的四个普通数据字节。底层 files 句柄由 daemon 持有。账本吊销提交后立即阻止旧会话和旧凭据，其后只读资源检查亦失败。持有者正常退出时，凭据内存、普通会话和私用端点均回收。

两个操作只在该显式配置内启用，沿用既有私有请求和回复尺寸。登记授权的请求保留 16 字节固定描述，包含 u64 对端与两个 u32 端点。读取请求的 token 为当前会话，成功回复数据位于原有 32 位载荷字段。失败回复继续清零附加字段。普通候选不接纳这两个操作。

## 配置范围

开发启动流程只负责当前独立持有者和临时封存对象。物理控制台的交互验证、物理设备的独立代际来源和整个系统的凭据残留审计仍需各自验证。普通用户或 shell 客户端不需要获得登记端点。持久资源所有者标签、通用文件所有权及 xsh/dash 登录计划留在资源与身份契约。 [资源服务](pumpkin_resource_service.md)

专用宿主入口已验证用户自己保管并在全新虚机提交同一份凭据。 [用户凭据领取和提交](pumpkin_user_login.md)
