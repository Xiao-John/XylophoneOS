# Pumpkin 资源服务授权

当前实现是同一串行循环内的读写授权验证。跨进程交接是后续接入契约。独立代际已有宿主开发实现，客体接入仍待专项验证。

## 主体和对象的交接

现有 files 使用 sys27 取得内核绑定的文件会话。服务按该会话查找句柄、打开描述、访问方向和实际文件对象。Pumpkin 通用端点的 sys84 查询只对该端点的参与者可用。Pumpkin 与资源服务各自核验自己持有的内核端点，通过受信的服务间端点关联各自看到的连接。

1. 受信启动者选择真实的资源服务及 Pumpkin 实例，为两者交接专用双向 sys84–86 端点。两边用各自可见的内核对端核验启动授予及两端归属。启动关系只用于核对授予链。服务注册域和授权席位归入这一授予，服务重启重新授予。可沿用 [files 私有租约](pumpkin_files_client_probe.md) 已验证的启动流程。
2. 客户端在已认证的 Pumpkin 连接上请求关联。Pumpkin 生成绑定该连接、会话及目标资源服务的一次性短期请求号。客户端通过自己的真实资源连接递交请求号。资源服务从内核文件会话或通用端点核对发起进程，为当前连接分配有界、同一服务代内不复用的连接号。它通过专用端点向 Pumpkin 确认请求号、真实对端和资源连接代际。Pumpkin 比较两侧的真实主体，检查待关联会话及其本地端点仍有效后消耗请求号。两个服务保存自己的实际会话绑定，并在各自的授权点检查连接仍有效。可见名字、客户端自报的字段和裸 PID 均不能建立关联。成功 exec 使通用端点失效、文件请求 token 更换，同一 PID 继续持有普通文件描述时也需重新建立绑定。失败 exec 保持当前绑定。fork 取得的原有描述本身不能传递 Pumpkin 会话。
3. 提交操作时，资源服务从当前客户端的句柄表解析显式操作，在同一对象和打开描述上核验访问方向，绑定当前对象标签。它在受保护的服务间端点上将一项确定的操作交给 Pumpkin，包含服务实例、资源连接、请求序号、对象键、当前会话和服务查得的权利及标签。Pumpkin 核验此关联和所有者交集，回复只适用于该端点上的同一序号、对象代际及操作。回复由资源服务一次性消费，应用仅得到操作结果。

权限依赖实际端点、发送者角色及当前对象。跨进程接入须限定端点队列、连接数和单次负载，拒绝未知版本、越权操作和过期请求。服务停止或控制端点消失时停止接纳并回收绑定。此阶段没有分配消息号。

## 服务管理的所有者与撤销

资源服务保存标签，键由资源注册域、对象序号和代际组成，值由完整的 Pumpkin 安装域与账户编号以及允许的操作位组成。创建受保护对象时，在已有创建权限和当前已认证账户的基础上，原子提交对象及初始标签。缺少标签、代际不匹配及权限不足均拒绝。资源服务对命名空间、句柄、只读约束、配额和实际数据继续负责。POSIX UID/GID 和 mode 按各自兼容层的语义处理，无特殊 UID 旁路。

同一活动对象的别名和重命名使用同一标签。删除后即使底层槽位或公开名字被复用，也分配新对象键。资源服务须在所有指向受保护对象的访问路径执行同一检查，包括别名、dup 和转交描述。涉及多个对象或命名空间的管理操作需要另行定义其完整授权条件。当前 files 可用目录项位置归并别名，服务内的 `st_ino` 也能跟踪活对象。目录项位置与合成 inode 经重启不构成持久标签。只用当前 FAT 实现时，未来测试应限定于明确登记的运行时对象。跨重启启用归属要求有稳定且不复用的对象标识，并验证对象和标签的原子提交以及重启恢复。现有 file v2 和 POSIX 文件处理流程继续适用于普通文件。

Pumpkin 核心在检查当下串行决定是否接纳一次操作。先到达核心的注销、有效吊销、连接到期或失效，阻止其后的授权。有效吊销在账户版本提交后生效并结束该账户现有会话。若核心先接纳某项操作，该次操作可在同一对象代际上完成。资源服务在等待期间固定准确的对象与打开描述，在执行前再次确认本地权利及端点仍有效，若失效则放弃操作。需要变更同一对象时，以该固定引用或资源服务内同一串行边界协调。客户端在交付后丢失结果时按结果未知处理，避免自动重发有副作用的请求。服务重启使旧实例的关联和在途许可失效。

`resource_dispatch` 在同一循环中运行这条授权路径。受信资源解析器拿到已绑定连接和句柄，自行提供打开描述、内核或资源权利与所有者标签。授权成功时按准确的打开描述和实际对象执行一次操作。宿主测试检验同一对象的不同打开描述、其他连接携带已登录会话、其他账户持有原生权利、两个权利掩码、缺少标签、旧对象代际、重新认证、注销和吊销。启动交接、native exec/fault 与跨进程在途顺序留给真实 guest 验收。

## 独立账户代际来源

独立记录保护的是账户快照选择与吊销历史。它采用现有 [`generation_mark`](../../src/user/pumpkin/snapshot_publication.hpp) 的完整比较语义，覆盖安装域、修订号、快照长度及摘要。双槽同步和读回能够证明正常重启时的数据存留，整盘历史状态仍可能被离线恢复。两种能力需要单独验收。

| 来源 | 当前能力 | 采用条件 |
| --- | --- | --- |
| XOS 现有设备 | sys23–26 的 ATA 路径经 files 操作当前工作盘。私有尾区隔离普通会话，但与快照在同一可替换介质上。sys112 已接入的 PCI 类别为网络。sys46 为启动后的时间，sys64 为 RTC 实时时间，sys63 为随机字节。当前树与测试配置都没有接入 TPM 持久代际。 | 生产评估可从具有独立 NV 状态的平台设备开始。需受限的设备授权与初始化链、完整记录的原子比较发布、单调性、耗写限制及断电恢复证明。它们属于新的设备资格，当前不具备。 |
| 显式开发环境的宿主记录 | [宿主开发代际组件](pumpkin_host_generation_authority.md) 已在 APFS 上验证私有目录、完整记录比较发布和宿主进程重启。每个已配置安装域独占一份记录，由可信宿主监督器修改。 | 待通过显式开发 profile 的专用通道，绑定经过监督器授予并具备当前 files 租约的客体 Pumpkin 实例。独立目录始终在 guest 盘和虚机快照范围外。 |

开发实现应让可信宿主监督器持有已初始化状态。仅明确创建的新安装域可进入首次发布。配置为已初始化后，记录缺失、不可用或安装域不符均停止启动。服务先同步候选槽并读回校验，再请求监督器按完整旧记录比较发布。监督器串行比较已提交记录，在同一受保护目录写新临时记录并同步，经原子替换再同步目录，以该宿主与文件系统实测的持久语义确认结果。只有确认旧记录仍保持时可返回已知未提交。公布状态不确定时停止认证与账户变更，恢复时以宿主记录选择确切的一个槽，禁止自动切回旧槽。宿主记录随 guest 或 QEMU 恢复时也回退的配置无法采用本方案。

最低验收应使用实际独立宿主记录和一次性槽介质。仅恢复旧盘时阻止认证和启动，用同修订号的不同摘要确认比对完整记录，覆盖宿主发布前后中断、回复丢失、当前槽损坏及记录缺失。生产硬件初始化、管理权和物理断电资格仍独立验收。
