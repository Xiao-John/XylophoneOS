# Pumpkin 私有对象与账户快照发布

[前一轮实测](pumpkin_storage_feasibility.md) 已验证 FAT 正常同步后的存留，并确认
普通会话可读取和替换候选文件。此阶段实现一个可独立验证的用户态发布器。私有
存储对象的授予，以及独立代际记录的后端，仍需完成接入。

## 路线与边界

| 路线 | 基线已有接口 | 下阶段仍需完成 |
| --- | --- | --- |
| files 私有对象，优先 | files 服务掌握 FAT 与块同步，文件会话由内核认证，通用 IPC 已有独立端点和退出撤销。 | files 内建立私有对象标签、写者租约和启动授予。固定两片快照的后端隔离及失败语义。 |
| 另挂独占卷 | sys23–26 指向既有工作盘并且只有 files 可调用。sys112 能授权独立设备，但现有类别仅接纳网络设备。 | 先提供可选择、可撤销的独占块设备权利及对应用户驱动，再验证写入范围、FLUSH 和设备失败。卷独占只覆盖访问边界，代际记录仍需独立保护。 |

内核继续负责 IPC、主体认证和设备隔离。文件对象/存储策略、快照和账户由用户态实现。
选用 files 私有对象的条件是保留旧路径行为，并让授权走明确的对象接口。

## 授予及兼容方案

1. files 启动时可用 sys22 取得现有启动控制收发端，随后用它与 sys27 枚举出来的
   文件会话配对，确认真实 bootstrap supervisor。监督器能创建普通程序，因此进程
   亲缘关系只用于核对启动链。正式授予另需受保护的控制请求。
2. 受信监督器显式选定安装域、私有对象与所需操作，记录实际启动实例。准备阶段的
   子进程尚不能接收 sys84 通用端点。待实例运行后再建立专用端点，并在发行授予前
   核验实际内核对端。可沿用 [Pumpkin P1](pumpkin_daemon_p1.md) 的父进程配对方法
   交接端点。绑定只为已核验的对象、席位和实例设权，文件名、可发现名称、PID、UID
   和请求中的数字不赋予权利。
3. 文件服务在实际授权点查授予表。每个安装域最多一个写者，从读取当前代际到完成
   发布都持有租约。单独比较代际不能防止多个写者先后覆盖同一个非活动槽。客户端
   退出、成功 exec 或控制端撤销后回收租约，失败 exec 保留原绑定。重新启动通过
   明确授予恢复，不继承客户端持有的旧标识。
4. 沿用旧 file v2 路径入口、错误语义和包布局。私有对象标识由 files 自己管理，
   客户端按对象获得权限。若底层存放在 FAT，内部存放名仅用于定位，经真实目录项
   检查覆盖短名、长名、大小写别名、枚举与父目录移动。已有路径上的文件在新配置
   启用前核对冲突，保留原数据供显式迁移。工作盘导入导出、xypm、离线检查与
   恢复清理也需覆盖新布局。当前 `XOS*.TMP` 已被公共路径保留，其中部分名字会被
   启动恢复扫除。私有持久数据不要占用这些既有临时名。

跨进程协议版本、控制消息、路径保留或公开 SDK 编码由总协调登记和评审。此阶段的
`publication_io` 是 Pumpkin 进程内接口，未占用协议号，也未修改 files 或监督器。

## 快照与持久代际

候选快照沿用 P0 格式。发布记录含安装域、严格递增的版本、长度和覆盖快照头及全部记录的 P0 摘要，
版本奇偶决定槽位。存储适配器需提供以下三个独立保证：

- **受保护的槽读写。** 持有现行独占租约的写者可以写入非活动槽并同步，错误只会
  破坏该槽。所属安装域、对象与写者均要核验。
- **原子发布。** 读取当前已认证记录并核对选中槽，写入后同步非活动槽，再读回
  核对长度、版本与摘要。最后对完整旧记录做原子比较并持久更新。提交成功仅在新
  记录确认后返回。仅能断言旧记录完整且未改变时可返回已知未提交。遇到不确定结果，
  身份核心停止服务，重新启动时核对选中记录后恢复。
- **持久代际。** 发布记录是恢复时的唯一选择。未选中的新槽不能自动生效，旧槽也
  不能在活动槽损坏时自动恢复。发行环境若允许离线替换整盘，发布记录需存于保护
  范围独立于可替换盘的来源。来源须保证非递减、防清空及明确的已初始化状态。
  只有受信初始化明确证明从未初始化才可报告空库，缺失或无法确认的发布记录阻断
  启动。读出更换过的 data 盘时，即使快照自身校验通过，也必须与独立记录一致。

目前实现的发布器消费上述能力。受保护代际来源、实际文件对象授予与介质断电资格
仍需各自验收。应先验证真实后端上的写者和对象生命周期，再执行提交中故障、断电、
设备错误和仅更换数据卷的恢复验证。
