# Pumpkin 账户库持久化勘查

基线为 `9f7a9a0f`，账户快照沿用 [P0](pumpkin_identity.md)。当前客体账户库继续使用
[P1 显式测试配置](pumpkin_daemon_p1.md) 的易失存储。私有测试盘已验证现有 FAT 上的
同步存留，同时观察到独立普通进程可以读取及替换同一快照文件。

## 现有实现的边界

| 机制 | 已有行为 | 对 Pumpkin 的影响 |
| --- | --- | --- |
| files 单文件替换 | `replace_begin/chunk/commit` 验证 staging 属于请求的认证会话。提交同步 staging，记录目标 journal 和备份，再发布目录项及同步。遇到部分错误会阻断后续文件访问，保留恢复材料。 | 可用于测量一次已确认写入的存留。staging 的所有者只在一次替换期间限制操作，正式路径仍服从普通命名空间规则。请求没有上一版本字段。 |
| files `sync` | 对打开的 FatFs 文件同步，然后 `CTRL_SYNC` 经 sys25 触发 ATA FLUSH CACHE。 | 已验证 QEMU 在同步后重新启动可读回。该路径未验证断电、扇区撕裂或设备缓存异常。 |
| xypm P2 维护事务 | xsh 监督器暂停应用准入，指定唯一 worker 持全局写租约，再准备备份、摘要、journal 和 commit 记录。启动恢复器按材料判断回滚或清理。屏障下仍允许读取。 | 恢复状态机和逐点故障方法可以复用。运行中身份库需要持续服务，普通会话也须被拒绝读取账户库。全局维护时段及其路径不能作为此权限。 |
| 原始块访问 | sys23–26 的 `block_access` 只授予系统 files 任务，ATA 路径面向现有工作盘。sys112 当前受支持设备类别为网络。 | Pumpkin 普通进程调用 `sys_block_info` 得到拒绝。为它暴露整盘会扩大权利，独立块设备的授予与驱动还需专项设计。 |

快照摘要可识别字节损坏，不能证明快照仍为最新版本。存留试验的客体先正常同步，
随后由宿主关闭并重开 QEMU。写入方提前退出覆盖的是提交前进程失败，故障点在
`replace_commit` 前。未对正在提交的磁盘命令实施中断。

另一个普通会话可以读出有效 P0 快照，随后也能用 files 原子替换接口发布新版本。
同一文件名、FAT 只读属性、合成 UID/GID、保留名以及维护租约均不足以提供账户库
需要的专属读写和版本担保。普通会话能够读取快照本身阻断生产接入，写入路径也
无法独立建立 P0 的版本比较和单写者承诺。

## 可推进的底座

优先验证现有 files 服务提供持久私有对象的路线。可信启动链应显式授予受保护对象
及所需操作，授权绑定实际端点和对象世代。常规路径解析、目录枚举、读写和替换均
须在真实对象上执行拒绝。服务重启后通过受保护的绑定重新打开对象；客体故障测试
覆盖打开对象复用和不同主体权限。另一路线是独立块设备，由真正确认的控制者只授
对应设备权利。该路线需要新增实际块设备选择、撤销、I/O 与同步资格。

两条路线都须独立验证快照发布条件。若使用双槽，写入并同步非活动槽后读回检查，
再用有原子保证的提交记录引用新槽。已写完的数据仍需已提交记录才能发布。
异常时维持已确认版本或停止服务等待恢复；只有后端能证明旧提交仍在时才可回答
已知未提交。若要支持可离线替换的磁盘，版本锚点须在不能随同相同磁盘镜像回滚的
受保护位置。锚点更新与提交记录的崩溃边界也要纳入验证。

P2 持久后端继续待接入。当前试验没有注册 ABI，也没有把候选路径接到守护进程。
