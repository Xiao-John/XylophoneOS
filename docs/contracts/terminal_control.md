# 终端内部控制协议：试行

2026-10-30。本协议仅连接 COM1 终端服务与内核认证的授权 supervisor，不是普通应用
终端会话或稳定 POSIX ABI。固定版本 2、固定大小消息，序号为非零单调值；由内核
认证的两条单槽通道按顺序承载请求和应答，失败后的业务结果可能未知。

`read_until` 接受绝对单调纳秒截止时间，UINT64_MAX 为无限；输入到达时返回实际
字节，截止返回 timeout。等待中有新的控制请求到达，则读取可返回 `interrupted`，
后续请求继续按序处理。`cancel` 不带数据，作为可用于打断读取的普通后续请求，
读取的应答排在 cancel 应答之前；如果读取先完成，则返回实际结果，cancel 仍应答。
所有请求而非仅 cancel 都可中断等待。零长度读取立即返回。输入、请求及截止同时
发生时，不能预设哪一个先完成。控制者关闭或退出时服务关闭通道、唤醒读取并退出；
消息已发送时的处理结果未知，不得自动重试。

`write_until` 等待 UART 发送就绪后返回实际写入数量，可能短写；使用相同的绝对
单调截止时间和请求中断规则。驱动在写入暂不可用时启用 THRE 中断，IRQ 处理先
禁用 THRE 再应答，避免空闲时持续中断；后续阻塞写入按需重新使能。超时或中断不
代表前一请求一定未写入：客户端只有收到有效应答才能知道该次已确认的数量。
控制客户端的 `read_until` / `write_until` 最多处理 256 字节，并验证应答长度；调用方
负责处理短读写。授权 IRQ 的单次 THRE 触发、关闭设备中断原因和 ACK 已有[受限客体检查](../work_log/0173_authorized_irq_wait.md)；这不证明全部收发中断交错、硬件短写或撤权竞争。

客户端 `submit`/`receive` 支持最多两个未收应答的请求并验证顺序；允许先提交读取
和 cancel、再依次收取两个结果。`exchange` 仅在没有未决请求时使用。调用必须串行，
并发访问同一客户端对象尚不支持。内部 mailbox 最多一个待处理请求；服务还使用一条
IRQ 线程和一条控制接收线程。请求中断、应用交接与服务重启已有[受限客体检查](../work_log/0149_terminal_handoff_and_fault.md)；并发访问同一客户端、全部请求交错和故障后的结果仍未获得完整资格。

supervisor 可用 `attach` 请求一个应用通道对：两个 handle 必须均由内核报告为该
supervisor 创建，具有正确的服务端收发方向和同一目标 PID。服务仅保留一个应用
会话，运行独立接收线程；应用仅能请求读、写和取消，不能发控制命令。会话存在时
supervisor 不能通过控制通道直接读取或写入设备；detach、通道关闭或应用退出会结束
会话。应用必须依次收取应答：为防应用不读应答而阻塞 supervisor，应用应答槽已满时
服务关闭该会话，不无限等待。应用与控制消息到达次序、发生故障时结果均不可推定。
应用通道是试行内部接口；下文所述单线程 fork/exec 和会话切换只有指定子集的客体证据，不构成完整的 POSIX 继承或作业控制语义。

SDK 试行 `terminal_client.hpp` 可按启动者给出的 supervisor 与服务 PID，核对应用端
两条通道的内核认证控制者、对端和方向后连接；客户端串行处理单个请求，并校验应答
序号和长度。该接口本身不认证启动参数来源，也不自动获得控制权；未匹配时拒绝连接。
传输或格式失败关闭通道，先前请求结果可能未知。正常非零长度读写不会将零结果
当成成功或 EOF。试行 startup2 扩展可由受信启动者传递应用发送 handle；
`connect_startup` 根据内核枚举到的句柄核对控制者、服务对端和双向通道。只有声明
`.xos.tty` v1 的目标可由加载器使用该扩展；它不授予通道权。单线程 libc 试行使用
同一个终端对象承载初始 fd 0/1/2，最后一个引用关闭通道；read/write 使用原始字节
并返回实际短结果，`isatty` 和 `fstat` 报告字符终端。现阶段仅有受限 termios 模式，
带该终端对象的单线程 fork 试行派生并登记独立子通道，子进程重新认证绑定；派生、
登记、files 克隆或 commit 失败时父进程 abort 子进程。登记传输失败时原会话结果
可能未知；成功 commit 后服务失效会使子进程后续终端操作失败，而不撤销已成功 fork。
`tty-run` 为该路径授予有限进程创建权限，受现有进程及 fork 深度限制；多线程运行库
拒绝该启动扩展及 fork/exec。单线程 exec
试行显式保留应用通道，并在 startup v3 中传递下一请求序号；目标必须声明 `.xos.exec`
v3 和 `.xos.tty` v1。非 CLOEXEC 的终端描述符按原别名恢复，全部关闭时通道按原
默认关闭；失败 exec 保持旧会话。该路径依赖调用者没有未完成请求，不保证断线或
对端违规时旧请求结果；同 PID、别名、模式、失败和 CLOEXEC 已有受限客体验证，
不代表完整 POSIX 终端或作业控制。

试行应用模式保存在服务端，每个应用会话初始为无回显、非规范、115200 8N1 的
原始字节模式；关闭会话重置。当前仅接受所有可变标志均为零、固定速率，以及
`VMIN/VTIME` 为 `(1,0)`、`(0,0)` 或 `(0,1..255)`；其他配置明确返回 unsupported，
不会静默成功。`read_mode` 分别表示至少一个字节、立即读取、最多等待指定分秒数；
后两种无数据可返回零，该零值表示本次无数据，不能推为设备 EOF。模式变更先检查
完整请求再更新，失败不更改状态。

单线程 libc 现提供试行 `termios.h` 和原始模式映射：`tcgetattr` 查询服务实际模式，
`tcsetattr(TCSANOW)` 仅接受上述模式和固定 115200 8N1；未支持标志和组合返回
ENOTSUP，非终端返回 ENOTTY。初始终端 read 使用 `read_mode`，零值可能表示限时或
非阻塞读取无数据。`tcdrain` 和 `TCSADRAIN` 通过用户态驱动检查 16550 的 TEMT 位
确认发送寄存器及移位寄存器均空；硬件没有 TEMT 中断，未空时按单调时钟 tick 睡眠
后重查，控制请求或失效可中断。`TCSADRAIN` 仅在确认排空后更新模式，中断或错误
时模式不变。`tcflush(TCIFLUSH)` 在驱动锁内先有界丢弃硬件接收数据，确认 FIFO
已空后清理软件队列；`TCSAFLUSH` 依次排空发送、清空输入、更新模式。连续输入
超过一次 256 字节工作限额时返回 busy，部分硬件数据可能已经丢弃，不能伪称回滚；
错误时模式不变。之后到达的数据不属于清空前输入。`TCOFLUSH`、`TCIOFLUSH` 仍
返回 ENOTSUP；符号速率常量不代表设备支持改变速率。专用应用的受限客体路径调用过 `TCSADRAIN`、`tcdrain`、`TCIFLUSH` 和 `TCSAFLUSH`，见[交接探针](../work_log/0149_terminal_handoff_and_fault.md)及其对应 fixture；这不证明 FIFO 满载、忙返回后的字节集合、物理串口时序或所有中断交错。
已排队单字节的 `TCIFLUSH`、`TCSAFLUSH`、模式更新及后续新字节读取另有
[客体检查](../work_log/0186_terminal_input_flush_guest.md)，其不覆盖连续输入竞争。

试行 `wait_readable` 对应用会话以绝对单调截止时间等待输入队列非空，不消费字节；
超时、控制中断和服务错误分别返回错误。单线程 libc `select` 当前只支持一个终端
读取描述符；写入、异常、多个或无描述符以及其他对象均返回 ENOTSUP，非法描述符
返回 EBADF。它不是通用多源等待；ncurses 的方向键及限时读取已有[客体集成证据](../work_log/0145_terminal_readable_wait.md)，空队列、就绪不消费输入和部分错误参数已有[直接客体检查](../work_log/0185_terminal_select_contract.md)，不证明所有 select 参数和竞争。

supervisor 桥接试行显式重连：桥接失败后只在没有附加应用、旧服务完成结果可用时
非阻塞回收；COM1 已隔离则请求受限 recover，资源已空闲则尝试重新启动服务，仍被
占用或完成结果未就绪时返回错误。失败保持 unavailable，不回退旧控制台、不重放
旧请求，也不保证交接期间的输入或输出。无应用附加时的终止、重启和新应用启动
已做受限客体验证；应用在途故障、旧请求结果及资源压力仍未验证。

当前不提供完整应用前台会话、完整 termios、通用 stdio 继承、通用故障恢复、信号或稳定设备救援；所有
权限、并发、时限、短写及退出路径均须在相关修改提交后的真实客体测试中验证。

试行 `fork_attach` 允许现有应用请求登记内核已派生的子通道对。接收线程依据该请求
实际到达的原端点调用 `verify_fork_pair`，在子进程仍为 building 且有空槽时先将
通道加入等待集合，再向原应用应答。服务最多保留三个应用端点对，共享终端模式；
派生子项关闭时移除该项并打断设备等待，根项关闭时结束应用会话。回复发送失败时
关闭对应派生项，根项失败结束会话。父进程必须在出错或结果未知时 abort 未启动的
子进程，不能重试可能已执行的登记。单线程 libc 试行接入该事务，此接口、竞争、
资源压力和多进程终端行为尚未获得完整客体资格。
