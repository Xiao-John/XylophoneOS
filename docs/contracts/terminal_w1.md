# W1 终端底座：工作契约草案

2026-10-28，设计草案，未实现、未验收；不分配 ABI，不改变既有 POSIX 契约。
本草案用于 W0 缺口收敛，须结合真实 ncurses 版本与目标探针冻结后实施。

## 输入与所有权

终端应有可由内核认证主体操作的受控对象；用户态服务管理终端输入模式与前台策略。
普通后台进程不能通过现有直通 console 绕过独占读取；拒绝时返回错误而非假 EOF。
supervisor 在前台应用可运行前，将读取权委派给可信的实际子代；委派不能扩大权限，
切换与入队、等待及唤醒必须消除丢输入竞争。确认会话失效、队列溢出及服务退出时的
可观察结果和界限；客户端不能凭程序名、路径或自报 PID 获得权利。

成功 exec 默认保持同一进程原有权利，以维持现有前台 exec；失败 exec 不改变原状态。
fork 的默认继承与显式委派须与现有 dash 行为共同核对，不以 PID 重用造成旧权利指向新
进程。正常退出、kill、故障和服务失败撤销权限、唤醒等待者；supervisor 能接回终端，
用户态决定恢复策略，服务失败后的结果未知不能冒充请求未执行或成功。

## Escape 与模式

现状 `timer_entry` 调用 `cancel_foreground`，会消费串口 ESC 并终止前台任务；因此方向键
等 ESC 序列可能被取消机制截断。旧程序的默认前台 Escape 取消语义保持；可信前台读取
权持有者显式请求逐键模式后，ESC 字节完整交应用，不能依据程序名绕过。逐键模式下旧
Escape 取消不能同时工作，救援通过可用的监督操作；不声称 SIGINT 或 Ctrl-C。程序退出
或失权后恢复默认，原模式保存/恢复和异常路径均须验收。

## 等待与设备

现有 `sys_pipe_wait` 对 console 返回 would_block，旧 `sys_read` 空闲可返回 0；newlib
读取可返回 EAGAIN。COM1 接收 IRQ 当前关闭，`debug_peek` 是轮询与单字节缓存；进程内
`wait_word` 不会因串口到达而唤醒。因此不得把空闲当 EOF，也不得把周期 sleep 轮询说成
事件驱动/无丢唤醒。应评估 UART IRQ4、有界队列、溢出报告、设备权限和原子检查/登记
等待；PIC 掩码要兼容 IRQ0/1/12，IRQ 只做有界设备工作。时间上限、错误和资源回收须
在最终 ABI 前冻结。新设备机制需满足 C20，启动/调试直通及旧取消若暂留，须按 C26
登记必要性和退出条件；登记不豁免原则冲突。

## 文本与 locale

当前 vendored newlib 的 `newlib.h` 关闭 `_MB_CAPABLE`；存在 `setlocale`、`mbrtowc` 等
符号不证明 UTF-8 locale。应分别核对新构建的普通与线程 profile、宽字符转换与资源、
`wcwidth` 和 XOS 现有显示宽度规则；不可盲目替换已发行 SDK 或改变旧报告绑定。
`tests/fixtures/ncursesw/wide_locale_probe.c` 为消费者探针，尚未在客体运行。

## 后续冻结项

终端对象协议与权利来源、与旧控制台/pipe 的兼容及迁移、退出/exec/fork 原子性、
读/写和非阻塞/超时的错误、尺寸配置、UTF-8 locale 数据版本与新 SDK 构建方案，须先
逐项冻结并登记占用，再实现和编写独立客体验证。用户要求所有相关改动提交后才做验收；
当前没有 W1 通过资格。

## 2026-10-28 前期拆分

1. 优先确定一个通用受控字节流设备对象：UART 接收中断向有界队列入字节并报告溢出，
   原子检查/登记等待，关闭和故障唤醒；设备权限由可信授予和生命周期约束。此层不解释
   ESC、shell 或应用协议。IRQ4 与 PIT/PS2 的 PIC 掩码合并管理，不能由显示初始化覆盖。
2. 用户态终端服务持有设备读取权，负责前台会话、按键模式与输入分发。原有 `sys_read`
   和 `sys_handle_read` 直通路径必须纳入同一受控边界，否则后台可绕过独占；早期引导与
   调试通路的例外另行按 C26 审查。只有真正继承 console stdin 的进程需要输入权，管道
   中其他进程不自动获得。
3. 既有 `sys_process_foreground` 是至多四个子进程的取消登记，不是终端对象或授予权。
   前台权须在子任务可运行前安全交接；成功 exec、失败 exec、fork、kill 和故障的语义按
   本契约前述边界处理，不能以程序名识别 ncurses。旧 ESC 策略向用户态迁移，逐键模式
   禁止内核抢消费；是否保留过渡机制须说明范围与退出条件。
4. 服务需要同时响应控制 IPC 和串口事件。评估分别等待的线程与通用多源等待；须证明
   生命周期、锁序与唤醒，不将忙轮询或显示专用 wait 当成通用等待。先以具体消费者探针
   和最小接口冻结方案，再登记 ABI；本草案不直接指定具体 syscall。

这只是实现拆分；此前系统、显示、线程或 UTF-8 资格不能用作上述新机制的客体验收。
