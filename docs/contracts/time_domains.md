# 时间域与内核基础设施边界

2026-10-29。细化宪法C28/C29，不新增ABI或声明新时钟实现。旧线程等待契约保持。

## 统一管理的对象

统一的是系统时间的语义、选择/校准和转换责任，不要求一个硬件、一个变量或一个写入点。
通用时间管理定义时间域；ISA/平台后端提供实际计数器读取与时钟事件配置。
时源提供读数，时钟事件负责触发唤醒，二者可以使用不同硬件；不要求时间只在中断到来时前进。
新增时源、切换、校准和并发更新必须由该管理机制协调，保证已公开的时间与等待契约。
当前周期tick实现可以保留，不因此提前实现高精度、无周期tick或SMP支持。

| 时间域/用途 | 约束 |
|---|---|
| 系统单调时间/线程deadline | 共享已定义的域；睡眠、锁等待、驱动通用超时不使用模块私有tick替代；不得因校时倒退或重新起算 |
| sys_ticks兼容接口 | 按既有单位、宽度与起点契约保留，转换须说明取整/溢出；不是要求所有时间量化到旧tick |
| 实时时钟 | 需要真实纪元/校时来源；可表达为单调时间加偏移或其他受管理映射，不能把uptime当墙钟；调整不改写已有单调deadline |
| CPU执行时间、包含暂停时间等新域 | 只有实际需求时设计；明确计量对象和暂停行为，独立准入，不因本文件视为已有 |
| 设备时间戳/音频采样计数 | 可来自设备；明确单位、频率、回绕/重置和来源；跨域关联须定义转换及误差，不能直接与系统deadline比较 |
| 应用动画、仿真、媒体播放时间 | 可暂停、缩放、重置；不得冒充系统时间；底层阻塞最终使用等待接口所要求的域 |
| 诊断计数/耗时测量 | 可独立计数，但次数不是时长；直接硬件计数不得默认有纳秒精度、跨CPU可比性或替代系统等待的资格 |

绝对时间点须能识别所属域；时长本身不含起点，但从两个时间点作差前须确认同域或已转换。
新接口应使用明确命名、类型或版本化字段表达域；不为追溯标注而擅自破坏现有ABI。
转换说明比例、偏移、有效期、校准责任、精度/误差、取整与溢出；不能证明映射时拒绝跨域操作。
时间单位为纳秒不等于纳秒分辨率。源切换、墙钟调整、暂停恢复和计数器回绕按实际支持范围验收。

## 中断机制与C28边界

EOI/屏蔽接口不得隐式推进时间、记入业务进度或执行超时策略；时间更新使用明确的时间管理入口。
允许透明诊断计数/跟踪：必须有界、无新增阻塞、不改变应答顺序或成功条件，不能成为时基或等待谓词。
EOI次数、设备完成次数均不得乘以猜测周期充当系统时间。实际中断路径可以显式调用计时和调度机制，
不要求整个中断处理过程除了EOI以外什么也不做。

C28允许的基础设施限于内核自身隔离、调度、时间管理必需的最小硬件控制；逐项按C20给出理由。
时钟基础设施不得使用上述例外承载图形、存储、网络等设备数据通路；RTC的必要读取也不意味着
全部RTC管理功能必须在内核。固件与ISA/平台边界仍按C03/C24，不写死PIC、PIT或某ISA计数器。

存量整改登记见[0088](../work_log/0088_kernel_driver_c28_debt_register.md)：它是当时的裁决记录，
不是当前各文件的永久豁免或逐行合规证明。对存量只修安全问题、缩小边界或实施迁移不等于新增
内核态驱动许可；新增业务功能应落用户态。新增/扩大过渡实现须按C26论证，不能自行登记豁免。
本次修订不重判某PR的具体计数器，也不撤销旧证据；须检查它是否隐式推进时间或影响功能语义。

## PR审查的最小问题

1. 时间值来自哪个域，单位/起点是什么，谁负责校准？
2. 是否复制了私有计数来替代系统时间，或绕开已有时间管理？
3. 绝对deadline与等待接口是否同域？伪唤醒是否沿用原deadline，墙钟变化是否影响它？
4. 涉及设备/应用时间时，是否明确隔离或转换，避免直接混比？
5. EOI/屏蔽是否藏有时间推进、业务逻辑或影响应答的统计副作用？
6. 新时源/基础设施是否说明必要性、ISA边界及适用的单调/回绕/调整/超时测试？

只审实际新增或改变的行为，不要求每个应用重跑全部时间测试。测试虚拟时钟允许显式注入，
须限定测试范围，不可静默代替生产时间或计入真实客体计时资格。
