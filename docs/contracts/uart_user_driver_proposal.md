# 用户态 UART 的设备授权与交接提案

2026-10-30。状态 P，未分配 ABI、未实现或验收。本文收敛 W1 对 C28/C29 的具体
依赖，不以提案或引导调试例外宣布终端可用。对照[通用设备提案](network_device_v1_proposal.md)、
[时间域](time_domains.md)、[终端计划](../plans/ncursesw.md)和[串口整改记录](../work_log/0115_w1_c28_irq_withdrawal.md)。

## 为什么需要新机制

PC 16550 使用 x86 I/O 端口，不能通过现有用户 MMIO 映射访问；普通用户的 IOPL 和
TSS 访问控制默认拒绝端口 I/O。现有 IPC 与 sys54 无法向用户进程交付 IRQ4。为遵守
C28，驱动中的寄存器协议、FIFO、缓冲和错误处理必须留在用户态；内核只做资源权限、
中断递送/应答、隔离及撤销，不逐字节代理 UART 收发。现有 sys80 claim 暂时不可用，
它不是设备授权或终端服务。

## 资源和主体

- 只允许可信资源管理者向经内核认证的受控驱动进程授予已经登记的设备实例；输入
  中的 PID、名称、端口地址或程序路径不单独授权。授权引用不可复用的进程身份与设备
  generation，单设备独占，权限不可扩大或擅自转授。具体可信管理者和启动身份须在
  实际服务启动链中固定，不能凭此文新增对普通应用的设备权利。
- 第一目标是 COM1，PIO 窗口限于 `0x3f8..0x3ff`，独立 IRQ 路由为 IRQ4；这只是
  PC/QEMU profile 的硬件资源，不是跨平台 ABI。1/2/4 字节端口指令的全部字节须在
  同一授权窗口内；该窗口允许控制 UART 寄存器，驱动因此必须受信。不得开放全局
  IOPL、PIC、PCI 配置端口或其他设备端口。
- 每个进程的有效端口权限必须在上下文切换前装入 TSS bitmap，并与所有线程共享一致
  的进程授权。默认全拒绝；撤销时在进程再次运行前清除权限，不能让线程切换、fork、
  exec、异常或 PID/槽位重用继承旧权利。exec/fork 默认不继承；失败 exec 保持原状态。
  不能把全局 bitmap 留成上一个进程的权限。当前 0116 的全拒绝 bitmap 尚无该功能。

## 中断和失败

IRQ 权利与 PIO 权利独立。绑定、等待、确认和撤销应复用通用设备机制：事件带不可
复用的对象身份与序号；内核只屏蔽、应答、通知和重新使能，不读取 UART 状态或数据。
驱动读取并清除设备原因后确认；重复/过期确认拒绝。WAIT 的条件检查与睡眠原子化，
deadline 使用系统单调时间域，超时、失效和关闭返回不同的真实结果。共享 IRQ 未
设计前不承诺支持；绑定冲突必须失败。接收缓冲满、硬件 overrun 和驱动失效须由
用户态服务向消费者提供可观察结果，不能伪装 EOF 或静默成功。

撤销、exit、fault 和成功 exec 必须先阻止新访问并屏蔽/解绑该 IRQ，再撤销 PIO 并
唤醒等待者；应答与设备状态不确定时不得将 IRQ 路由交给新所有者而宣称已恢复。
不可合作的驱动可能使设备原因持续，首版应保持线路屏蔽、设备不可用，等待受信
用户态恢复；不要求内核执行 UART reset。失败 exec 不能撤销现有授权。

## COM1 交接

当前内核引导和救援 console 也使用 COM1。要将它授予用户驱动，必须先实现可验证的
独占交接：停止内核 console 后续寄存器访问与输出，处理未消费输入并屏蔽 IRQ，再
授权用户驱动；客户端改接用户态终端服务后才进入交互。不能同时让内核日志和用户
驱动访问同一 UART。驱动退出时不假设设备状态已复原；内核日志备用路径和用户可用
救援方式须在实际环境中单独实现与验收。选择另一串口可用作隔离开发探针，但不能
代替既定 COM1 交互和恢复的最终资格。

2026-10-30 后续实现限定：对单核、无 DMA、IRQ4 独占的 COM1，撤权和屏蔽后允许
supervisor 显式解除隔离，再由新的用户态所有者在 IRQ bind 前先禁用设备中断并重建
配置；不可将旧设备状态、输入和请求结果当作已恢复。PIC 残留事件及交接竞争仍须
客体验证，最终接口和结果以 [PIO 契约](pio_grant.md)及
[IRQ 契约](irq_event.md)为准。本补充不推广到未证明可隔离的设备或共享 IRQ。

## 实施及证据

先核通用设备/IRQ 接口与其他分支的真实进度，在共享登记中认领具体编号和结构，再
实施经认证的设备授权、架构 I/O bitmap 切换及原子撤权。独立测试至少覆盖未授权
in/out fault、范围和跨边界访问、其他端口隔离、多线程/进程切换、无效主体、重复
授权、fork/exec、撤权和故障后的旧权限失效；IRQ 覆盖先到达/后等待、超时、重复
ACK、撤权竞争及资源基线。COM1 交接另验正常退出、故障、日志与救援。随后接入
用户态终端、UTF-8 及 ncursesw 两个消费者。所有相关更改提交后执行客体验收，不以
宿主位图测试、单独构建或其他设备的旧结果代替。
