# E08-3 压力测试计划：binutils Seed 与工具运行时

状态：**已执行（部分失败）**；结果见 `reports/e08_3_stress_report.md`。
S1/S3/S4 通过，S2 34 成员 archive final `ld` 失败；E08-3 压力测试不算全绿。对象是 E08-3 的 GNU Binutils Seed（as/ld/ar/ranlib/
strip）及其下的 E08-1/2 文件、进程、管道、堆和持久化底座。不是 GCC/G++ 压力，
也不把 binutils 的结论升级成完整 POSIX。

## 1. 已有覆盖，不重复

正式 E08-3 gate 已有 7 组、32 次客体命令：

- 五个工具 `--version`；
- 两轮 as/ar/ranlib/ld/strip 完整链路，guest 产物退出 42；
- archive 索引从无到有、宿主 readelf/nm 静态核对；
- 相同输入/输出拒绝、汇编/链接错误、未定义符号、plugin 拒绝；
- 每步页/任务/完成记录回到基线；
- 源码逐字节保留；sync 重启后 stripped ELF 仍可执行。

压力测试补的是：**重复次数、规模、故障注入、长时间资源曲线、重启循环**。

## 2. 目标与不变量

每个压力场景都要盯住：

1. **资源**：空闲物理页、任务数、完成记录、文件打开/句柄、FatFs 锁、临时文件、
   磁盘剩余空间回到基线；不能只靠“进程退出了”。
2. **数据**：输入源码/脚本逐字节不变；输出 ELF/archive 正确；失败不破坏旧产物。
3. **生命周期**：工具退出、被 kill、超时、取消后，子进程/临时文件/锁被回收。
4. **持久化**：sync 后重启，生成物仍能执行；不是缓存看起来成功。
5. **有界性**：固定 TCG 下命令有超时；磁盘满/工具错误返回非零，不挂终端。
6. **性能基线**：记录每命令耗时/吞吐；只做回归比较，不作为真机或 GCC 性能证明。

## 3. 测试环境与约束

- 固定 Seed manifest：`47ddd3071e2ad7f69b8b903c51b491aa59d81ed96e173fb0f506341248af0a9e`；
  SDK 快照必须与 Seed 链接输入一致。运行时/SDK 变化时重新绑定，不能混用。
- 固定系统构建 ID/Seed 后再跑压力；**禁止与 E08-4 的 build/ 并发构建/清理**。
- QEMU 512 MiB、单核 TCG；临时 FAT32 512 MiB 盘；日常 `work_disk.img` 不动。
- 使用专用临时目录/盘；失败时保留镜像、serial 和报告，不自动清理证据。
- 命令行仍受 argv 64 项/255 字节、每会话 8 打开、全局 16 FatFs 锁限制；
  压力不能把这些文档上界当成“无限”。

## 4. 分层场景

### S0 基线（每个候选 Seed 必跑）

现有 `tests/binutils_smoke.py` 的 7 组。只作为前置 sanity，不重复计入压力结论。

### S1 快循环（CI/每次 Seed 变更）

- 10 轮：as 两文件 → ar → ranlib → ld → 执行 → strip → 执行。
- 每轮使用独立输出名或显式清理，避免把“覆盖旧文件”当成功。
- 每步检查资源回到基线；每轮后检查 `/tmp` 无残留、源码哈希不变。
- 目标：短时间发现句柄/页/任务泄漏，不追求规模。

### S2 规模

- 32 个对象（每对象唯一符号）逐个 as，归档为 archive，ranlib，ld 链接；
  必要时用 ld 的 response file 或 archive 控制 argv 长度。
- 64/128 个 archive member 的逐个添加、索引和 nm 检查（在磁盘/时间允许内）。
- 大对象：至少 1 MiB `.text`/`.rodata` 和 8 MiB BSS 级别样本，验证页预算、
  零填 BSS、W^X 和装载；不要伪造超过 256 MiB 用户页上限的样本。
- 路径/目录：接近 255 字节路径、嵌套目录、长文件名；终端不能输入空格的限制
  用 exec-driver/固定脚本绕过，不声称终端支持空格。
- 多文件 `/out`（如 100 个）下的 ls/stat/cleanup，验证目录分页与句柄上限。
- 验收：工具退出码正确、ELF 可执行、archive 索引/符号正确、资源/磁盘回基线。

### S3 故障注入（优先）

- 语法错误、缺失输入、未定义符号、坏目标文件、截断 archive、非法 member、
  重复 member、把目录当输出、同输入/输出、显式 plugin。
- 磁盘满：宿主填入接近满盘的数据，再尝试 as/ld/strip；必须非零、源码不变、
  无半成品被当作成功。
- 中途取消：前台 as/ld 用 Escape 或 supervisor kill；`spawn-file` 子工具用
  kill；检查半成品/临时文件/锁/任务回收，重启后源码仍可读。
- 超时：对大输入/异常路径设上限，确认不会永久卡住终端；失败后继续可用。
- 每个失败场景都记录期望错误码/诊断、输出文件状态、资源与源码哈希。

### S4 Soak（长跑，手动/夜间）

- 以 S1 链路为单元，100–200 轮；每 25 轮 sync + 关闭/重启一次。
- 采样空闲页、任务、完成记录、磁盘剩余、打开句柄、`/tmp` 文件数、命令耗时。
- 通过：没有单调漂移；每轮结束回到基线；重启后仍可执行；总时长有界。
- 若 TCG 下耗时过长，拆成多个 25 轮区间；不把“跑得久”当通过。

### S5 持久化/恢复

- 每 25 轮 export 源码/产物并逐字节比较；重启后执行 stripped ELF。
- 在 save/输出中途 kill，再 sync/重启；允许半成品存在，但不能污染源文件或
  让后续工具无法继续。
- 不测试任意掉电事务；E07 的边界仍适用。

## 5. 指标与通过标准

| 指标 | 通过标准 |
|---|---|
| `resources` 空闲页/任务/完成记录 | 每个命令/每轮后与基线完全一致 |
| 文件句柄/FatFs 锁 | 无持续增长；关闭/退出后可再次打开 |
| `/tmp`、输出目录 | 只有预期产物；取消/失败后临时文件清理 |
| 源码 | 所有输入 SHA-256 不变 |
| 产物 | guest 执行成功；readelf/nm/ar 静态检查正确 |
| 磁盘 | 失败/取消/清理后回到预期水位 |
| 时间 | 有上限；报告实际耗时，不与真机/宿主比 |
| 稳定性 | QEMU 不 panic、不退出、不永久卡终端 |

任何不确定/偶发失败都保留证据并判失败；不能用重跑一次覆盖。

## 6. 执行顺序与优先级

1. **现在**：S0 + S1（10 轮）建立 E08-3 基线；不改 E08-4 的构建。
2. **E08-4 并行期间**：S3 故障注入和 S2 中等规模，使用固定 Seed/临时盘；
   不与 E08-4 共享 build/ 或日常盘。
3. **E08-4 稳定前**：S2 上限规模 + S5 重启；确认 binutils 基座不会在 GCC
   压力前先漏。
4. **E08-4 之后**：S4 长 soak；若 runtime 变化，重新绑定 Seed 后重跑 S0/S1，
   不沿用旧结论。
5. 完整 OS 压力/E09 试用另列，不由本计划替代。
