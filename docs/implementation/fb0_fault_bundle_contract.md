# FB0 应用故障包 v1 格式及勘查

2026-10-29。本文冻结 FB1/FB2 的首版输入/输出约定，不宣称报告生成器或读取器已经实现。
前提及分期见[应用故障包计划](../plans/app_fault_bundle.md)。FB0各项实测结果与未完成项
由工作记录单独登记；本格式不是新 syscall，不改变48字节 `process_status`。

## 取数、身份与单次消费

xsh 诊断运行是首版唯一生产者；它创建/等待其直接子进程，在既有 `result_line` 的
`wait(child,status)` 成功返回处复制 status 到用户态报告工作项。成功 wait 已消费记录；
不能异步另起消费者再 wait。wait 失败保持真实错误，不生成假故障；对可能阻塞的文件
I/O，先输出原运行结果，再保存。若启动者在取数前退出，按当前内核父子规则处理，
不保证产出报告。收集期间无新增 PID 查询权限，也不从串口提取其他进程信息。

运行 ID 使用16字节随机数的小写十六进制32字符；使用已有安全随机接口且检查失败。
随机不可用时不创建持久包，报告未保存，不使用 PID、墙钟或固定种子替代。创建目录
必须检查已存在，冲突时有限次重试；ID 是区分符而非授权凭据。一个 run_id 只代表一次
已绑定启动尝试；普通退出与 kill 可按用户选择报告，不伪称 fault。

文件 ELF 来源必须由装载器持有的读句柄逐块读取全部字节计算 SHA-256，保持同一
打开实例到全部载入页复制完成；在启动前读取/哈希失败则诊断运行失败或以明确 unknown
模式运行（由调用者选择），不在退出后依路径重开补算。用于符号化的运行ELF、带符号ELF
可能不同，必须由构建回执明确关联两份摘要；只认名称不算关联。exec后无法绑定的映像
标记 unknown；内建映像和多进程链在FB1不宣称已覆盖。路径、SDK标识仅为生产者提供的
元数据，不能作为授权或证明真实身份。内核传给父进程的 status 是内核来源，其余字段
明确标为 loader/collector/host 来源。

## 包布局和编码（v1）

每包一个根目录，固定文件 `report.json`、`image.json`、`context.json` 和最后发布的
`manifest.json`；不创建 `log.txt`，日志采集留FB3。文件名为精确ASCII，拒绝大小写
别名、链接、子目录及其他文件。所有JSON为UTF-8、无BOM、单个对象，拒绝重复键、
未知键、无效UTF-8、整数溢出、嵌套超过8层及版本不等于1；解析器读取前检查长度。
对象中的字段均必需，未知值显式为JSON null，不省略也不填假值；本节未规定扩展。

- `report.json`：`version`=1、`run_id`（32位小写hex）、`status_version`=1、
  `outcome`（`exited`/`faulted`/`killed`）、`pid`（16位小写hex字符串）、`code`（有符号
  64位十进制字符串）、`vector`（0至255的十进制整数或null）、`address`/`instruction`（16位小写
  hex字符串或null）。fault时vector及instruction必填；address仅vector 14有效，其值
  允许为零。非fault的vector/address/instruction均为null，且code为内核返回原值。
- `image.json`：`version`=1、`run_id`、`source`（`file`/`unknown`）、`size`（0至4294967295的
  JSON整数或null）、`sha256`（64位小写hex或null）、`elf_type`（`ET_EXEC`或null）、
  `sdk_profile`（不超过128 UTF-8字节的字符串或null）、`build_id`（同上）。`file`时
  size/sha256必填；unknown时二者为null。sha256为装载实例实际字节摘要。
- `context.json`：`version`=1、`run_id`、`collector_version`（1至64 UTF-8字节）、
  `system_build_id`（1至128 UTF-8字节或null）、`monotonic_ns`（无符号64位十进制
  字符串或null）、`utc_ns`（有符号64位十进制字符串或null）。时钟取值失败为null；
  原始地址、路径与上下文本身仍可能敏感，导出前应先给用户查看。
- `manifest.json`：`version`=1、`run_id`、`state`=`complete`、`files`对象。files恰有
  上述三个文件名，每个值恰有 `size`（非负JSON整数）和 `sha256`（小写64位hex）；
  摘要覆盖文件原始字节，manifest不包含自身。四份文件的version和run_id必须一致。
  完整包以存在、解析和摘要均通过的manifest为必要条件；不能将manifest存在本身
  当作磁盘已安全写入或来源可信的证明。

大小上限：每个JSON文件8 KiB，JSON合计32 KiB，目录总计128 KiB；同一收集器最多
16包且总计不超过2 MiB。首次实现为满额拒绝，不自动删除未知文件。UTF-8字符串长度
按编码后的字节计算；各字符串还受单文件与总量上限。64位十进制字符串采用规范形式
（零为`0`、其余无前导零；负值以`-`开头、禁止`-0`），十六进制不得带`0x`。

## 持久化与故障语义

候选流程是独立新目录写各内容、检查每次写入长度/close/sync，最后以可核对方式写入
manifest并再次sync。若无法证明某步完成则显示失败或UNKNOWN，保留原始进程状态，
不可报告已保存；中途无完整manifest的包是partial。该流程只目标正常同步及重启后可
读，不承诺突然断电/扇区撕裂原子性。实际创建、最终发布与恢复的具体API须在FB1真实
失败夹具验证；既有xypm事务或编辑器单文件资格不自动适用。

文件服务调用实现有8192次接收/让出上限，耗时不等于有保证的墙钟截止；发送失败、
响应超时和真实I/O错误分别记录。尤其发送成功后没有响应时结果可能未知，不能推断
请求未执行或盲目重试覆盖。保存不可达时只输出既有最小结果；若调用未能在可测范围
返回，自动保存标blocked，不得宣称故障报告可用。日志、参数、环境、内存和全寄存器
默认不收集；哈希检测损坏，不是签名或可信来源证明。

## FB1 接续

先在 loader 的同一 reader 生命周期引入测试型流式哈希及回执，验证文件不可替换、
短读/关闭失败与启动回滚；在 xsh wait 唯一消费者接入报告工作项。编码器和解析器
需要格式往返、重复键/未知键/非法数值/错摘要/截断/超额拒绝测试；客体需验证异常、
正常退出、kill、资源回收与保存错误。文件服务退出、同实例ELF哈希与用户态生产者
的实测覆盖以FB0工作记录为准，未通过项目不得提前写成支持。
