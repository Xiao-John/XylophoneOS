# 音频输出计划：PC Speaker 单音到可选 PCM

2026-10-29，基线 `94f8e30`。用户已要求编写计划；本文是待实施方案，
AU0–AU5 均未实施、未运行专项验收。不预占 syscall、设备号或服务协议编号。

## 目标与分期选择

先让 XylophoneOS 播放可取消、可静音、退出后不会持续鸣叫的短旋律，形成可复用的
用户态声音入口。首版选择 PC Speaker 方波单音，演示通知音与一段自制旋律。
不默认开机鸣叫，也不改变故障诊断、Shell 或 GUI 的成功/失败语义。

PC Speaker 是独立的第一项交付，不是 PCM 音频已完成的证明。第二条可选线再评估
QEMU AC'97，或在实际探针显示更合适时选择 HDA；只落地一种 PCM 后端。
PCM 先做一种固定格式的 WAV 播放，之后才评估混音、第三方解码或 Qt/SDL 消费者。

首版不实施采音、麦克风、MP3/AAC、MIDI 合成器、蓝牙、USB 音频、网络音频、完整
POSIX `/dev/dsp`、PulseAudio/PipeWire/ALSA 兼容或实时音频承诺。PC Speaker 不能
提供 PCM 音量/混音质量，也不作为木琴音色采样器；后者依赖 PCM 和素材许可。

## 当前基底与缺口

| 源码/环境 | 当前事实 | 必须补齐的内容 |
|---|---|---|
| `src/kernel/platform/pc/interrupts.cpp` | PIT channel 0 产生调度时钟；使用 `0x40`/`0x43` | Speaker 不能重编程 channel 0，也不能改变现有时钟频率 |
| `src/kernel/platform/pc/` | 已有 PC 输出、RTC、PS/2、ATA等设备实现，没有音频实现 | PC Speaker 平台后端、受控访问、强制静音和生命周期 |
| 线程时钟与等待 ABI | 已有单调时钟、sleep_until、wait_word等受限能力 | 核对时间粒度、服务排队与终止；不把 sleep 成功当作音频准时送达 |
| IPC/句柄与进程退出 | 已有认证主体与资源回收机制 | 音频会话/设备租约如何授予、撤销，旧连接如何失效 |
| `scripts/run_qemu.py` | 固定单核 TCG、串口、std VGA；当前未显式配置音频后端 | 可选择的宿主输出和 WAV 捕获路径；默认无音频的已有运行路径保留 |
| ABI 登记 | 现有编号到 66；后续号段有其他责任范围 | 没有现成音频 syscall 或服务协议，不能私自使用空闲号 |

时钟/设备的存在不代表声音可听；QEMU 必须连到实际音频后端。云环境可能没有扬声器，
因此自动测试首先使用捕获文件证明输出，人工试听单列，未试听不写成“已听到”。

## 微内核分层与最小机制

| 层次 | 责任 | 边界 |
|---|---|---|
| PC 平台后端 | PIT channel 2 和 Speaker gate 的窄硬件操作 | `src/kernel/platform/pc/`；ISA I/O 指令经架构接口，不放到通用 core 或应用 |
| 内核机制 | 认证设备使用主体、验证范围、租约到期/退出撤销、必要设备停止 | 不解析音名、旋律、WAV、包路径或 Qt 对象；不按进程名字授予权利 |
| 用户态音频服务/模块 | 接收有界请求、排队/拒绝、取消、静音策略与应用会话 | 复用 IPC；序列/解码/混音策略不放入调度器或内核 |
| SDK 与应用 | 有版本的客户端、短旋律工具、后续播放器 | 按显式授予的连接使用；只读文件权限不自动授予设备控制 |
| 宿主验证 | 显式 QEMU 后端、WAV 捕获、信号分析及人工试听 | 不用宿主播放模拟客体硬件输出，不自动访问麦克风 |

AU0 必须先比较：现有受控设备机制能否满足、用户态安全端口访问是否真实存在、
窄平台操作加设备租约是否更小。当前没有可假定可用的通用端口授权，不能给任意程序
IOPL 或直接使用 I/O 指令。推荐仅在实际缺口证实后增加窄设备机制，并说明现有 IPC
为何不能单独操作硬件；不借第一声提示音建设全套驱动框架。

音频服务名称是用户态约定。启动者必须基于已认证的连接与可委派权利授予设备使用者，
不能复制显示等既有服务的名称/固定 PID 特判来制造音频权限。若现有委派模型不足，
先设计真实授权链，不写固定成功的服务注册。接口设计按
[宪法](../xos_plan.md) C20–C25 与[ABI登记](../contracts/abi_registry.md)推进。

## AU1：PC Speaker 硬件与安全停止

拟使用 PIT channel 2：通道数据端口 `0x42`，命令端口 `0x43` 只发送选择 channel 2
的控制字；Speaker gate 经 `0x61` 控制。共享端口采用读改写保留无关位，临界区
保持有界，不覆盖 channel 0/1 配置；具体控制字与设备模型在 AU0 对照资料核定。

候选频率范围为 40–5000 Hz，依据 PIT 输入时钟 1193182 Hz 计算整数分频，先检查
输入/取整/分频范围，再设置硬件。对外区分请求频率、分频值与实际近似频率，不承诺
任意频率精确等于整数 Hz。休止符是显式停止状态，不用 0 作除数或假装静音音符。

每次硬件发声都带受验证的最大有效期。只让用户态 `sleep_until` 后发送 stop 不够：
服务或客户端死锁会留下长鸣。候选做法是有上限的单调截止时间租约，由内核定时机制
在到期后执行必要的静音；通用定时机制只推进截止时间，不解释旋律或应用协议。
具体归属、等待路径和静音 hook 在 AU0 冻结，不能借此向 core 放 PC 端口地址。

必须静音的情况：正常完成、取消、最后一个有效会话退出、设备所有者退出/异常、
租约过期、授权撤销、服务连接失效后的已声明期限及系统 halt。内核 panic 停机路径
应评估是否能安全做尽力静音；若某类故障无法执行清理，保留明确限制，不承诺任意
内核故障或真实硬件失控都能停止。

不忙等待音符时长，不关中断整段播放，不为提高音高精度修改调度 PIT。用两项并行
任务和单调时钟对照，证明播放期间调度、终端输入及原等待超时仍工作。

## AU2：单音服务与用户入口

建议的 SDK 概念操作为查询能力、打开会话、提交单音序列、查询结果、取消和关闭；
这些是待冻结语义，不是已分配的 wire operation 或 syscall。
首版一次只有一项设备播放任务，额外请求返回 busy；不默认无限排队、混音或抢占。

| 请求要素 | 候选约束 |
|---|---|
| 会话 | 内核认证调用主体，持有实际授予的端点/权利；旧 handle 不指向重启后的服务 |
| 序列 | 1–64 项，每项为 tone 或 rest；总长至多 10 秒；单项 10–2000 ms |
| 时间 | 内部使用单调绝对截止时间，检查累计溢出；量化粒度以实际 tick 声明 |
| 并发/配额 | 首版 1 个活跃序列、最多 8 个会话；各项上限在 AU0 实测后冻结 |
| 音量 | 首版仅 mute/unmute；方波没有线性 PCM 音量，不提供假百分比接口 |
| 取消 | 只取消本会话任务；重复取消返回稳定的已结束状态，不停止别人的新任务 |
| 结果 | 分开 accepted、playing、completed、cancelled、expired、device_lost 与错误 |

命令入口可采用 `tone <Hz> <ms>` 和 `melody <file>`，名称及文本格式在 AU0 冻结。
旋律在用户态预校验或有界流式读取，非法序列不能半校验后无限播放。服务使用内核
认证的 IPC 发送者；消息自报 PID、路径、程序名不授予权利。

payload 必须遵守实际 IPC 消息大小，不能假定现有 64 字节默认通道可一次携带完整序列。
AU0 比较小分块、有界服务存储与现有传输机制，冻结版本/长度/提交顺序、失败丢弃、
重复提交和取消竞争语义；未提交完整的序列不得开始播放。

全局静音/设备重置仅由被授予管理权的主体操作。默认不自动重连重播；服务死后已
受理但未有终态的请求可为结果未知。客户端可观察失败，重启后的新会话不继承旧任务。
若尚无通用断连通知或有界等待，先记录并解决公共缺口，再承诺 cancel/失联期限。

PC Speaker 首版不提供音量渐变和多声部，也不通过高频 gate 抖动冒充 PCM 后端。
客户端取消与服务停止的最长延迟，候选为两次实际调度 tick 加一次已测服务调度延迟；
AU0 必须将其换成可重复测量的上限。不得先承诺未经 TCG 压力验证的硬实时毫秒数。

## 宿主输出与可重复验收

音频选项由调用者显式启用，不改变默认 `make smoke` 的设备拓扑。先核对 QEMU
11.1.2 的 `-audiodev help`、`-machine pc-i440fx-10.0,help` 与设备帮助，确认 PC Speaker
音频路由。候选命令片段如下，AU0 验证成功后才写成正式使用命令：

```sh
-audiodev wav,id=xos_audio,path=<private_capture.wav>
-machine pc-i440fx-10.0,pcspk-audiodev=xos_audio
```

此片段应与既有 machine 配置合并，不额外创建第二个 machine。捕获只写私有 `build/`
目录，停止 QEMU 后再检查 WAV 头、帧数、频率、静音区间与结束后的无持续信号。
WAV 捕获证明客体设备经过 QEMU 输出链，不能证明真实扬声器的声压、音色或延迟。

为人工试听另选宿主实际可用后端，不假设云机有 ALSA/PulseAudio/SDL；失败要显示
后端不可用，不能静默切到 null 后宣称声音通过。无音频后端的旧启动与静音降级另验。
测试使用短、自制、无版权争议的波形/旋律，默认静音，不自动占用用户宿主设备。

## AU3–AU5：可选 PCM 与应用移植

### AU3 设备与数据通路

在单音交付后独立勘查 QEMU AC'97 与 HDA，先核 PCI 枚举、BAR、DMA、IRQ 路由、
物理内存约束与缓存一致性；当前 PS/2/ATA/PIT 经验不能代替 PCI 音频已可用。
建议优先评估 AC'97 的成本，只选一个有证据的后端，不同时实现两套驱动。

PCM 候选格式为 48 kHz、双声道、16-bit little-endian；AU3 依据真实设备能力核定，
不能支持的格式返回 unsupported，不自动按另一个格式解释。先播放生成的短正弦样本，
再接文件；设备/服务资源所有者与播放会话分开。

新增 DMA 机制必须说明页面固定、可访问物理范围、描述符校验、写入方向、配额、
映射撤销、关闭时停止 DMA/确认设备停机后才释放内存，以及设备异常时隔离/降级。
未经校验的物理地址、用户指针和任意端口访问都不向普通应用开放。IRQ/设备必要机制
可以在内核，解码、混音与文件路径仍在用户态；不因“用户态驱动”口号绕过 DMA 安全。

第一版使用有界拷贝缓冲，候选总量不超过 64 KiB，数据不足输出静音并计 underrun，
不得重放未初始化或上一个进程的数据。写入返回值表示接受的帧数；已接受、已送设备、
已消费和 drain 完成分开。取消/超时/设备移除时不得无限等待 drain。
首版无共享内存、零拷贝或实时优先级前置；若 DMA/PCI 基底成本过大，本阶段可停在
勘查结论，不阻碍单音交付。这里的 PCI、DMA 与中断改造均不是当前功能。

### AU4 WAV 与播放器

先支持 RIFF/WAVE PCM、唯一冻结的音频格式、有界分块读取。检查 chunk 长度/填充、
算术溢出、文件截断、数据帧对齐和重复关键 chunk，未知格式明确拒绝。
限额按帧/缓冲而非一次加载整首文件，支持停止、退出、短读和 I/O 失败；不把残缺文件
以 completed 状态返回。播放器只持文件读取权和音频会话，不获得设备/DMA管理权。

复用成熟小型解析/解码组件前先固定版本/哈希、实际文件与许可证；只播放 PCM WAV
时不预先引入 FFmpeg。音频素材、样本和音序文件同样记录来源/分发许可。

### AU5 消费者与后续

PC Speaker 客户端 API 与 PCM 帧 API 分开查询能力；同一上层应用可以选择实际后端，
不让方波伪装成完整 PCM。按需求扩展通知音、Qt 应用、小游戏与混音；Qt Multimedia
或 SDL audio backend 分别做固定版本的移植勘查，不因已有 Qt Widgets/QPA就宣称
它们可运行。首批消费者无需等待完整 POSIX、SMP、GPU、录音或第三方编码器。

多客户端混音、重采样、PCM 音量、设备热插拔和低延迟分别验收。混音需要明确幅度
累加、饱和裁剪、静音、流终止与饥饿规则，不能以两条线程轮流写缓冲代替混音。

## 交付与 gate

| 阶段 | 交付 | 最小验收 |
|---|---|---|
| AU0 勘查冻结 | 设备/授权/截止时间清单、QEMU捕获探针、预算/错误/服务协议草案 | channel 0/2 隔离；实际音频路由可测；调用主体与失联期限明确；无私占 ABI |
| AU1 单音机制 | 窄平台后端、租约与强制停止 | 多个音高、静音/休止、非法频率/时长/溢出、无权请求；到期/所有者退出/故障后不长鸣；调度时钟不漂移 |
| AU2 服务与演示 | 有界序列、SDK/命令、取消与静音 | 完整提交才播放、busy/配额、取消竞争与会话复用、服务死亡/重启、双程序隔离；捕获波形与资源回收 |
| AU3 PCM 基底 | 一种设备和有界帧缓冲 | 固定格式波形、DMA边界/退出回收、欠载静音、设备失败、有限drain；不泄露旧缓冲 |
| AU4 文件播放 | WAV播放器与独立XPK | 合法/坏WAV、长文件流式、I/O错误/取消、实际输出与退出；单音回归 |
| AU5 应用交付 | 已选择消费者、许可与用户说明 | 干净安装、能力缺失提示、明确后端与格式；Qt/SDL等各自独立证据 |

AU0–AU2 构成首个可交付功能；AU3–AU5 依探针与需求继续，不自动成为当前 GUI 或发行前置。
PC Speaker 上的波形输出不证明 PCM/DMA 通过，宿主波形测试不替代客体权限/回收测试。
人工听觉、自动波形、功能/故障与性能分别登记；性能记录实际 TCG 配置、CPU占用、
定时误差、取消/停止延迟、underrun与资源计数，不声称硬实时或真实硬件已验。

## 文件范围与下一步

AU0先在独立 `codex/` 分支、私有 build 子目录做有限探针，不动公共构建或新增 ABI。
后续按实际模块落到 PC 平台后端、窄公共声明、用户态服务/SDK、播放程序与定向测试。
需要共享头/分发/manifest时先登记，并同步普通/线程SDK；服务策略不堆入 tasks.cpp。
接口必须说明版本、单位、宽度、时间基准、可用能力和失败行为，不能以路径名授权。

优先执行 AU0 的 PC Speaker→QEMU WAV 捕获探针，再冻结有期限的设备使用与退出静音
契约。PCM仅做候选成本评估，不提前创建空驱动目录或导入解码库。
回归按实际影响覆盖 PIT/线程等待、隔离/授权、设备回收及原启动路径；当前仅计划文档，
尚无客体音频、人工试听或任何新资格结果。
