# 日常工具集设计

2026-10-27，DU0设计稿。P类实施方案，未实现、未冻结新SDK/profile或引导载荷格式，
不代表工具已安装或通过验收。用户要求先设计，统一补齐；不在本轮修改程序。

## 目标与现状

让新安装的XOS从xsh启动dash后，可以直接列目录、管理文件、查看/处理文本及运行开发脚本。
工具是可独立安装的用户程序，两种Shell共享同一文件系统/执行契约；不扩大xsh内建来补dash。

| 层 | 核对结果 |
|---|---|
| dash内建 | pwd/cd、echo/printf/read、test/[、true/false及环境/Shell控制等有入口；具体范围受Shell契约约束 |
| 独立日常工具 | scripts/build_sbase.py仅构建cat/cp/mkdir/mv/rm，且为受限适配 |
| 构建/发行 | 普通系统构建不自动安装它们；1026发行通过额外ELF清单携带这五个，未含ls |
| xsh命令 | ls等为xsh内部实现，不自动成为dash可搜索的/usr/bin程序 |
| 文件底座 | libc已有opendir/readdir/closedir/stat等入口，不表示完整权限/时间戳/链接/locale |
| 交付缺口 | 现有ISO携带dash单程序，不等于日常工具包；新make disk仍应保持无隐式预装 |

当前依据：scripts/build_sbase.py、src/ports/sbase/README.md与source_lock、
scripts/package_release.py及build/releases/0.0.1-1026/release_manifest.json。
本地receipt用于核对已有发行，不因设计改写或重新发布。

## 命令范围

每项支持面必须单列，unsupported选项明确诊断/非零，不当作文件名误操作，也不静默忽略。
下面是目标行为，不是既有实现声明。基础工具集是XOS自定义子集，不称完整POSIX/coreutils。

### DU1 文件与目录（先让ls可用）

| 命令 | 首批目标支持面 | 依赖/验收重点 |
|---|---|---|
| ls | 默认单列、-1/-a/-A/-d，多个文件/目录操作数；确定性C字节序排序 | 点项/隐藏项、空目录、错误与资源回收；-l/-R/-F等后续，不用合成0777属性假报可执行/权限 |
| cat | stdin、文件、-、多个输入，保留字节 | 短读写/EOF、管道、文件失败后退出状态 |
| cp | 普通文件复制；目标文件及已有目标目录；明确覆盖/同一文件检测 | 源目标身份、短写/满盘/关闭失败；普通cp不承诺原子覆盖，失败不能误报成功 |
| mv | 同卷rename，目标文件及已有目标目录，明确冲突策略 | 对象身份/已存在/打开实例限制；不伪造跨卷复制后删除 |
| rm | 普通文件、-f、--和多个操作数 | 缺失/目录/权限/I/O错误分开；首批不递归删除，拒绝目录而不是暗转rmdir |
| mkdir | 多路径、-p、-- | 已存在目录与非目录冲突分开，组件失败返回真实错误 |
| rmdir | 多路径、--，仅空目录 | 非空/根目录/无效路径、打开对象与身份错误 |

现有五工具须按该目标重新逐项审计，不能以“已有文件”推定这些选项已支持。
不完整支持的行为须显式记录偏差；例如普通cp失败后的部分目标文件行为要与上游选择一致，
不能将文件服务的staging承诺自动扩展成所有工具的事务保证。

### DU2 文本与脚本常用组件

| 命令 | 首批目标 | 依赖/验收重点 |
|---|---|---|
| head | 默认10行、-n非负计数、stdin/-/文件 | 空行、无末尾换行、多个输入、边界/溢出 |
| tail | 默认10行、-n非负计数、stdin/-/文件 | 非seek管道与有界内存策略，较长输入；-f后续 |
| wc | -l/-w/-c及默认组合，多个输入/合计 | 换行/字节/词定义按声明locale；不把字节数假报字符数；-m待多字节语义 |
| tee | stdin到stdout和文件、-a | 任一目标失败的诊断/状态，不能吞短写/满盘 |
| basename | 单路径、可选suffix | 空串、尾斜杠、根路径及按标准核对的边界 |
| dirname | 单路径 | 与basename同组冻结标准输入/输出，不以简单字符串截断替代语义 |

首批文件/文本命令共13个：7个DU1、6个DU2。echo/printf/pwd/test等暂不重复造外部版本；
若消费者确实要求/usr/bin/printf等路径，再作为外部工具另加，不假设内建可替代显式路径。

### DU3 环境、时间与进一步处理

| 命令/组 | 目标与前置 |
|---|---|
| env、printenv | 环境枚举/查询；env支持-i、NAME=VALUE及执行命令，必须核PATH/exec/继承/退出码；printenv缺变量返回非零 |
| sleep | 实际时钟等待、合法持续时间解析与溢出拒绝；不忙轮询，信号中断行为随PX1另核 |
| touch | 创建及已有文件的真实时间更新；须先有文件时间元数据/更新接口，不能对已有文件无操作却报告更新时间成功 |
| date、ls -l | 只读墙钟可先独立实现；完整列出文件时间/权限/主体仍依赖真实元数据，不展示合成属性冒充真实事实 |
| grep、sed、find | 优先核固定上游的正则/遍历/表达式依赖；不是先写同名字面串过滤器冒充标准工具 |
| sort、uniq、cut、tr | 明确字节/C-locale、字段与多字节边界；按真实脚本需要逐项冻结选项 |
| cp -R、rm -r、ls -R等 | 遍历/循环/身份/失败与配额专项后开放，不能用不完整递归破坏用户文件 |

DU3各项可独立交付，不让touch元数据或完整grep阻塞基础ls。DU1/2完成也不是宣布
“所有日常工具齐全”；后续选择以真实脚本与用户需要登记。

## 统一语义与实现路线

- 继续优先评估现有固定sbase来源c546c3a及其MIT材料；每个新命令重新核调用和许可/来源，
  扩展source_lock的实际文件摘要，不把仓库完整性或未核命令推定已验证。优先维护上游逻辑，
  将必要XOS适配集中在端口/运行库边界；不要建立另一套私有mini-libc。
- 现有适配是人工收窄的代码，须区分上游原样文件与自研/改写部分，保留原声明和新增授权。
  若某命令不适合现有来源，再按实际成本选成熟实现，不在本设计预设第二套大依赖。
- 程序放/usr/bin，数据/许可随包；stdin/stdout/stderr按继承FD使用，正常输出不夹调试文字。
  短读写、EOF、EINTR/EAGAIN、EPIPE及部分失败遵循当前SDK/专项范围，未知选项不默默成功。
- DU1/2优先流式处理；tail环形缓冲、ls排序等须先声明数据/内存预算，超限真实失败。
  不把固定截断输出伪装为完整列表。目录枚举不是全局快照，并发变化按实际错误/语义处理。
- 路径按实际SDK/profile声明。UTF-8文件名工作已在独立分支，尚未在当前分支整合；先基于
  ASCII基线验收，再对合入后的UTF-8路径定向验收。文件内容逐字节保真与locale/字符宽度分开。
- 文件名不授予构造权；env exec及一般工具只持其已有权限，不为工具名增内核特判。
  仅为ls不新增syscall。真实底座缺口按ABI登记与文件服务协议流程处理，不预占新编号。

## 构建、SDK/profile与包

设计统一daily-utilities清单作为构建/安装/验收的共同输入，列出每个命令的来源/支持面、
源码/补丁、目标SDK/profile、guest路径、ELF摘要/尺寸、许可及状态；避免三处手抄工具名。
清单不是自身信任证明，打包/安装仍校验实际内容与全部路径。

- 扩展scripts/build_sbase.py或拆成明确的通用构建入口，保留既有五工具回执，不覆盖旧cache。
- 使用支持C3文件stdio/pipe继承的当前CRT/SDK。旧single-b2-v1包profile不能未经迁移就宣称
  接受新SDK；DU4入包前冻结新的工具包profile及ELF/运行库契约，再与xypm共同登记/验收。
  DU1/2可先用匹配SDK独立ELF做定向验证，不等待包管理和ISO安装器的全部扩展。
- 拟采用单个基础工具XPK（包ID在实现时核归属后冻结），避免17个库/许可清单各自漂移；
  工具仍为独立ELF。若引入multicall，须另验argv[0]/别名及安装方式，不在首批默认采用。
- 不依赖符号链接或/bin/sh；既有五工具迁入新包时检查未归属/已修改目标，不能无条件覆盖。
  不能卸载后悄悄删除用户创建文件；新旧版本/profile变迁须有明确安装/迁移方案。

## DU4 交付闭环

目标是同一已验工具包同时服务开发盘准备、发行工作盘和未来ISO安装，不修改旧1026资产。

1. 开发路径：显式构建包→在新候选盘离线安装→xsh/dash验证；普通make build不隐式
   修改日常盘，make disk继续创建干净工作盘。说明书明确“空盘”和“已准备开发环境”。
2. 发行路径：发布打包器读取同一包/安装清单，替代手填多个--extra-elf参数；逐文件核对
   包、镜像、SDK/profile、路径和摘要。不能仅证明宿主目录里有ls。
3. ISO完整安装：现有payload只交付dash，不能只往ISO放BASEUTIL.XPK就宣布已安装。
   需专项设计通用安装数据载荷及用户态安装流程：引导器交付有界不透明字节，内核仅保持
   通用payload读取/生命周期，归档解析/路径/依赖/安装策略留用户态，不在内核识别工具包。
4. 安装容器版本、目录/完整性、容量与旧载荷兼容在DU4实施前冻结后另实施；沿现有ISO容量预算，
   实测所有ELF/许可/包总量与启动资源，不预先承诺17工具必然装得下。若改变ABI先登记。
5. 客体写安装使用合入并验收后的xypm P2/内置恢复器，避免第二套覆盖文件/事务实现。
   P2独立分支资格不直接改绑本分支；安装包自身不能依赖尚未安装的工具来完成安装。

DU1/2可先交付显式准备的开发盘，但DU4最终验收必须覆盖从空盘+ISO开始的完整过程。
没有该结果前，文档不得写“启动ISO即可获得完整日常工具”。

## 批次与验收

| 批次 | 完成判据 |
|---|---|
| DU0 | 本设计、首批精确清单/支持面；DU1前冻结源码/预算/SDK，DU4前冻结包profile与安装载荷方案。本轮仅设计文档，其他未运行 |
| DU1 | 七个文件工具逐项构建；ls默认/-a/-A/-d、文件/目录/错误；原五工具回归与rmdir |
| DU2 | 六个文本工具在文件/stdin/多输入下精确输出/退出；管道和重定向真实运行 |
| DU3 | 每项依赖独立补齐；env真实exec、sleep真实等待、touch元数据等各自gate |
| DU4 | 清单→包→盘→发行/空盘ISO安装全程绑定；失败保护、重启、升级归属与资源验证 |

每批客体至少覆盖：/usr/bin显式路径及dash PATH查找，xsh调用同一ELF，stdin/stdout/stderr、
管道/重定向、缺失/无效选项/不可写/部分I/O错误；输出字节与退出码、资源基线/终值。
ls测试点项、混合操作数、隐藏文件、多个目录和预算；文件修改工具核原文/用户文件及失败状态。
文本测试空文件、空行、无末尾换行、二进制/NUL、长行与有界内存；UTF-8路径另绑定合入后基线。

行为按固定标准/上游版本选定输入与宿主参考逐项对照，不用宿主执行代替目标运行。新包profile
至少验旧profile拒绝、当前SDK准入及文件stdio/pipeline继承。安装验收用私有盘，缺包/损坏/
部分安装/重启不能破坏已有文件，限于已声明故障模型，不冒称任意掉电安全。

命令台账状态用planned/built_not_run/accepted_subset/unsupported分别记录，报告绑定源码、
工具链、SDK、ELF、包、镜像、安装清单、环境与夹具。只跑新增及受影响回归，长期压力专人负责。

## 实施文件与协作边界

- src/ports/sbase/：现有来源、适配与支持矩阵；src/user/libc/缺口由运行库线处理。
- scripts/：构建/打包/安装清单接入，按实际职责拆分，不堆进系统构建器或复制xypm事务。
- tests/：共享输入与目标/宿主对照、Shell/包/安装专项；新文件snake_case。
- docs/implementation/：真实交付后才新增当前工具范围；本文件继续保留后续目标与偏差。

本轮未派工、未实现、未构建、未修改安装器或发行，也未新增第三方依赖。下一步先做DU0
输入/清单/profile审计并冻结DU1接口，随后实施ls与既有五工具整合；不先扩大xsh功能。
