# 日常工具 DU4：通用 ISO 安装载荷设计

2026-10-28，设计中；不代表 ISO 安装已经实现或验收。目标、项目边界和完整验收见
日常工具设计；已运行的包与 P2 组合证据见[0069](../work_log/0069_daily_utilities.md)。

## 问题和约束

当前 BIOS file-backed ISO loader 只把根目录 `DASH.ELF` 作为不透明字节交付；
`sys_boot_payload` 只允许 supervisor 读取，现有用户态把完整载荷视为 dash ELF。
因此附加 XPK 到 ISO 不会自动安装，直接在内核读取包/决定路径违反 C01/C21。
不扩权限、不按程序名或路径授权；保持旧仅 dash 和无载荷启动兼容。

## 建议的版本化容器

- ISO 根目录保留 `DASH.ELF` 文件名以兼容现有 loader，内容为独立识别的 `XOSBND1`
  容器；若不是容器且是合规旧 dash ELF，继续旧路径。容器格式/命名只是当前载荷的
  外层约定，固件、loader、内核只传递不透明字节，不解析成员或依赖。
- 固定宽度、小端、版本 1、总长和记录数显式；有界成员清单携带类型、偏移、长度和
  SHA-256。类型只在用户态解释，允许多个 XPK，但首版冻结受限的 bootstrap xypm、
  dash 和日常工具包。拒绝未知版本/类型、重复角色、重叠、越界、溢出、缺项、畸形
  ELF/XPK 和哈希不符；绝不能回退为旧 dash 来执行未知容器。
- 建议最大总长沿用现有 32 MiB payload 预算，成员数、元数据长度、路径、对齐和各项
  上限在编码实现前由实际包大小冻结。现有工具包约 10 MiB，尚未包含完整启动组合，
  不据此推断一定满足总预算。摘要只检测损坏，不提供签名或发布者身份。

## 客体端执行与权限

1. supervisor 在用户态验证整个容器边界和成员摘要，然后准备 dash、bootstrap xypm 和
   所需 XPK；拒绝覆盖未知已有文件，不能用文件名或自报包身份授予维护权。
2. 维护入口依据可信 supervisor 的明确委派和实际子进程身份，使用 P2 的进程门禁、
   维护租约和 journal 安装 xypm 包及工具包。先核 bootstrap 程序的不可替换来源、
   检查到装载的对象身份和并发窗口；可考虑从受控载荷 reader 直接加载同一已校验
   快照。不能校验某条路径后再打开一个可被换掉的文件来授权。
3. 安装包/目标状态按 P2 真实归属检查；已有相同受管理安装、版本不符、未托管文件
   冲突、缺空间、校验失败、启动失败分别制定可观察的退出/恢复方式。中断后沿用
   xypm journal 与内置恢复器，不建立第二套覆盖/回滚器。
4. 空盘初次安装、重启复用、已安装/本地修改及失败恢复必须分别定义。常规 make disk
   继续只创建空盘；旧 dash ISO 不自动升级为新安装语义。

## 必须先解决的接口与验证

- 确认当前 128 KiB `spawn_buffer` 上限无法直接容纳约 233 KiB 的 stripped xypm；
  评估用户态 loader 对现有受限 payload 的分块 reader，或冻结可行的安全替代；不因移植
  方便添加内核专用包解析或绕过认证的授权机制。新 SDK 接口要同步契约和测试。
- 容器生成器从实际 dash、xypm XPK/ELF、daily XPK 和 profile 生成确定性元数据；
  绑定系统、SDK、工具链、各成员哈希、许可及候选包资格。校验 32 MiB 边界和
  ISO9660 路径/legacy 兼容；不改写已发布 1026 资产。
- 空盘从 ISO 启动后，经真实客体 P2 安装，再运行 dash 和工具，sync/重启核归属与
  文件内容；覆盖重复启动、坏头/坏摘要、截断、超限、冲突、磁盘满、维护失败和恢复。
  过程仅用专用盘，按实际中断模型标注，不能推断任意断电或公开发行资格。

上述是 P 类接续设计，容器字节布局和 ABI 分配尚未冻结，也没有生成或验收该 ISO。
