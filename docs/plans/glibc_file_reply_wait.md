# glibc 文件会话等待

## 范围

统一 glibc SDK 的 Dash 启动静态 Qt Quick 时实测首帧 137.281 秒，xsh 同镜像
为 5.664 秒。文件请求 A/B/A 的正常路径每 192 KiB 等 960 ms。空接收后的
1 ms 定时睡眠按内核 10 ms 时钟粒度唤醒，静态装载按 4 KiB 页拆分的
13,619 条请求可累计约 136.190 秒。等待机制和源数据分开测量。
[Qt Quick 验收 PR](https://github.com/Xiao-John/XylophoneOS/pull/333)

在独立工作树由运行库线负责共享 IPC 等待枚举、现有调度唤醒点、glibc 私有
文件会话及测试与契约。依次完成语义与旧版兼容、真实客体错误路径、候选库重链
和双入口时延回归。静态装载器的页划分、文件服务报文及通用轮询由各自工作线负责。

## 等待原语

在 sys85 增加 `file_reply_until` 模式，复用既有 IPC 等待和绝对单调期限队列。
仅当前进程由 sys22 取得的文件服务回复端点可用。内核核对本端所有者、接收者和
认证服务对端，原子检查应答就绪或登记等待。原模式及 wire 布局保留。
入睡前已就绪和登记后到达都唤醒。回复队列只有实际接收时消费，等待只通知就绪，
不持有用户缓冲区。现有内核只有 generic IPC 端点支持 sys85，而且无法指定期限。
sys81 和 sys88 各自绑定另一套端点，不会观察当前文件回复队列。

第三参数为现有系统单调时钟的绝对纳秒期限，零无效。glibc 延续同一个 5 秒
RPC 上限与调用者给出的更短期限。新内核在到期返回现有线程超时代码。
兼容期只有旧内核对此固定新模式返回 invalid argument 时才回退到现有睡眠
轮询。权限、对端死亡和其他错误都沿失败路径退出，已送达操作仍不重试。

Files 服务启动时获得认证身份，目前只有引导路径设置 `files_pid`。死亡时
先唤醒旧端点的等候者，再由既有清理路径撤销配对 token。将来的重启需要单独
定义新身份和端点分配，旧 token 与已失败的 glibc 会话均不能重新使用。
回复、到期和退出共用调度状态转换。退出会销毁自己的等待者，服务退出唤醒对端；
多个就绪路径以第一个状态转换为准。glibc 在取回消息后仍校验原截止时刻、
请求序号和响应形状。迟到或重复响应均不能使已失败的会话复活。

## 验收

- 主机验证静态和早期 D1 共用的会话流程。覆盖已就绪、等待后就绪、旧内核回退、
  服务死亡、期限已过和期限竞争、信号式中断返回、错误及重复消息、失败状态、
  发送次数和非重放语义。
- 真实客体验证排队前后到达、服务死亡、到期、错端点拒绝、取消回收以及并发读；
  对未实现的 POSIX 信号语义保留实际范围。复用现有 D1 文件接力与 Files 服务
  死亡夹具，核对任务与会话资源回到预期值。
- 新候选 glibc 重链实际 Dash，在同一普通 ISO 从 xsh 和 Dash 启动 Qt Quick
  并完成图形、输入、双周期复开和回收。时延仍以 60 秒默认门测量。
  固定工作量额外记录文件会话吞吐和逐请求时间。
