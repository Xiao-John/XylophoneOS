# 输入与编辑体验第一档：现有终端和行编辑器

2026-10-27。F1/F2 已实现并有定向客体证据，完整验收仍为 partial，见
[0064](../work_log/0064_input_edit_first_stage.md)。本文不修改宪法、现有 ABI 或
POSIX 契约。UTF-8 输入和文件内容为本档优先交付；UTF-8 路径紧随本档推进，详见
[多语言设计](multilingual.md)。第二档见[终端编辑器选型](terminal_editor.md)。

## 目标与现状

在现有串口交互中，能安全修改已有小文件，并能在 Xshell 提示符处方便地改错。
Xshell 仍是默认入口；dash 和 Python 保持各自现有行为，不以本组为它们的实现承诺。

第一档之前 `edit` 位于用户态 supervisor，载入最多 8192 字节、输入行最多 159 字节，
正文只追加，输入只接受可打印 ASCII；已有内容按字节载入。`:w` 使用文件服务
replace，失败时缓冲保留，`:q` 拒绝丢弃脏缓冲。Xshell 行上限为 2047 字节，
合法 UTF-8 校验和尾部按码点退格已有专项；第一档增加行内光标和历史。UTF-8 正文、
路径、终端字符宽度和图形输入是不同能力，见[UTF-8计划](utf8.md)。
旧 [E05](../e05_file_service.md) 记载了历史 RAM 后端，不用于推断当前 FAT 后端
的容量或断电原子性。具体实现以源码与当前文件服务契约为准。

## F1：安全的行式文件编辑

### 文档模型和输入

- 保留 `edit <file>` 和既有 `:w`、`:wq`、`:q`、`:q!`、`:p`、`:c`、`:help`；
  普通正文行仍追加。新命令使用 `:p N [M]` 显示含行号的闭区间，`:i N` 在第 N
  行前插入一行，`:r N` 替换第 N 行，`:d N` 删除第 N 行。行号从 1 起；插入可用
  行数加 1 表示末尾。空文件视为零行；无效行号、参数或超限不改变缓冲。
- 插入与替换命令后读取一条正文行，不解释该行的前导冒号；普通追加时用 `::` 开头
  表示去掉第一个冒号后存入正文，其他未知 `:` 命令报错而不写入正文。帮助须解释转义。
- 文档以字节保存：行由 LF 分隔，CR 是内容的一部分；保留未修改行的所有字节、空行、
  行尾空格及文件末尾有无 LF。替换保留原行是否以 LF 结束；插入与普通追加产生 LF，
  在末尾无 LF 的现有行后追加时先补分隔 LF。删除包含该行原有的结束 LF。
- 普通输入及新行支持合法 UTF-8；输入行不接受 NUL 和未定义控制字节，非法 UTF-8、
  超长或输入中断时整次操作拒绝，不更改文档。已载入的任意字节原样保留，按行删除或
  替换只改变目标字节范围；显示不可打印字节的方案须避免向终端直接注入控制序列，
  采用转义显示，并提供明确标记。行号与修改按原始 LF 字节而非 Unicode 分段。
- 初版继续使用 8192 字节文档和 159 字节输入行上限，按字节计；超限打开必须失败，
  不能编辑截断前缀后覆盖原文件。变更先计算完整结果大小再修改；内存不足和失败不
  留部分编辑。限制可在后续专项增加，不能通过静默截断解决。

### 保存与冲突

- 无修改时保存不改变字节；失败时保留缓冲和 dirty 状态，`:wq` 仅在明确成功后退出。
  缓冲可以导出或打印，错误提示包括文件名、操作和可用错误信息。
- 依赖当前文件服务的 replace 契约，不擅自宣称任意断电原子性或跨客户端无冲突。
  开工先检查版本/替换语义：若不能可靠地在提交点检测外部修改，则明确提示该限制，
  不把独立 stat 后 replace 描述为原子冲突检测。请求超时或服务退出造成提交结果未知时，
  提示结果未知、保留缓冲且不自动重试；后续重新读取核对。
- 正常保存后的持久化与 `sync`/重启分别验证；空间不足、文件服务故障和数据盘错误
  分开记录，不以成功路径推导任意断电安全。

### 验收 F1

在专用客体盘验证新建和已有文件的查看、插入、替换、删除、冒号正文、dirty 退出；
逐字节比较空文件、空行、CRLF、无末尾 LF、UTF-8、已有非 UTF-8、尾随空格、上限及
超限文件。注入无效 UTF-8、超长行、无效行号、空间不足和服务错误，检查缓冲与原文件；
分别验证保存成功、sync 后重启以及可实际注入的未知结果。未能注入的场景标为未运行。

## F2：Xshell 单行编辑

- 在提示符内提供左右、Home/End、Delete、当前位置插入和 Backspace；上/下选择本会话
  历史，保留进入历史前的未提交草稿。只记录成功提交的非空合法行，连续重复可合并；
  历史只存在内存，初版固定 16 条、每条不超过现有行上限，达到上限淘汰最旧项。
- 串口默认支持常见 ANSI/VT 的方向键、Home/End 和 Delete 序列；识别集合在实现与
  帮助中列明。转义解析有固定长度和超时，未知、截断和超时序列整段忽略并提示或静默
  拒绝，不能把尾部碎片当作命令执行。孤立 Escape 在提示符无编辑动作；前台运行时现有
  Escape 取消路径独立保留，不把它描述为 SIGINT。具体超时以可测时钟冻结，测试慢速输入。
- 内部以字节偏移标记光标，仅停在合法 UTF-8 码点边界；提交前整行验证，输入超限、
  非法字节或粘贴异常不能执行截断前缀。按已支持的显示宽度刷新；组合字符、emoji 和
  宽字符表不完整时明确限制，不能声称按字素簇正确。对异步输出和折行先做真实探针，
  若不能可靠重绘，声明单行终端宽度/输出限制并安全回退，不伪造完整终端支持。
- 回车/换行归一化须覆盖 CR、LF、CRLF，保留既有分词和执行权限语义。遇到输入溢出
  整行拒绝并清理到行结束；不得执行剩余片段。后台进程仍可能与 supervisor 竞争 stdin，
  本组不声称解决前后台终端所有权。

### 验收 F2

真实 QEMU 串口注入中间插入/删除、方向/Home/End、历史草稿恢复与淘汰、CR/LF/CRLF、
UTF-8 多字节、无效与分段序列、超长、Escape 和前台取消；核最终 argv/执行结果而不只看
回显。检查控制序列不泄漏、行宽变化/折行和后台输入竞争；未支持的终端按声明回退。
对有现有证据的 UTF-8、Xshell、前台取消路径执行针对性回归。

## F3：可复用部分与交付顺序

先分开交付 F1 和 F2；仅当两个实际消费者需要时，把字节边界、有限状态按键解析或
行缓冲抽为用户态小组件，接口显式传入容量、输入和输出状态，不改变文件或内核 ABI。
Python REPL、dash、全屏终端模式和历史持久化均不在本档交付；其重定向/EOF、控制字符、
许可和终端恢复语义要独立核对。实现前登记文件占用，影响 ABI 时先登记；完成时绑定
源码、SDK、镜像与独立盘报告，并按纪律交接。
