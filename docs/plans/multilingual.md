# XOS 多语言文本与文件：设计路线

2026-10-27。用户要求提高 UTF-8 输入和文件支持的优先级。本页为 P 类设计及分阶段
实施计划；实现和验收状态以各阶段记录为准，不改变宪法和现有 ABI。
第一档已实现并有定向客体证据，完整验收为 partial，见[输入与编辑](input_edit_foundation.md)；原有 U0/U1 证据和约束见
[UTF-8 文本通道](utf8.md)。

## 优先顺序和目前能力

| 优先级 | 范围 | 状态与目标 |
|---|---|---|
| 最高 M1 | 串口 UTF-8 输入和文件内容 | Xshell/dash U0/U1 已有受限资格；本组为 `edit` 增加 UTF-8 正文输入、按字节保留已有内容，与 Xshell 行内编辑一起验收 |
| 高 M2 | UTF-8 文件和目录路径 | 当前未支持；紧接第一档开展设计探针和文件服务实现，作为后续编辑器的重要依赖，不等待 Qt 或完整 locale |
| 后续 M3 | 字符宽度、组合字符、locale | 分别核 Unicode 版本、宽度和应用需求；当前码点退格不是完整字素簇处理 |
| 后续 M4 | 原生键盘布局、字体与输入法 | 对接 E16/QPA、焦点和字体，图形文本与组合输入单独验收，不把宿主输入法冒充客体输入法 |

内容、路径、终端显示和字符语义分别验收。UTF-8 是文本接口编码，不强制把普通文件
当成 UTF-8：加载、未修改保存和不相干行修改必须保留原始字节。当前串口可接收宿主
输入法提交的 UTF-8；图形事件目前只有原始键鼠，不提供文字或 IME。

## M1：文字输入与内容

- Xshell 和编辑器在输入边界接收 UTF-8；跨 read 分片保留残片，提交前拒绝非法、
  截断、overlong、代理区和超出 Unicode 范围的序列，拒绝整次输入而非执行或保存前缀。
  以字节计数容量、拒绝溢出且不覆盖缓冲。正文输入与终端控制字符分开解析。
- 文件内容以字节为单位保存。LF 分行的编辑操作只修改选定范围，保留无末尾换行、
  CRLF、空白以及未修改的非 UTF-8 字节；向终端显示控制/非法字节时转义，不执行它们。
  输入合法性不应变成读取已有文件的附加条件。
- 文本光标至少按 Unicode 码点边界移动；显示宽度按已实现范围标明，不能把近似宽度
  表称为完整字素、emoji 或所有终端宽度支持。组合字符的显示与删除差异作为明确限制。
- 宿主 IME 粘贴、CJK 与拉丁多字节文本、分片、错误序列、容量边界、编辑后逐字节比较
  和保存失败均须在客体测试；保留 ASCII、前台取消、重定向和 UTF-8 现有回归。

## M2：路径和目录专项

现有 [文件 ABI](../../src/shared/include/xos/file_abi.hpp) 的 `max_name` 为 256 字节，
`files.cpp` 的路径校验只接受可见 ASCII；FatFs 开启 LFN，`FF_LFN_UNICODE=0`、
code page 437，自研 `fatfs_unicode.cpp` 只做 ASCII 转换。仅删除 ASCII 拒绝条件
会造成名称错误或碰撞；当前不能声称中文文件名可用。

1. **冻结端到端契约。** 路径以合法 UTF-8 字节传递，保持现有 NUL 终止与路径长度
   边界，分量和 FAT UTF-16 限额分别检查；拒绝 NUL、非法编码、禁止字符、非法分量与
   超长，禁止静默截断。保留根路径、分隔符及已有路径兼容行为。
2. **核 FatFs 配置和转换。** 评估使用其 UTF-8 API 配置与完整 Unicode/OEM 转换所需
   代码、版本、许可、存储与大小；正确处理非 BMP 字符与代理对。不能用不完整映射或
   假大小写映射声称通用 Unicode 支持。明确磁盘已有非法或不可转换名字在列目录时的
   返回方式，不让一个条目破坏整个目录或产生可误操作的替代名字。
3. **统一身份和冲突语义。** FAT 的大小写、短名别名与现有 `names_equal`、打开实例、
   replace、rename、删除及多客户端检查必须使用同一对象身份或一致的比较规则。
   明确大小写折叠与规范化策略、Unicode 版本及碰撞，拒绝歧义；不假设视觉相同的名字
   必然相同，也不通过改变名称静默覆盖其他文件。
4. **贯通消费者。** 检查文件服务、共享协议及 SDK、newlib 路径包装、Xshell、编辑器、
   Python、目录枚举、xypm 和宿主镜像工具；分清协议布局是否变化与仅语义扩展，必要时
   先登记 ABI/version 并保留旧客户端兼容。Xshell 目前按 ASCII 空格分词，因此含空格
   路径还需单独的引用/转义设计，不能只靠 UTF-8 支持宣称可用。
5. **专盘验收。** 创建、列举、stat、打开/读写、重命名、替换、删除、sync 和重启后
   内容/名称逐字节核对；中文、重音、组合形式、非 BMP、大小写、别名碰撞、无效序列、
   长度极限、异常磁盘项及旧 ASCII 名称均覆盖。比较主机与客体访问，但不以主机工具
   写盘成功取代客体验证。数据保护、目录枚举与冲突故障分别记录。

## M3/M4：渐进扩展

先根据真实消费者冻结 Unicode 数据版本、字素边界与宽度表和受支持终端，验证组合字、
全角、emoji、窗口折行；locale 的字符分类/排序/模式匹配分别立项。原生图形输入按
键盘布局→文本提交→组合态/候选窗推进，并验证焦点切换、输入丢失重同步、字体回退
与退出清理；剪贴板与无障碍另定。Qt Widgets 编辑器沿 [Qt 计划](qt.md)，不等待这些
扩展全部完成，但须诚实描述其支持范围。

## 交付纪律

每阶段先登记负责人和文件范围，公共 ABI 变更先登记；测试绑定源码、SDK、镜像、
宿主终端、测试盘及报告，旧资格不改绑。路径工作影响文件安全与第三方代码，须同步
来源/许可及错误测试；不可用或未运行的故障场景逐项列出。
