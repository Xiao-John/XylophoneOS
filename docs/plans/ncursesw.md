# 宽字符终端库：ncursesw 设计

2026-10-28。状态 P：选择 ncursesw 作为可复用终端库的实施方向；版本、配置、接口和
资格尚未冻结。它是用户态库，不是新内核业务或 Qt 前置。终端编辑器优先探查 nano；
[第二档](terminal_editor.md)保留 kg 作为备选。本文不宣称 POSIX、完整 locale 或
Unicode 字素支持，也不改变现行宪法、ABI 和 PX 契约。

## 目标与当前基础

通过真实的通用接口，让独立程序在串口终端上可靠地进入交互、画屏、读取按键、处理
UTF-8 和退出恢复；供编辑器及其他终端程序复用。先完成库的窄 profile，再移植消费者。
不要将某个程序的兼容补丁当作公共终端已完成，也不要为了接口数量把业务加入内核。

Xshell 有受限 UTF-8 行编辑；文件服务 UTF-8 路径有[0068定向证据](../work_log/0068_utf8_filenames.md)，
不等于所有路径/字符语义完成。当前无已验的 POSIX 异步信号、termios、控制终端或作业
控制；有关范围见[POSIX子集](../contracts/posix_subset.md)。QtCore 已有其独立资格，
不能推断 curses 或通用事件等待已通过。

## 分层与责任

1. **用户态终端服务/适配**：管理受控终端对象、输入模式/回显、前台读取所有权、尺寸
   与状态恢复；确定 supervisor 和应用退出、异常或取消时的处理。访问依可信主体与授予
   对象/权限，不以应用名授予。不存在的功能明确返回错误，不能用成功桩冒充 termios。
2. **内核通用机制**：仅按实际缺口提供受保护的对象、阻塞等待/超时、进程生命周期或
   必要的设备机制；先解释现有 IPC/等待为何不足，定义主体、权限、生命周期、失败和
   中断行为。串口硬件/平台细节留正确层次，终端协议与编辑策略不入核；任何新增 ABI
   先在登记中分配，再同步 SDK 和客体测试。
3. **libc 与 SDK**：在目标 newlib 的真实实现上审计 `setlocale`、`mbrtowc`、`wcrtomb`、
   `wcwidth`/`wcswidth`、字符分类、必要文件和终端包装。头文件存在或宿主链接成功不等于
   目标可用；逐项补齐真实缺口并暴露给独立应用。避免重复实现不一致的 UTF-8 宽度表。
4. **ncursesw 与 terminfo**：固定来源/许可证/版本/构建选项，提供匹配的静态库、宽字符
   头文件和 SDK profile。宿主生成工具与目标库分开；固定 `TERM` 与一组实际可用的
   terminfo 数据或内置 fallback，验证格式、查找路径、未知类型与缺失数据失败行为。
5. **应用**：nano 与其他程序只消费公共接口；文件数据保真、保存和崩溃恢复由应用与
   文件服务契约负责，不能从 curses 运行推断文件安全。

上游参考：[ncurses 构建与交叉编译](https://invisible-island.net/ncurses/INSTALL.html)、
[宽字符接口](https://invisible-island.net/ncurses/man/curs_get_wch.3x.html)、
[nano 构建配置](https://www.nano-editor.org/dist/latest/nano.html)。宽/窄库 ABI 和
所选 feature 宏要一致；库本身不自动提供字体、Unicode locale 或终端模拟器。

## 首版 profile 与依赖

- 单核、现有串口和明确指定的一种 VT 兼容宿主终端；单前台交互程序。固定尺寸可由
  配置提供并声明，不能伪造系统自动探测。未知或不支持的终端明确失败或采用经验证的
  fallback；不依赖 GUI、GPU、动态链接、SMP 或完整 POSIX。
- 冻结可使用的读取模式：逐键与无回显、超时/非阻塞的真实行为、短读/EOF/错误和多字节
  分片；终端模式保存、恢复、调用者退出与异常处理必须可观察。明确不支持的标准标志
  返回错误，语义不要用进程私有假状态伪造。ESC/功能键解析有有界等待，避免吞掉文本。
- 宽字符路径至少覆盖 ASCII、UTF-8 中文全角和组合字符的输入输出、光标与刷新。冻结
  宽度数据/版本、非法序列处理和宿主兼容范围；组合字符、emoji、字素簇及终端宽度分歧
  按实际能力声明。应用必须明确启用可用 UTF-8 locale；当前 C locale 不自动等于 UTF-8。
- 首版不要求实现 PX1 全套信号、PX2 全套作业控制或 PX3 全套 poll/select；按实际
  ncurses 调用冻结可行的最小依赖与受限配置。SIGWINCH/动态尺寸、Ctrl-C、挂起与恢复、
  后台作业分别依赖相应真实机制，未实现则禁用或报错。不能将 Escape 取消说成 SIGINT。
- 线程安全不预设；先核选定构建和消费者实际模型。终端重定向、会话/权限隔离与多进程
  并发分别验证；无前台所有权保障时不开放多个读取者冒称安全。

## 分期与证据

### W0：只读勘查与冻结

固定版本和哈希、许可证及构建配置；列出目标源码路径的 `termios`、等待、尺寸、信号、
locale、文件和内存依赖。用目标 SDK 构建最小可链接探针，记录成功、未解析符号、实际
缺失语义和必要预算；configure 的宿主自动检测不得冒充客体能力。先核 newlib 已实现的
内容和版本，不预定新接口编号或新增完整服务。

### W1：复用底座

按 W0 的真实缺口定义终端对象、模式和等待契约，实施 SDK/用户态服务及必要通用机制；
分别覆盖权限、失败、资源回收、正常退出和异常退出。字符转换/宽度按独立 profile 验证。
更新 ABI 登记与契约只针对实际变化；先有机制的消费者探针再扩范围。

### W2：ncursesw 独立交付

使用与目标库相容的宿主工具生成 terminfo，冻结库/头文件/数据及来源；从独立 SDK 构建
真实 XOS 应用。至少两个独立消费者：一个覆盖窗格、颜色/刷新、方向键和中文输入输出，
另一个验证重入终端、尺寸/错误和恢复。第二个可以是小探针，不把 nano 编译成功当成
库的完整资格。声明库版本、功能子集、资源预算、限制和未验证接口。

### W3：nano 评估与移植

确认实际 UTF-8 构建、终端、locale、文件、内存和许可依赖；固定来源与功能选项。以
真实输入、宽字符显示和内容字节保真、保存失败/结果未知为门槛。需实际构建与客体通过
后才正式定型；若依赖代价过高，评估 kg 或 ne，不退化为 ASCII 假通过。

## 验收及边界

所有相关改动提交后，基于提交的源码及匹配 SDK、独立系统镜像与专用测试盘，在实际
QEMU 串口及声明的宿主终端上记录源码、版本、配置、图像/库/terminfo 哈希与结果。
W1/W2 分别验证：UTF-8 分片/非法字节、CJK 宽度与组合字符、方向及功能键、超时/EOF、
屏幕局部刷新、越界和尺寸、终端类型不支持、重复进入/退出、故障恢复、权限、竞争、
资源基线。不能模拟的异常或动态尺寸/信号标注未运行。W3 另验证文件保存、短写、满盘、
sync/重启与数据保真；不承诺任意掉电原子性。旧报告不改绑，新组合不借用旧全量资格。

ncurses 和 terminfo 的许可、源码/补丁及静态分发要求按实际锁定版本审查，材料检查不
等于逐成员法律审计。测试、发行与 Qt 接入分别交付，不将设计或编译结果标为验收通过。
