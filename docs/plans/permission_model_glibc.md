# XOS 权限、身份与文件元数据设计

2026-11-13。状态：**设计裁决与实施路线；尚未实现或验收**。本设计适用于 #123 和 glibc 迁移，不改变现有 syscall 数字、file ABI、发行 SDK 或 xos_plan 宪法。现有实现与目标有差异时，以实现和实测为现状，不能用本文声称能力已存在。契约和 ABI 具体编码须在实施前单独登记。

## 一、原则与参考

XOS 保持微内核、用户态服务和最小授权：内核认证主体与通道、管理隔离和资源生命周期；文件服务解析路径、管理文件对象和存储策略。ELF 解析、libc、包安装及用户界面不因兼容性进入内核。遵守 [xos_plan](../xos_plan.md) C16、C20、C22、C25、C31 和 [ABI 登记](../contracts/abi_registry.md)。glibc 是使用 XOS 接口的运行库，不是权限权威，也不凭符号存在宣称 Linux ABI 或 POSIX 完备；其迁移与默认切换仍服从 [勘查与验收门](glibc_port_scout.md)。

成熟设计的参考是 Capsicum 的句柄权利收窄与显式委派、seL4 的不可伪造能力、Unix 的主体/对象访问控制，以及 Linux VFAT 的挂载身份和权限掩码。XOS 不照搬它们的 syscall、全局 root 或实现；[Linux VFAT](https://docs.kernel.org/5.18/filesystems/vfat.html) 的 uid/gid/mask 也只是无所有者磁盘格式的一种投影。用户界面可以帮助用户授权，但名称、路径、包签名、uid 或进程自称均不是授权凭据。

## 二、长期模型：权限上界与兼容策略相交

一次操作允许，当且仅当：内核认证的会话/进程拥有对此对象及操作的有效、未撤销 authority；解析过程位于已授权命名空间和根之内；文件系统及挂载的只读等约束允许；启用的身份/DAC 策略允许；资源预算和对象状态允许。任一项拒绝即失败。兼容 uid 0、mode 0777、安装应用或 glibc 调用均不扩大 authority，也不能绕过只读介质。将来管理权限必须是单独授权、限定对象和用途的能力，而不是 uid 0 隐含万能。

概念上的权限区分：目录遍历/枚举，读取，数据写入，创建/删除/重命名子项，读取元数据，修改 mode/时间，修改所有者，执行/启动，以及授权和委派。它们是设计分类，不代表现有内核位或现已细粒度实现。父目录的创建、删除和重命名授权独立于文件数据写；exec/loader 授权独立于读取、安装或文件的 x 位。修改元数据权不可由数据写权或可读描述符推断；当前只有粗粒度文件服务授权时，应保守拒绝无法可靠区分的操作，直至代理和协议有真实可信的授权来源。

拥有者、组、补充组和进程主体为未来真实 POSIX 兼容所需的认证属性；仅由受信系统组件设置，继承/切换须有明确授权、原子发布和失败行为。先定义单用户 profile 与确定的非特权兼容身份，uid/gid 0 不自动授予任何能力；身份数值及 NSS、set*id 和映射方案在专门契约与应用兼容测试后冻结，不在本文件伪造实现。原生文件系统可持久保存并执行 uid/gid、mode、umask；ACL、命名空间、多用户登录及 setuid/setgid 各自另行设计。特权提升位及文件能力默认不得生效；无实现时显式失败。

## 三、句柄、委派与生命周期

文件服务只信任内核认证的来源和服务自身维护的句柄表，不相信请求体内自报 uid、路径或权限。打开/授权时绑定稳定对象身份、调用主体、权限子集、世代及会话；转交和 fork/spawn 只能保持或缩减由父项显式允许的权利，不能从路径或 POSIX 位恢复被删减的权利。exec、CLOEXEC、会话断开、服务重启、进程退出与句柄复用按现有专项契约验证，失效句柄不能因编号重用而复活。

修改 mode 或撤销 capability 对已打开句柄的影响必须分开：默认 POSIX profile 中打开时获得的文件访问权不因后续 chmod 自动撤销；显式 capability 撤销的传播、在途操作的完成边界和错误由实现前的撤销契约冻结，不能仅靠重新检查 pathname。目录内 rename/unlink 不得将已打开对象重绑定到后来同名对象。无法对已 unlink 或匿名对象安全修改元数据时返回 ENOTSUP，不对替代对象执行；是否可利用内部稳定 backing 名称须以身份及崩溃恢复证明为前提。

## 四、#123 裁决：FAT 的诚实子集

FAT 是互操作存储，不是 POSIX 权限数据库。P0 不做影子所有权或 sidecar；支持的属性及其限制随挂载/backend profile 显式公布。挂载身份和默认 mode 是受信配置投影，不表示磁盘记载了所有权；引入配置前的固定值必须文档化且不形成特权。FAT 的 AM_RDO 只表示后端可表达的只读属性，不是按用户隔离的 ACL；目录 RDO 是否有语义必须以 FatFs 和实际磁盘行为验证，不能先承诺目录 0555。

- **stat/fstat**：从同一稳定对象取回真实类型、大小、可得的 mtime 与 RDO，再按挂载 profile 合成 uid/gid 和 mode。不得把合成 uid 解释为对象所有者的安全证明；nlink、atime、ctime 的近似值及不可区分性明确记录。只读介质和授权不足不能只改变 stat 而漏掉实际 I/O 检查。
- **chmod/fchmod**：仅当请求与挂载投影可往返一致地表达时修改文件 RDO；检查特殊位及不可表达的读、执行、组/其他位，不能静默丢弃并报成功。不可表达返回 ENOTSUP；无 metadata authority 返回 EACCES/EPERM（以冻结契约细化），只读挂载返回 EROFS。RDO 与既有写句柄/待处理写的关系先冻结并实测；禁止绕过后端只读。目录和文件分别测试，不能假设相同。
- **chown/fchown/lchown**：FAT 后端不存储所有者或组；对要求改变的值返回 ENOTSUP，不伪造成功。POSIX 特殊的 `(uid_t)-1`/`(gid_t)-1` 无变更请求、路径/fd 校验和权限优先级应在 libc 契约确定并测试；不把 FAT 的限制推广成系统永久禁令。
- **时间**：按具体 FAT 字段和范围实现 mtime，报告量化规则，禁止溢出或使用错误时区静默改变日期。缺少可用墙钟时 NOW 明确失败；指定时间及 OMIT 的不同组合逐项定义。无法表达 atime 的显式更新返回 ENOTSUP；两个 OMIT 的无变更路径仍须执行规定的对象/参数检查。不得以成功忽略 atime 冒充语义；旧应用需兼容时可以选择仅请求 mtime。ctime 是变更时间而非 mtime，缺乏持久数据时只可标明投影，不可声称真实记录。
- **access**：是检查时刻的咨询结果，不是后续 open 的授权凭据；按 profile 的真实/有效身份规则、路径遍历、authority、后端 RDO 和只读挂载综合判断。R_OK、W_OK、X_OK 不得无条件成功。不同 identity 或 capability 的交叉测试覆盖 TOCTOU；实际操作必须重新验证。

P0 可针对不存在的对象/缺失 fd 先报告真实错误，然后处理不支持的功能；准确的错误优先级、symlink/no-follow、AT_FDCWD、无效纳秒、UTIME_NOW/OMIT 和时钟故障在接口契约冻结。更新多个字段时，先验证全部输入与权限；若不能保证失败时无部分变更，只提供单字段操作或显式报告部分提交，绝不宣传原子性。unlink/rename/重启/断电、只读介质和 FatFs 失败均须测量；不要以单线程服务推断持久化事务。

## 五、分阶段与验收

1. **M0 契约**：盘点当前文件 ABI、会话认证、权限位、路径与 FD 生命周期、FatFs 配置及两套 SDK；定义现状/目标差异、版本协商、错误和回滚。占号前在 ABI 登记，避免假定版本只能整体升级；旧客户端和已发布 SDK 必须有兼容矩阵。
2. **M1 FAT 元数据**：按 M0 实现受控 RDO 与 mtime、元数据读取和查询；为 metadata 授权建立可验证的来源。对不能表达的行为真实失败；兼顾已打开/重命名/unlink 对象、失效句柄、服务中断、只读挂载及恢复。不得先把账本标 fixed。
3. **M2 POSIX 身份与原生存储设计**：明确主体凭据、默认身份、用户/组管理、mode/umask 持久性、授权衰减和执行策略；设计 capability 与 DAC 的交集。决定是否有独立原生文件系统或可恢复的元数据存储时，先定义原子提交、标识绑定、备份/迁移、容量及损坏恢复；sidecar 不能仅按 pathname 匹配。
4. **M3 glibc 集成**：独立 sysdeps/SDK，比较 glibc 对 stat、access、chmod/chown、时间、身份、FD、目录与进程凭据的真实依赖；新旧 SDK、静态和将来动态 ABI 分别验证。不得以 glibc 链接成功宣称所有权、权限、NSS 或 Linux 兼容完成。

验收包含：不同 authority 与身份交叉（含 uid 0 无额外权）；路径越界、目录权限和句柄委派；chmod 可表达与不可表达回读；RDO 对真实 open/write/truncate、access 和只读卷一致；mtime 精度/边界/NOW/OMIT/无墙钟；atime 和 chown 不支持的真实错误；rename/unlink/重用和 fork/exec；服务故障、崩溃恢复与资源回收；旧 SDK 与两个 libc profile；tar/cp 等在 xsh 和 dash 的真实行为。冻结源码、系统、SDK、profile、输入和输出哈希，保存客体原始日志；宿主单测、编译或旧镜像均不能替代客体验收。未运行项明确记录。

本裁决不授权直接部署、更改线上磁盘或宣称特定存储后端已通过资格。
