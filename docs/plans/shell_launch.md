# 双 Shell 普通命令启动与权限继承计划

2026-10-29。状态：planned，尚未实现或验收。源码勘查基线为FB1/FB2分支
`92acd02`（含主线VirtIO-GPU PR #16）；开工前重新同步主线及核对PR #17合入状态。
本计划细化既有微内核、可信委派和双Shell验收方向，不修订宪法或分配ABI编号。

## 目标与用户行为

用户在xsh或dash直接输入应用名即可运行，在应用结束后回到原Shell；应用按已有授权
启动编译器、辅助工具或诊断目标，不要求用户理解启动深度、使用`exec-driver`，或用
`(exec ...)`绕行。目标示例：`dash`、`make -B`、`gcc hello.c -o hello`、
`xos-diag /bin/fault.elf`。示例不扩大Make、编译器或Shell既有语法支持范围。

dash的`exec program`保留替换当前Shell的语义。内核与运行库仍可内部使用exec，用户
无需显式输入它；本计划不把两Shell语法统一，也不把dash改成默认Shell或安装为/bin/sh。
xsh现有`exec`是启动内建镜像并等待的历史命令，首版保持兼容、清楚标注，不能静默改成
Unix进程替换；将来若调整名称或语义，另列弃用窗口和迁移方案。

## 已有行为与根因

| 位置 | 实际行为 | 本组要解决的问题 |
|---|---|---|
| `supervisor.cpp` 普通命令分支 | 普通命令授予一级启动能力；按名称识别dash/make后授予三级 | 保留已有裸命令能力，去掉工具名与授权策略绑定 |
| 同文件显式文件启动入口 | `exec-file`不授予创建权，`exec-driver`授予一级 | 作为兼容/受限入口保留，日常工具不再依赖它 |
| `newlib_syscalls.cpp` 普通posix_spawn | 子进程默认不获得创建后代能力 | 普通spawn与fork/exec的授权结果不一致 |
| `jobs_xos.c` | GCC/Make按名称选不同委派接口；普通程序走posix_spawn | 通用启动语义不能靠不断增加名称特例维持 |
| 内核进程机制 | fork复制spawn_depth，exec默认保留；显式委派必须递减，最大3 | 后代创建能力与递归深度混合，工具调用链容易耗尽 |
| FB1/FB2独立诊断程序 | dash需子Shell中exec；目标由诊断程序创建 | 用普通调用验证新机制，保持真实父进程单一wait消费者 |

此前“xsh普通启动不给权限”的概括不准确；应以上述源码行为为依据。

## 拟定契约

以下是实施目标，SL0冻结后进入专项契约，不代表现有接口已支持。

1. 将普通应用创建后代的能力与历史spawn_depth分开。能力由内核认证的进程身份承载，
   明确记录可使用与可继承范围。普通启动默认继承父进程允许继承的部分；子进程不能
   增加权限，父进程可主动削减。没有创建能力的进程仍不能spawn/fork，也不能借exec获得。
2. 同一父进程、同一授权配置下，普通spawn与fork后exec的创建/继承权保持一致。
   exec不恢复被削减的权利；更名、PATH变化、ELF标记和自报环境变量均不授予权利。
   ELF/CRT标记只用于格式与FD恢复兼容准入。
3. 资源不足真实失败。首版复用已有全局进程、完成记录、页分配和端点预算，不通过
   提高全局上限掩盖问题。授权不得因创建孩子而按代耗尽；现有fork快照深度等实现限制
   单独登记，不能因此宣称任意嵌套fork已支持。exec也不能重置资源账目。
4. 若实施需要新增进程树预算，后代必须共享同一预算归属和计数，不能复制余额；
   父进程退出后归属保持到最后引用释放。首版无实际需要不建设新配额框架。
5. 默认交互会话及其普通工具使用可继承的创建能力。维护模式、受限进程和服务启动
   清单单独明确选择权限；不把普通用户的创建权等同于设备、内存、维护或任意IPC权限。
6. 启动失败不得留下已运行的半成品，回收进程/端点/会话/完成槽。正常退出、fault、
   kill和取消分别保留原语义；等待仍按真实父进程消费，诊断失败不改变目标结果。

内核变更理由：当前授权和委派校验在内核，用户态无法使普通spawn继承能力而又消除
fork绕行差异。内核只提供通用继承、削减和生命周期机制；命令搜索、ELF解析、脚本、
工具识别与诊断策略继续放在用户态。按宪法C20/C22审查，不引入完整capability框架。

## 用户态统一与兼容

建立共同的启动选项与错误约定，由两个Shell适配现有用户态装载器。搜索路径取调用者
有效PATH；明确路径直接解析；工作目录、环境快照、stdio、共享打开描述、CLOEXEC及
失败回滚沿用实际契约。xsh无对应Shell功能的项目标为不适用，不伪造POSIX语法。

普通posix_spawn遵守新继承契约，接口外观与POSIX兼容；XOS专有削权选项使用独立版本化
扩展，不占用或冒用标准flag。SDK默认spawn与显式诊断启动采用同一规则。新字段不得
静默扩展旧`spawn_options`二进制布局；先核对调用模式，选择独立接口或带版本/大小请求。

历史sys_process_grant/delegate、深度接口和旧SDK行为不静默重解释。SL0确定双轨兼容表：
旧请求保留原限制，新SDK使用新契约；未知版本明确拒绝。分阶段移除用户态GCC/Make/dash
名称分支，再逐个淘汰深度专用包装器。过渡期保留旧接口不等于继续推荐旧入口。

旧CRT可运行范围维持已有准入：不因本计划允许丢失文件FD后继续运行；不能恢复v3
描述符的目标在需要exec或文件FD继承时继续明确失败。执行权限和安装状态仍分别检查。

## 分阶段交付

| 阶段 | 交付内容 | 退出条件 |
|---|---|---|
| SL0：冻结契约 | 核对fork/spawn/exec、服务与维护启动，记录权限与资源表；建立专项契约、兼容表及ABI登记 | 授权来源、削减、继承、失败及旧接口行为可逐项判断；任何新接口先登记，不抢预留号 |
| SL1：通用机制与SDK | 内核最小继承机制、版本化SDK接口；明确资源归属与清理 | 客体探针证明普通spawn与fork/exec一致；无权/削权不可绕过；旧路径按兼容表运行 |
| SL2：两个Shell接入 | 普通启动使用共同契约；去除名称授权特例，保留历史入口；更新帮助和使用说明 | 普通命令、改名程序、脚本和嵌套工具链在适用Shell可运行；无需显式exec/driver |
| SL3：诊断与工具迁移 | xos-diag普通调用；Make/编译驱动及既有工具适配；检查环境、目录和FD | 诊断完成回Shell且退出码正确；真实最小C工程经Make构建运行；旧SDK边界验证 |
| SL4：组合验收与交付 | 最新主线独立构建；双Shell矩阵、权限/资源回归、文档与PR | 回执绑定最终源码/SDK/镜像/工具；pass/partial/fail/not_run逐项记录，无未解释失败 |

SL1与SL2可在隔离构建上定向验证；最终验收不得使用早期混杂构建。每阶段更新state、
SDK/ABI及实现文档。接口冻结与实现先后依照既有登记流程，不为例行实现另设用户审批。

## 双Shell验收矩阵

按宪法C27尽可能经xsh与dash各跑一遍；一方通过不能替代另一方。宿主对照只核指定输入，
客体功能必须在XOS执行。每项记录两列结果、命令、实际授权、退出状态和证据路径。

| 场景 | 关键判据 |
|---|---|
| 普通ELF、PATH命中、显式路径、缺失/不可执行/损坏文件 | 无需exec；正常回到Shell；错误分类准确，无孤儿或完成记录泄漏 |
| 应用创建帮助程序、至少四层spawn链 | 后代不按代耗尽创建权；fork深度与同时存活数另记，资源不足可预测失败 |
| 不同路径/名称的同一程序 | 同一权限上下文得到相同授权结果；命名gcc/make/dash不产生额外权利 |
| 无创建能力、只允许创建不可继承孩子、主动削权 | 原始syscall、SDK、fork、exec及名称变化均不能增权；旧接口也不能恢复新权利 |
| 环境、相对路径、工作目录和参数 | 按各Shell支持面继承；空参数、空格、超限及错误回滚真实验证 |
| 文件重定向、管道、共享offset、CLOEXEC | 覆盖适用入口，不靠路径重开；旧CRT显式拒绝；xsh未提供的语法登记不适用 |
| dash脚本、子shell、显式exec | 普通调用可继续；exec替换PID/会话符合契约；xsh历史exec单列兼容 |
| xos-diag正常/故障/缺失/取消 | 裸调用后回Shell；目标摘要和wait结果准确；报告只针对真实目标，保存失败不吞原结果 |
| Make -B、编译驱动、汇编器、链接器 | 真实小工程构建并执行，不以--version或伪造子进程探针替代；两Shell各跑 |
| 进程/完成槽/页/端点资源不足、装载中失败、父子退出 | 真失败，清理后可再启动；无新增不必要全量压力；服务与维护准入不被扩大 |
| 旧SDK及新旧接口混用 | 逐项符合SL0兼容表；旧深度规则、新权限削减和未知版本不发生静默混淆 |

内核和SDK探针补充两个Shell未直接暴露的权限路径；不能用它们代替Shell客体验收。
最终重跑受影响进程/文件/取消、FB1/FB2与工具链定向回归，文档与ABI一致性检查。

## 非目标与后续

本组不实现完整Unix/POSIX、后台作业控制、信号/TTY、多线程fork、COW、动态链接、
第二ISA端口或新的安全沙箱。普通调用能运行不代表进程数量/嵌套深度无限，也不把SDK
兼容性或既有诊断配额缺口算作已经解决。Shell体验优化不引入工具专属内核ABI。
