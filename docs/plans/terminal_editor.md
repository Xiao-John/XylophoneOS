# 输入与编辑体验第二档：小型终端编辑器选型

2026-10-27。状态：P，先推进 ncursesw 公共底座，nano 为首个编辑器评估对象；尚未移植或正式定型。
第一档见[现有终端和行编辑器](input_edit_foundation.md)。
UTF-8 输入、文件内容和路径的优先顺序与边界见[多语言设计](multilingual.md)；
候选选择须优先核 UTF-8 输入和内容保真；[ncursesw 设计](ncursesw.md)定义公共底座。

## 目标与边界

在 XOS 的串口终端上运行一个独立的小型全屏文本编辑器，方便朋友编辑实际源文件；
`edit` 保留为可救援的行式入口。候选优先成熟、小、许可和依赖清晰的工具，不因原创性
而自研完整编辑器，也不以 Vim/Emacs 级功能为首版目标。
当前不要求 Qt、图形显示、动态链接、网络、完整 POSIX 或完整 Unicode 编辑。

当前串口字节通道不等于已验 TTY：没有受验收的 termios、前后台会话/作业控制或异步
POSIX 信号；后台进程可与 supervisor 竞争输入。第一档的 Xshell 行编辑只解决 Xshell
提示符，不能自动证明独立程序可获得逐键输入或可恢复终端状态。

## 候选筛选与决策

对每个候选固定版本、源码来源/哈希、许可及修改，
确认是否要求 curses/termcap、termios、信号、窗口尺寸、locale、文件替换、动态链接
和构建工具；按实际代码路径列出必需功能与可配置关闭的功能。

按以下顺序比较，缺一项不能只凭体积或编译成功选定：

1. **数据安全**：保留已有字节和末尾换行；空间不足、写入/同步失败或异常退出时不
   假报保存成功；能解释覆盖原文件与临时文件的真实边界。
2. **底座适配**：能以当前 SDK 和最小明确补充运行，拒绝用假 termios、假信号或假尺寸
   掩盖关键依赖；不会在退出后让串口不可用。
3. **可用性**：移动、插入删除、保存、退出和未保存提醒易于发现；明确文件大小上限、
   支持的编码及按键，适合串口和现有受限 UTF-8 路径。
4. **维护与许可**：来源、静态分发义务、补丁量、依赖与资源占用可接受；许可证材料与
   源码修改按项目纪律记录，不以材料检查通过冒充完整许可审计。

交叉编译只是候选筛选，真实客体的交互、文件和故障探针通过后才能选定。所有候选均不
合适时，记录具体缺口，保留第一档，不把实验性原型直接当交付。若缺口需要独立底座，
向对应负责人提交最小消费者探针和契约；不按程序名添加内核特权或专用 syscall。

### 2026-10-27 原初选：kg（2026-10-28 调整）

用户提出优先积累可复用的系统接口后，主线改为先实现 ncursesw、再优先评估 nano。
以下保留原勘查及其风险，kg 是不依赖 curses 的备选，不是当前首选。

当时首选 [kg](https://github.com/troglobit/kg)，勘查提交
`449fac2d54cd3a423d5d9c3d251ce716d00469aa`，BSD-2-Clause。它是 C 编写的 kilo 衍生
编辑器，上游声明使用 VT100、无需 curses、支持 UTF-8；提供 Emacs 式快捷键。首版只
取 T1 的单文件编辑范围，其他上游功能逐项核依赖，不自动承诺可用。该提交仅为可追溯
勘查输入，尚非发行 source lock；开工时重新核版本、完整许可、源码摘要和补丁。

| 候选 | 优点 | 当前取舍 |
|---|---|---|
| kg | C、BSD-2-Clause、不依赖 curses，已有 UTF-8 码点编辑 | 备选；终端、中文列宽和文件安全仍需适配与客体验证 |
| [ne](https://github.com/vigna/ne) | 上游声明 UTF-8 多列字符和二进制编辑，GPL-3.0 | 备选；POSIX 依赖及无 curses 构建选项需要专项核实，不预称更易移植 |
| [GNU nano](https://www.nano-editor.org/dist/latest/nano.html) | 使用习惯友好、提供 UTF-8 配置 | 优先评估；其 UTF-8 配置要求宽字符 curses，依赖公共 ncursesw 先行 |
| [原版 kilo](https://github.com/antirez/kilo) | BSD-2-Clause、小、VT 序列 | 不作为首选：上游源码按字节处理且保存先截断；修补 UTF-8 和数据安全工作较大 |

**源码勘查明确的 kg 缺口**：`tty.c` 调用 `tcgetattr/tcsetattr`、`ioctl`，需要原始
模式和尺寸探测，`main.c` 注册 SIGWINCH，暂停依赖 SIGTSTP，`shell.c` 依赖 poll 等。
上游“无需 curses”不等于无需真实 OS 终端语义。首轮使用独立 XOS 用户态适配，按实际
前台字节通道验证输入和退出恢复；不能伪造成功的 termios。尺寸可明确配置，暂停、
外壳命令及其他需要未支持信号/作业控制的功能要禁用或明确失败。

`buffer.c` 的列宽计算将每个 UTF-8 非续字节计一列，中文全角和组合字符因而不正确；
必须修改并覆盖中文字输入、左右移动、删除、滚动与刷新，支持范围按实际宽度表声明。
`fileio.c` 依赖临时文件、fsync、元数据和 rename，并以 mtime/大小判断外部变化；不能
假定它在当前 XOS 上具有上游的保存或冲突语义。需先核文件服务的 replace、并发和
失败/未知结果，再设计 XOS 保存适配；还要验证 CRLF、无末尾 LF 和非法字节往返。
这两类问题是首版门槛，不能通过关闭 UTF-8 或缩小验收绕开。

用户要求所有改动提交后才验收。本轮只读上游和项目源码，不运行客体验收；上述选型
是有依据的探索优先级，最终采用以提交后冻结输入、真实客体探针与故障测试为准。

## T0：终端与文件探针

在改动第三方源码前，确定并记录真实行为：

- 输入：独立前台程序能否逐字节读取、空闲与 EOF 如何区分、Escape 序列是否完整；
  supervisor 等待期间输入所有权以及后台竞争的实际情况。
- 显示：串口宿主支持的最小 VT 控制集、颜色开关、行列数取得/人工配置、窗口变化和
  不支持控制序列时的回退。尺寸缺失时不得声称自动检测；初版可用显式配置并设合理上限。
- 退出：正常退出、读写失败和被取消后，哪些状态由宿主终端、XOS 或程序管理；若没有
  可靠方式恢复，记为阻塞该候选，而不是静默跳过。
- 文件：大于缓冲的输入、短读短写、旧文件读取、空文件、改写、空间不足、sync 和重启。
  比较当前 replace 与普通文件写入的可用能力及局限；不将正常 sync 推断为断电安全。

若候选确实需要终端模式、就绪等待、信号或控制终端，按[POSIX路线](posix.md)拆分最小
依赖：PX1/PX2 为真实信号和终端作业，PX3 为就绪等待。没有这些语义就选择不依赖它们的
候选或暂停相应功能；无需等待所有 PX 阶段完成才探索，但不得自行宣布它们已实现。

## T1：首版交付范围

- 通过版本化 SDK 构建并作为独立用户态程序安装；名称、固定版本、依赖和许可证由选型
  后冻结。支持打开/新建一个文件、屏幕滚动、光标移动、插入删除、保存、退出和脏缓冲
  确认；帮助显示实际快捷键及终端要求。
- 文件大小和内存预算在客体探针后冻结，超限需在修改和覆盖之前明确拒绝。内容按字节
  保真；初版 UTF-8 的输入、显示与光标操作分别声明实测范围，非法字节至少不能被静默
  改写。路径继续按当前文件服务的受限 UTF-8 能力，未验范围不得外推。
- 保存策略必须明确成功、失败与结果未知的区别；写入和同步错误保留未保存缓冲，不
  自动重试未知结果。检查外部修改检测是否真能在提交点生效；不以先 stat 再写宣称无
  竞态。异常退出、磁盘已满及掉电保护按实际文件服务能力分别报告。
- 不默认提供剪贴板、撤销、搜索、语法高亮、多文件、鼠标、输入法或历史持久化；候选
  具有这些功能时另列验证与限制，不妨碍后续按兴趣扩展。

## T2：客体验收

在隔离系统镜像和专用测试盘，以真实串口按键完成打开、移动、编辑、滚动、保存、退出、
重新打开和 sync/重启后逐字节比较。覆盖空文件、无末尾 LF、CRLF、UTF-8、非法字节、
长行、大文件边界、屏幕尺寸和支持的宿主终端；记录实际资源和交互结果。

故障路径覆盖文件不存在、不可写或空间不足、短读写、终端输入异常、取消/异常退出、
保存结果未知及退出后 Xshell 恢复。只能测到的错误逐项报告；无法注入的故障保持未运行。
同时验证现有 `edit`、Xshell、Python 和 dash 既有受影响路径，确保未改变默认 Shell 或
误报信号支持。冻结源码/补丁、工具链、SDK、系统镜像、候选程序与测试盘报告；不把
旧资格或宿主运行当成本次客体通过。

## 暂缓

Qt Widgets 编辑器仍沿 [Qt 计划](qt.md) 的 E15–E17 交付；它与本档共享文件安全目标，
不依赖本档选定的终端编辑器。GUI 键盘布局、输入法、字体、剪贴板、多窗口及完整终端
作业控制另行设计和验收。
