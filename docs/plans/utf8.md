# UTF-8 文本接口计划：先做文本通道，原生输入另立

2026-10-25，0033。用户要求为 shell（dash/xsh）落地 UTF-8 文本接口，并明确
**输出/读取解码**与**原生多语言输入**要分开考虑。本文只定义 U0/U1 的文本通道；
U2 路径、U4 locale、N1 原生输入法均不在本批实现，也不据此标为已完成。

## 结论与边界

把“UTF-8 文本接口”拆成两层：

| 层 | 内容 | 本批 | 归属 |
|---|---|---|---|
| 文本通道 | 字节契约、UTF-8 校验/解码、按码点退格、按显示宽度擦除、回显 | **U0/U1 实现** | shell/SDK |
| 路径编码 | 文件名、目录项、文件服务的 UTF-8 路径 | U2 未开始 | 文件服务/FatFs |
| 字符语义 | UTF-8 locale、`wcwidth`、字符级 `?`/`[]` | U4 未开始 | libc |
| 原生输入 | 键盘/HID、布局、输入法、组合态、候选窗、字体 | N1 未开始 | 输入/显示/GUI |

关键判断：

- **串口输出已经是字节透明**，`cat`/`printf`/Python 的 UTF-8 不需转码；VGA
  仍是一字节一个字符单元，本批明确不承诺 VGA 显示 UTF-8。
- **读取解码**只发生在交互行编辑：把字节流拼成码点，供退格和宽度擦除使用。
  数据可以来自脚本、粘贴、宿主终端或未来 IME；不需要客体键盘驱动。
- **原生多语言输入不是 shell 问题**。当前客体只有 UART 字节输入，布局与输入法
  在宿主终端完成；客体 IME 需要键盘、显示、候选 UI 和字体，属于后续 GUI 项目。
  只要 IME 最终提交 UTF-8 字节，shell 的 U1 就能正确处理。
- dash 上游本身按字节处理：语法表把 `0x80..0xFF` 归为普通词字符，`isalpha`
  已转 `unsigned char`；本批只改它的控制台适配层，不改解析器。
- 本批不改文件服务，因此**不承诺 UTF-8 文件名**；`ls`/`cat 中文名` 仍受 U2 限制。

## 文本契约（U0）

- 交互行、`argv`、`env` 和 stdio 内容统一为 UTF-8 字节串；不做 Unicode 规范化，
  不做大小写折叠，按字节原样传递。
- 交互行必须是合法 UTF-8：拒绝 overlong、代理区、`> U+10FFFF`、截断序列；
  非法输入整行拒绝，不执行截断前缀。
- 行编辑缓冲仍为 2048 字节；按字节限长，不按字符数。
- 退格删除一个完整码点；尾部不完整序列整段删除；擦除列数按显示宽度：
  组合字符 0 列、CJK/全角 2 列、其余 1 列。
- 分词规则不变：Xsh 仍只按 ASCII 空格切分；引号/转义是独立问题。UTF-8 字节
  除 `0x7F` 外均作为普通词字节。

## 实现（U0/U1）

1. 新增 `src/user/include/xos/text.hpp`：增量解码、整行校验、显示宽度、
   `erase_last()`（返回新的字节长度与擦除列数）。
2. `src/user/programs/supervisor.cpp`：接受高位字节；退格走 `erase_last`；
   Enter 前校验整行；回显仍按原始字节写出。
3. `src/ports/dash/console_xos.cpp`：同一套解码/退格/校验；非法行丢弃并提示，
   不把错误字节交给 dash 解析器。
4. 不修改 dash 上游词法、进程 ABI、文件服务或内核控制台；内核启动控制台
   `xos64>` 仍是 ASCII 行编辑。

## 验收

### 主目标：UNICODE_example1.cpp

新增 `tests/fixtures/utf8/UNICODE_example1.cpp`，在 XOS 客体里用原生 G++ 编译并运行，
stdout 必须逐字节等于：

```text
Wir müssen wissen, Wir werden wissen.
我们必须知道，我们终将知道。
```

即德语一行、中文一行，UTF-8 编码，末尾换行。该 gate 证明 UTF-8 源码字面量、
目标编译器执行字符集、程序输出和串口链路一致；不证明输入法或文件路径。

### 文本通道 gate

`tests/utf8_text_smoke.py` 通过串口注入字节（模拟粘贴/宿主 IME）：

- 回显保留完整 UTF-8 字节；
- 退格删除整个码点（`ab` + `é` + 退格 + `c` 最终执行 `abc`，不是 `abéc`）；
- 非法 UTF-8 整行拒绝并回到提示符；
- UTF-8 参数原样传给客体程序（小型 argv 探针）；
- 超长行仍整行拒绝。

### dash gate

重建 dash 后，在 dash 提示符注入 UTF-8 行并验证回显与退格；不重复 A/B0/B1 的
全部回归。若 dash 重建或客体运行受阻，明确记为未运行，不拿 Xsh 结果代替。

## 明确不做

- 不承诺 VGA/图形界面显示 UTF-8；串口是当前文本界面。
- 不承诺 UTF-8 文件名、目录列举、`stat`/`rename`（U2）。
- 不承诺字符级 glob、`${#var}` 按字符计数、locale 排序（U4）。
- 不承诺客体键盘、输入法、组合态、候选窗（N1）。
- 不放宽引用/空格分词；带空格的 UTF-8 路径仍需引用支持。

## 风险

- 不完整序列跨 `read()` 边界：解码器必须保留残片，不能逐字节校验后丢弃。
- 宽字符擦除：CJK 发一次 `\b \b` 会留半个字符；宽度表需覆盖常用全角区。
- 非法字节：整行拒绝优先于“尽力解码”，避免执行被截断的命令。
- 行缓冲上限按字节：UTF-8 长文本可用字符数会少于 2048。
- dash 的 C locale 仍按字节匹配 `?`；本批不声称字符级语义。
