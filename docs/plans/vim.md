# Vim 终端版移植路线

2026-11-14。状态：规划；尚未锁定上游版本、构建配置或开展 Vim 客体验证。目标是
在 XOS 上移植上游 Vim 的完整终端能力，以实际选定版本的特性清单为验收分母；`vi`
作为 Vim 的兼容入口考察其真实行为，不另做功能缩减的同名替代品。nano 不作为前置。
按项目纪律，先做小而真实的探查与消费者，再为实际缺口提供可复用接口；依兴趣推进，
不把所有阶段安排成必须一次完成的机械流水线。[上游源码](https://github.com/vim/vim)、
[特性说明](https://github.com/vim/vim/blob/master/runtime/doc/various.txt)及
[许可证](https://github.com/vim/vim/blob/master/LICENSE) 是选型起点，不是已冻结输入。

## 完整能力的边界

以固定版本上游的终端版构建选项、`:version` 特性、随附 runtime 和测试为对照，建立
逐项清单：编辑与多缓冲/窗口、搜索替换、撤销/持久状态、脚本和插件运行、帮助与
语法文件、Unicode、终端/信号、进程及外部命令、系统集成。分别注明开启、平台不适用、
依赖外部软件、未实现与已验收；不得把 tiny/small 构建、禁用核心功能的配置或探针
通过称为完整 Vim。GUI、剪贴板、鼠标、外部解释器、网络/远程功能等逐项记录上游
构建选项与平台依赖，若选定完整配置包含，必须完成或明确尚未完成；不把单个交付
阶段的暂缓当作最终目标的豁免。具体分母和是否提供独立 GUI 入口在 V0 根据上游源码
和用户需求冻结，未核实的功能及依赖不预判为必须内核实现。

## 当前基础与真实缺口

ncursesw 6.5 已有单线程、固定 80×24、xterm/串口的 guest_verified_subset，见
[验收记录](../work_log/0187_w1_final_acceptance.md)；这不是完整 curses、完整 POSIX
终端或 Vim 已能运行。终端当前只支持受限原始模式和单描述符读取 select；动态尺寸、
信号、作业控制与多线程 profile 未获完整资格，详见[终端契约](../contracts/terminal_control.md)。
UTF-8 数据和路径须遵守[多语言设计](multilingual.md)；文件系统的 rename、sync、
元数据、锁与错误传播按当前实现逐项探测，不假设 POSIX 语义或断电原子性。XOS 最近
的 VM、IPC、文件和进程工作可能改变缺口，V0 必须重新对照当前 main 和真实代码。

## 阶段与门槛

**V0：固定分母与探查。** 选定上游稳定版本及精确提交/归档和哈希，登记许可证、
runtime 和第三方组件；记录构建系统、宿主工具、交叉配置、目标路径与 `:version` 的
完整候选特性。依真实源码调用和 configure 结果列出依赖矩阵：接口、消费者、当前
实现/错误、可复用归属、缺口、验证与责任；配置探针不得冒充客体验证。检查现有内核、
libc、SDK、文件和终端接口，先把不确定项标为待核，建立分阶段资源预算和回退方案。
试验 Vim 与 ncursesw 的真实链接路径，不能假设 Vim 所有终端功能都必然通过 curses。

**V1：可运行的垂直切片。** 构建上游终端 Vim 的显式实验配置，固定 SDK、runtime 和
terminfo；QEMU 中验证进入/退出、模式恢复、键序列、UTF-8、读写一个文件及重启读回。
保留真实版本/特性标识和未启用清单；这只是探索，不称完整交付。文件失败、空间不足、
短写和同步失败不得假报成功；现有行编辑器仍可作为救援。

**V2：系统底座。** 按 V0/V1 的实际缺口推进可复用接口：终端尺寸查询与变化、信号及
取消、前后台与进程组、shell/子进程和重定向、通用等待、文件替换与元数据/锁、locale
和字符宽度等。每项先定义权限、生命周期、错误、竞争和资源边界，再登记 ABI、实现和
独立客体验证；业务与 Vim 名称不进入内核。以 Vim 调用链和最小独立消费者共同验收。
避免在缺能力时伪造成功，缺项按 unsupported 或明确失败处理。

**V3：完整终端特性。** 按冻结的上游特性矩阵逐项打开和验证：Vim 脚本、runtime、
插件、帮助、语法、多个缓冲/窗口、持久撤销/交换文件、终端相关模式与外部程序等，
以实际版本配置为准。每个外部解释器或平台组件分别审计来源、依赖、安全及测试；
不因某项耗时而悄悄从完整目标删除。核量内存、文件和进程配额及失败恢复。

**V4：完整验收与交付。** 锁定用户态程序、runtime、源码及补丁、依赖许可、工具链、
SDK、系统镜像和测试盘哈希；源码提交后从真实输入重建。在 QEMU 与声明的宿主终端
执行上游适用测试、独立交互/故障测试和系统回归，逐项报告通过、失败、未运行及
原因。覆盖 Unicode/组合符/宽度、长行与大文件、二进制与原始字节、异常退出及恢复、
写入/满盘/sync/重启、外部修改和并发、信号与尺寸变化、子进程与资源回收；按实际
文件服务承诺划分结果未知与断电边界。只有矩阵逐项达到冻结目标才称完整终端 Vim，
否则明确已交付的阶段与缺项。GUI 及平台特性资格不得从终端版通过推断。

## 立即下一步

1. 检查当前 main 的 POSIX、文件、VM、终端/SDK 与 ncurses 证据，获取并锁定合适的
   上游 Vim 稳定源码，审查许可证和 runtime；先形成 V0 特性/依赖矩阵。
2. 在隔离构建目录做真实交叉配置和链接探查，记录首次缺失符号、配置结果及源码路径；

3. 按最小可复用底座与数据安全优先安排 V1；如需碰其他正在进行的工作，先核状态和
   所有权，避免覆盖或干扰；每个交付按实际兴趣和依赖推进。
