## 跨计划剩余事项的明确交代

1. **本轮可以完成的确定性修复已纳入源码与定向回归。** 表中“本轮处理”不是把整个里程碑勾选完成；例如 SQLite 锁、Notes 保存、wait pin 与 O_TRUNC 清理均有各自清晰触发路径，验证等级不同。完整清单与未运行项见总报告，避免以修复数量冒充功能完成度。
2. **缺环境的工作是验收欠账。** 当前镜像、Qt GUI、音频、实际 BIOS 启动、完整 SDK 重建及新发行不能在没有固定工具链/客体环境时给出 PASS。下一次应保留本轮源码，恢复固定输入，运行相应既有门槛，失败记录照实留存。
3. **仍需实质开发的工作按依赖推进。** VM/COW 生命周期、IPC 支持资格、设备 grant/迁移、用户态网络/TLS、P3 包仓库、FB3/FB4、全屏编辑器和 WebKit/LocalPilot 是独立工程；不能只清除 TODO 注释或写空实现交付。实际优先级可沿总报告十点规划执行。
4. **已登记但未闭合的具体问题继续保留。** D4 Pillow 线程崩溃、D13 Studio 首跑间歇超时、D14 SSG consumer/Notes 退出与 stress 23/24、FS-01/02/04/08 的文件身份边界、BT-06 真 CPU 计时等仍需对应真实复现或架构工作。D14 的 globalAtomicSnapshot 仍未实现，scoped 资格不外推。旧单行 P3C 回放入口有历史用途，不为让当前 runner 通过而改写旧证据。
5. **来源与分发不能凭文档抬高状态。** D12 本轮已有统一 archive validator 和 14 项宿主回归，但首次依赖重建时的 producer `member_manifest.json` 及正式门禁仍待接入。两处已复现的 vendored newlib C11/泛型数学头问题未直接改 vendor，需用固定 GCC 16.2.0/实际 seed 验证头优先级，再从上游输入/补丁管线修复并重建 SDK。预编译库和第三方压缩包内部没有因此获得源码审计资格。
6. **历史已完成事项不重新要求开发。** DU4、SL1/SL2、P2 事务、VM2、Widgets/G05、Qt 0.0.2-1103 分发材料等按后续记录承认已有成果。新版来源变化需要新版验证，不构成抹除历史成果或重新实现整条功能线的理由。nano/kg/ne、多个浏览器、多个语言工具链等替代候选也不自动叠加为必须全部完成的需求。
