# Notes range boundary checks — partial P2C evidence

Source base is PR #9 commit `13c45217337954d5d9804fee17b5703a65fd39be`; the new fixture and runner are included in the same commit as this report. The corrected run exercises the actual `QtScene` and real `QPlainTextEdit`/`QTextDocument` in an XOS Qt Widgets process. It does not exercise the pipe or the Notes application. The run passed 13 checks for revision invalidation after an actual edit, protection and revocation rechecks, replacement of a document, deletion of a widget, empty document, final page, invalid offsets and lengths, and UTF-16 surrogate boundaries. Resource counters before and after the process were both `[130235, 3, 1]`. The report contains the QEMU command and image and ELF hashes; temporary disk and QMP paths no longer exist. The receipt records compilation inputs and command.

The initial run had 11 passes and 2 failures, retained with its exact fixture, report, receipt and serial log. That fixture attempted to install a QTextDocument without the QPlainTextDocumentLayout required by QPlainTextEdit, so replacement was refused; the corrected fixture installs that layout before replacement. No production logic was changed.

This is **not qualification of PR #9**: cross-process edit/revocation/protection, provider restart, malformed transport input and consumer cursor loop behavior remain to be tested. The existing P1 regression was rerun with the PR #9 artifacts and passed all 17 scoped checks; its report, IPC frames and logs are retained here. Complete Browser P2C acceptance remains a separate requirement. Browser pagination remains unimplemented and the original large-page failure remains in the P2 diagnostic report. No security qualification is implied.
