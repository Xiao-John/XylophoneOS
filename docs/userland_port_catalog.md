# XOS 用户态工具移植菜单

2026-10-25。本文是一张供项目所有者按兴趣选择的菜单，不是强制排期，也不把
所有候选变成主线前置任务。当前 dash 移植与 0027 Xsh 工作保持原样；本文不占用
它们的源码、测试或构建目录。

## 目的和选择方法

XOS 已有静态 ELF、newlib、文件/目录、stdio、动态堆、受限 `posix_spawn`、
GCC/G++、Binutils 和可选 dash A。移植新工具时优先选择能够：

1. 马上改善编辑、查看、构建或玩耍体验；
2. 复用现有能力，而不是先补一整套 POSIX；
3. 暴露一个以后还能复用的真实缺口；
4. 用较小、可检查的上游源码形成独立客体 gate。

候选分为四档：

- **现在可做**：只需工具本地适配或很小的公共补充。
- **补一个底座后做**：例如正则、终端控制、时间戳或阻塞管道。
- **单独大项目**：CPython、完整编辑器等，分阶段验收。
- **暂缓**：网络、动态链接、线程或完整桌面是其核心语义，当前收益不足。

选择某项只表示开始该项的第一批受限子集。每个工具实际开工时再冻结版本、原包
摘要、构建配置和许可证，不使用“最新版”作为不可复现输入。

## 当前共同边界

- 目标是 XOS 静态 ELF；不声称 Linux 二进制或完整 POSIX 兼容。
- 文件系统当前没有符号链接、Unix 权限位、可靠文件时间戳或任意掉电事务保证。
- 每个任务当前只有一个用户线程；没有动态链接、`fork`、作业控制和完整信号语义。
- 管道是 4 KiB 有界对象，通用阻塞/并发流水线仍属于 dash C 工作。
- `gettimeofday` 未实现；`stat` 的时间字段为零，不能据此正确实现增量构建。
- SDK 有 `regex.h`，但当前目标 `libc.a` 没有 `regcomp/regexec` 实现。
- 控制台可收发字节，但没有已验收的通用 `termios`、窗口尺寸、curses/terminfo。
- 普通工具不获得递归构造权；工具名和文件路径不成为内核授权依据。
- 失败返回真实失败。缺少语义时缩小功能面，不加入永远成功的兼容桩。

## 推荐起步组合

以下三条互不强制串行，项目所有者可以按当天兴趣任选一条。

### 1. Kilo-XOS：第一个上游全屏编辑器

**选型：** antirez/kilo，固定一个已审查提交；BSD-2-Clause。上游是单个 C 文件，
直接输出 VT100 转义序列，不依赖 curses，适合做一个轻松、可见的里程碑。

**为什么不是先做 nano：** nano 当前需要 ncurses；把 ncurses、terminfo、完整终端
语义和编辑器一起带进来，会把“先有一个好玩的编辑器”变成终端子系统工程。
Kilo 可以先用一个 port-local 的 `xos_console` 后端，不提前承诺通用 TTY ABI。

**K0 首批边界：**

- 一个前台进程、一个文件缓冲区、ASCII 输入；
- 固定 80x24 或由启动参数给定的尺寸，不调用虚假的 `TIOCGWINSZ`；
- 光标移动、插入/删除、保存、退出、简单搜索；
- 保留 Kilo 现有 C/C++ 语法高亮时，以实际画面和边界测试验收；
- 保存失败保留内存缓冲和旧文件；反复打开/退出资源回到基线；
- Escape 序列只支持客体验证过的方向键/Home/End/Delete 子集。

**K0 明确不做：** Unicode、窗口动态 resize、鼠标、多缓冲、shell 命令、信号恢复、
终端作业控制、完整 VT100/ANSI 模拟。若宿主终端不正确呈现转义序列，K0 失败，
不能用静态截图或宿主编辑器代替客体行为。

**后续：** K1 再提炼 XOS 的窄终端接口；只有第二个全屏程序也需要时才抽公共层。

上游入口：<https://github.com/antirez/kilo>。

### 2. sbase-dev0：第一组独立命令行工具

**选型：** sbase，固定提交；MIT。它是一组面向 Unix-like 系统的可移植小工具，
比 GNU coreutils 或 BusyBox 更适合逐个取用。首批构建独立 ELF，不依赖符号链接；
暂不为了节省磁盘做 multicall 分发。

**U0 建议清单：**

| 工具 | 首批功能 | 首批排除 |
|---|---|---|
| `cat` | 文件/stdin 到 stdout，短读短写 | 行号等扩展 |
| `cp` | 普通文件复制，失败保护目标 | 递归、权限、符号链接、时间保留 |
| `mkdir` | 单目录创建 | `-p` 可留 U1；mode 只解析不承诺 |
| `rm` | 普通文件删除 | 递归、交互确认、符号链接语义 |
| `mv` | 同盘不覆盖改名 | 跨文件系统、权限/时间保留 |
| `wc` | 字节/行；ASCII 词计数 | locale/Unicode 单词语义 |
| `head` | 行/字节前缀 | 多文件花哨标题 |
| `cmp` | 逐字节比较和状态码 | mmap 优化 |
| `basename`/`dirname` | 纯路径文本处理 | 不把文本处理当文件解析 |
| `env`/`printenv` | 查看和为单个程序准备环境 | 任意 shell 赋值语法 |
| `true`/`false` | 稳定状态码 | 无 |
| `cksum`/`sha256sum` | 文件校验 | mmap、大型并行优化 |

其中 `mkdir/rm/mv/cat` 与 Xsh 内建重名不冲突：Xsh 内建保留救援路径，dash 和普通
程序可通过 `/usr/bin/...` 使用独立工具。客体测试要明确自己调用的是外部 ELF。

**U1 文本批次：** `cut`、`tr`、`sort`、`uniq`、`paste`、`comm`、`nl`、`od`、
`strings`、`split`、`tee`。UTF-8/locale 只按工具实际支持声明；`tee` 与大流输入
要等阻塞/等待语义足够后再验收，不能靠偶然未填满 4 KiB 管道通过。

**不选 BusyBox 作为第一组：** 当前 dash 勘查已记录 GPLv2-only 与 Apache-2.0
静态组合问题，而且单体配置会把大量未支持接口一起带入。以后可以重新评估，
但不因为“命令多”就覆盖较清晰的逐工具证据。

上游入口：<https://git.suckless.org/sbase/>。

### 3. Lua：可选的轻量解释器玩具

**选型：** 若项目所有者想先玩脚本语言，优先 Lua 5.5.x 的固定稳定发布，MIT；
开工时复核 5.5 与 5.4 的兼容需求，不把 Lua 设为 CPython 或构建系统前置。

**L0 首批边界：** 解释器、REPL、整数/浮点、表、函数、GC、`load`、受限文件 I/O，
脚本从工作盘读取并可保存输出。关闭动态模块加载、网络、进程替换和未实现的 OS
库函数；`os.time` 等没有真实时钟的接口应明确不可用，而不是返回伪造时间。

Lua 的价值是很快得到一个可玩的解释器和 GC 压力样本；如果当时更想推进 CPython，
可直接跳过，不因菜单存在而实施。

上游入口：<https://www.lua.org/ftp/>。

## 正则与行编辑批次

### R0：POSIX 基本/扩展正则实现

`regex.h` 已随 newlib 头提供，但当前目标库没有实现。R0 应选择一个许可证兼容、
可独立测试的实现，提供实际 `regcomp/regexec/regerror/regfree`；不能只补符号。
候选优先审查 musl 的正则实现或另一套小型 BSD/MIT 实现，但要逐文件核对来源、
内部依赖和宽字符假设后再冻结，本文不预先宣称可以直接复制进 newlib。

验收包括 BRE/ERE、捕获组、回溯引用、空匹配、无效表达式、长输入、OOM 和释放；
ASCII 子集可先通过，locale/Unicode 单列未支持。

### R1：`grep`、`sed`、`ed`

正则通过后，优先从同一固定 sbase 源树移植：

- `grep`：先文件/stdin、BRE/ERE、`-F/-i/-n/-v/-c/-q` 的已测子集；
- `sed`：先地址、打印、删除、替换、分支的已测子集；不冒称完整 GNU sed；
- `ed`：作为脚本友好的行编辑器，支持读写、追加/插入/删除、打印、替换、撤销。

`ed` 不是首个交互编辑器的推荐，因为 XOS 已有一个简单行编辑器，而 Kilo 能带来
更明显的新体验。`ed` 的价值主要是脚本化编辑和复用正则。首批关闭 `!command`、
SIGHUP 恢复和其他依赖完整 shell/信号的行为；scratch 文件必须使用真实临时文件，
并在正常、错误和取消路径清理。

## 归档、压缩与传输

### A0：受限 `tar`

候选仍优先 sbase `tar`，但首批只归档/解包普通文件与目录：

- 保留路径和内容，校验 header/checksum，拒绝越界与 `..` 逃逸；
- 不恢复权限、uid/gid、设备、FIFO、硬链接、符号链接或时间戳；
- 不默认运行外部压缩程序，不用 `fork`/管道冒充 `tar -z`；
- 解包失败不能覆盖路径外文件，已产生的合法副作用如实报告。

### A1：压缩

单独选择 zlib/miniz 一类小型库及前端，先做内存块和单文件 gzip/deflate 往返。
Binutils 内部带有 zlib 不表示 SDK 已有公共压缩库；必须重新登记来源、实际配置和
链接闭包。zip/unzip、xz、bzip2 分别作为独立候选，不一次全装。

### A2：离线交换

当前没有网络，因此 tar/gzip 的第一用途是工作盘备份、源码包导入和发行附件交换。
TFTP/curl/wget/ssh/git remote 都等真实网络栈、安全边界和时钟以后再讨论。

## 构建工具

### 现在不把 `make` 误报为可移植

当前 `stat` 时间字段为零。传统 Make/Ninja 依赖文件修改时间判断是否重建；即使程序
能够编译和启动，也不能据此声称增量构建正确。dash B/C 的多层启动、重定向、管道
和取消也仍在推进。

### B0：先补正确前提

- 给工作盘文件定义真实、可持久、单调可解释的时间戳，或者明确选择内容摘要构建；
- 完成构建工具所需的子任务启动、状态收集和日志输出；
- 确定并发为 1 时的语义，不能用 `-j1` 掩盖缺失的错误传播；
- 真实验证中断/取消后不会留下被误认成成功的半成品。

### B1 选型

**首选 Samurai，而不是先冲 GNU Make。** Samurai 是 C99 的 Ninja-compatible
实现，使用 `posix_spawn`，许可为 ISC 加其参考代码的 Apache-2.0，和 XOS 现有方向
比较贴合。首批只做 `-j1`、固定 build.ninja、显式命令、depfile 关闭或受限；
并行调度、console pool、load average 和完整 Ninja 兼容另验。

选择 Samurai 意味着宿主先生成简单 `build.ninja`，不是宣称 Autotools/CMake 已在
XOS 运行。sbase `make` 可作为另一条兴趣支线；GNU Make 留到 shell、时间戳和进程
语义更完整时。三者不同时开工。

上游入口：<https://github.com/michaelforney/samurai>。

## CPython：已有规划的大项目

CPython 保持独立规划，不被 Lua、dash 或小工具阻塞，也不由本文另起实现。开工时
选择仍受安全维护的稳定版本并冻结；宿主 build Python 与目标 Python 版本匹配，
明确哪些生成器在宿主运行。

建议分层：

| 批次 | 目标 | 不声称 |
|---|---|---|
| PY0 | 交叉配置审计、核心解释器静态链接、`-c` 和纯计算 | 标准库完整 |
| PY1 | 工作盘脚本、import 纯 Python 模块、异常/GC/Unicode 基线 | 动态扩展可用 |
| PY2 | 选定内建 C 模块、文件/目录、真实 errno 和持久化 | pip/venv/网络可用 |
| PY3 | 子进程、时间、压缩等按真实需求扩展 | 线程、动态加载自动成立 |
| PY4 | 回归子集、资源压力、朋友试用和可分发材料 | 上游全测试通过 |

首批关闭或不构建 `socket`、`ssl`、`multiprocessing`、`subprocess`、`ctypes`、
动态扩展、线程等尚无底座的模块；具体列表以冻结版本的实际配置和链接结果为准。
不能为了让 `import` 成功放置返回假数据的模块。

PY0 已由 0030 完成（3.14.9，静态 ELF，7/7 客体检查），但固定哈希种子、无墙钟/
熵、无 fork/select/线程；PY1/PY2 尚未开始。证据见
[工作记录](work_log/0030_cpython_py0.md)。

官方交叉构建说明要求同版本 build Python：
<https://docs.python.org/3/using/configure.html#cross-compiling-options>。

## 终端工具的后续层级

| 层级 | 候选 | 开工条件与边界 |
|---|---|---|
| T0 | Kilo-XOS、简单 `more` | 固定尺寸、前台、有限按键；port-local 后端 |
| T1 | 公共 ANSI/按键层 | 至少两个真实消费者；定义尺寸、模式、退出恢复 |
| T2 | nano、less | curses/terminfo 或等价窄层、搜索、resize、取消通过 |
| T3 | Vim | termcap、文件交换/恢复、信号和更完整 libc 后再评估 |

GNU nano 当前上游要求 ncurses，许可 GPL-3.0-or-later；它适合 T2，不适合用一堆
空接口硬塞进 T0。Micro/Helix 分别会先引入 Go/Rust 运行与工具链，不作为当前首选。

## 其他可点项目

### 很适合随兴做

- `bc`/`dc`：计算器、脚本和大整数压力；先固定 sbase 实现及实际依赖。
- `cal`、`seq`、`yes`、`rev`：小而有趣，但真实时间不存在时 `cal` 必须显式给年月。
- `2048`、贪吃蛇、文字冒险：作为独立用户程序；不借游戏名义扩大终端 ABI。
- `diff`/`patch`：源码开发很有价值；先选小型 BSD 实现并做拒绝路径/原文保护。
- `more`：比 `less` 小；先只有前进分页和退出，不假装支持 seek/终端 resize。

### 有底座后再做

- `find`/`xargs`：需要稳定目录遍历、参数上界和启动失败语义；`xargs -P` 暂缓。
- `tar` 压缩过滤器和大型流水线：等 dash C/阻塞管道。
- `samurai` 并行构建：等并发等待、输出归属和资源预算。
- `ncurses`：至少由 nano/less/游戏中的两个真实消费者推动，再冻结 feature 子集。
- `Git` 离线子集：先需要时间、正则、压缩、diff、可靠进程/锁；网络 remote 更晚。

### 当前暂缓

- curl/wget/ssh、包管理器在线仓库：没有网络与 TLS/时钟基础。
- tmux/screen：PTY、会话、信号、终端复用尚不存在。
- 完整 Git、CMake、Meson、Autotools 原生 configure：依赖闭包过大，先由真实消费端
  逐项拉动；宿主生成文件继续是合法过渡方案。
- Vim/Emacs/Helix 完整版：可以作为长期挑战，但不适合作为第一编辑器。

## 每项移植的固定交付格式

每次只认实际证据，至少保存：

1. 上游版本/提交、原包 SHA-256、来源和完整许可证材料；
2. 构建地/运行地/目标、SDK 快照、配置、补丁和产物摘要；
3. 宿主编译、XOS 客体启动、正常功能、错误路径和资源回收分别的状态；
4. 输入、stdout/stderr、退出状态和文件副作用；可对照宿主但不由宿主代执行；
5. 明确的支持矩阵和未运行项；不把源码中存在的功能当成已支持；
6. 独立测试盘和独立输出目录；不覆盖日常盘、发布镜像或其他任务的 `build/`；
7. 对共享 libc/SDK/服务提出最小缺口；涉及内核或 dash 占用范围时停止实现并协调。

## 建议的轻松选择顺序

如果今天想看到画面：选 **Kilo-XOS K0**。

如果今天想让开发立刻顺手：选 **sbase-dev0 U0**，先从 `cat + cp + wc + cmp` 开始。

如果今天想玩语言：选 **Lua L0**；更想挑战大项目就沿既有 **CPython PY0** 规划。

如果今天想补一块长期基础：选 **R0 正则**，随后可以连续解锁 grep/sed/ed。

如果今天想做系统内构建：先做 **真实时间戳/内容摘要决策**，再开 Samurai；不从
“让 make 启动起来”倒推它已经正确。

菜单允许随时换口味。已经开始的工具只需把本批做到证据闭环，不要求把整个上游
一次移完；不好玩或收益不对时，如实记录后停在可复查的位置。
