# 0028：dash B0+B1移植

2026-10-25。目标是让可选dash在XOS内运行真实C/C++简单构建脚本，同时保留
Xshell/xsh为原生入口。本组没有替换默认Shell、安装`/bin/sh`、修改公开发行附件、
共享`build/xos.img`或日常工作盘，也没有触碰`localpilot/`。

## 实现与边界

B0新增`sys_process_delegate=37`和最大深度3的显式进程构造权。supervisor可给
building子任务配置深度；非supervisor只能给自己的直接building子任务设置严格
小于自身的深度。旧`sys_process_grant=28`仍是一层直接构造权。委派拒绝使用
`process_error_delegation=-10`，newlib映射为EPERM，避免与文件服务`-1`的not-found
混淆。

Xsh只对裸命令`dash`设置深度2。dash后端在用户态按basename识别
`x86_64-elf-gcc`、`x86_64-elf-g++`、`gcc`、`g++`，仅给这些driver的直接子任务
深度1；内核不识别名称、PATH或编译器。旧`exec-driver dash`仍只有一层权利，
因此其脚本再向GCC委派会EPERM、dash退126，building子任务被回滚且不留目标文件。

B1的admission递归放行case/NCLIST、函数定义和dot/source；参数展开继续使用
上游实现。管道、重定向、子Shell、后台、命令替换仍在执行前拒绝。固定sbase提交
`c546c3a5724c81cee9a11d816a38ccdf17472129`，加入cat/cp/mkdir/mv/rm窄移植；只承诺
普通文件、mkdir -p、同卷rename和非递归删除，不承诺递归、符号链接、权限位、
跨卷fallback或覆盖目标。

主要修改：`process_abi.hpp`、x86_64 `tasks.cpp`、loader spawn接口、新libc spawn
driver入口、supervisor的dash profile、dash admission/jobs/profile、sbase端口和构建器，
以及`tests/dash_b_smoke.py`与`tests/fixtures/dash_b/`。ELF解析仍在用户态。

## 构建与验收

使用发行冻结SDK构建两个可选端口；系统构建通过导入`build.py`并把`BUILD`显式设为
`build/dash_b_final2`，没有清理或覆盖共享build。等价的端口与验收命令为：

```sh
python3 scripts/build_dash.py
python3 scripts/build_sbase.py --sdk build/releases/0.0.1-1024/sdk
python3 tests/dash_b_smoke.py \
  --system build/dash_b_final2 \
  --dash-manifest .cache/xos_seed/dash/39f57f408a4362fda92e/manifest.json \
  --sbase-manifest .cache/xos_seed/sbase/2f27302d19f094f460d2/manifest.json \
  --report build/dash_b_final2/dash_b_acceptance_report.json
python3 tests/shell_smoke.py \
  --manifest .cache/xos_seed/dash/39f57f408a4362fda92e/manifest.json \
  --system build/dash_b_final2
python3 scripts/license_audit.py --build build/dash_b_final2
```

B gate的7项检查全部通过：旧直接driver兼容；无权委派拒绝且无副作用；
dash→GCC→cc1/as/ld；dash→G++→cc1plus/as/ld；case/函数/dot/参数展开；故意编译
失败后用cp替换源码并重译运行C/C++；五个sbase工具。每组后资源均回到
`[130336,2,0]`。同一最终系统上dash A的16项回归通过，许可材料检查通过。
用户loader改动另做AArch64第二ISA编译检查并通过；它只是编译边界检查，不是
AArch64移植或运行证据。
