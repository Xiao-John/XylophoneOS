# 0086 宪法修正案：驱动纯洁性与时基（仅文档）

2026-10-29。按宪法第1节"若确需改变原则，先取得用户明确确认并记录修订"，用户于
2026-10-29明确确认：不向内核态驱动实现妥协；不向用户态暴露与符合架构是两回事；
内核缺少必要接口不是把驱动放入内核的理由。同时要求内核统一时基，清除`pic_eoi`
中携带计时的耦合。本次仅修订`docs/xos_plan.md`第一部分并新增本记录，无任何实现、
ABI、build或冻结报告变更。

## 修订内容

- 升版v1.2→v1.3，文件头部登记修订来源与日期。
- 新增C28驱动纯洁性：设备初始化、队列与数据通路管理、传输收发属于用户态驱动服务；
  内核只保留中断递送与应答、授权MMIO、DMA资源授予、IPC与权利撤销等通用机制。
  内核暂缺所需接口不构成把驱动放入内核的理由，缺少的机制按C20论证后正确创建。
  授权MMIO为逐设备、窄窗口、显式、可撤销的授予，仅面向已认证驱动服务，普通进程
  默认无MMIO/PCI IO/DMA访问的隔离不变。内核态驱动实现为架构违规；引导、调试及
  过渡例外按C26登记范围与退出条件，不得作为交付驱动进入主线。
  C21末句"不能机械要求所有驱动用户态"的让步由C28替代。
- 新增C29时基与中断应答：内核只维护一套单调时基，由时间中断唯一写入、归属独立
  公共模块；sys_ticks、单调/实时时钟、线程deadline、驱动等待及一切超时语义由其
  同源导出。任何模块不得复制、旁路或自建计时。中断应答（EOI）、屏蔽等PIC操作为
  纯机制操作，不得携带计时、统计或其他副作用。

## 裁定影响（不追改旧证据，按C26末句）

- PR #20的内核态VirtIO-Net驱动按C28裁定为架构违规，`pic_eoi`内嵌计数器按C29裁定
  为违规。其冻结验收结果不追改，但也不默认已符合新原则；整改要求以PR #20的
  Request Changes意见另行提出。

  与C28不符，实施前须重设计为设备授权原语并重新登记；其rights、生命周期与token
  语义可沿用。
