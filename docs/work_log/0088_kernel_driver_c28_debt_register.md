# 0088 存量内核设备代码 C28 整改登记（仅文档）

2026-10-29。C28（[v1.3修正案](../xos_plan.md)）裁定内核态驱动为架构违规；C26末句
要求"现有实现的耦合按证据审查并登记整改，不因新条款追改旧验收结果，也不默认其
已符合新原则"。本记录对main现有内核设备代码做存量登记：它们是**带整改义务的
存量耦合，不是C28先例**；已合并的冻结验收结果不追改、不改绑。

## 约束

- 新设备驱动一律按C28自用户态起建；本表不构成把任何新驱动放入内核的许可。
  PR #20（VirtIO-Net）已据此裁定Request Changes。
- 迁移所依赖的设备授权原语须先经ABI登记：PR #18的frame-proxy设计须按C28重设计为
  设备授权原语（设备所有权/权利授予、MMIO窗口、IRQ递送、DMA授予、WAIT）后重新
  登记；其rights、生命周期与token语义可沿用。
- 每项迁移独立分支/PR、独立客体验收，不捆绑推进；未迁移前旧冻结报告不改绑、
  不重写，也不以本登记冒称任何迁移已开始。
- 授权MMIO按C28为逐设备、窄窗口、显式、可撤销的授予，仅面向已认证驱动服务；
  普通进程默认无MMIO/PCI IO/DMA访问的隔离（既有vector 13/14探针结论）不变。
- 本记录仅文档；未改实现、ABI、build或冻结证据。
