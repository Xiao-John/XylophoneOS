# Issue 37：客体路径误报的限定复核

状态：工具和合成负向测试通过；历史资料清理及跨机重放不因此自动通过。

路径扫描会把历史客体命令、合成输入中的绝对路径标成待审。新增的限定复核器只接受
逐文件列出的 `absolute_command` / `private_temp`，并要求：转换清单、源 Git 提交、
导出字节和根清单一致；被复核的客体字段与源提交字节语义一致；宿主命令不能残留
未模板化路径。个人主目录、身份、归档内未验证项、不可读取项均不可通过此途径。
CI 在原始扫描未通过时仅调用**基础分支**的复核器；复核器未在基础分支时仍失败。

`verify_evidence_migration.py` 分别核对来源/导出、原有索引与归档成员，按模板规则
检查非路径内容未改，并明确不声称客体重跑或 Git 历史清除。宿主 QEMU 命令模板只
替换能确认来源的 JSON 字符串；未确认的内容保留待审。工具的合成测试覆盖客体临时
路径误改、索引误绑、归档成员变化、私人路径豁免和未模板化宿主命令。

本地测试：宿主模板 11/11、迁移校验 6/6、客体复核 4/4；这些是合成测试，不是客体
资格。Issue 37 的历史 Git 对象及远端副本仍为 **OPEN**，真实跨机重放为
**MANUAL_REQUIRED**。是否使用本限定复核，仍取决于每份证据的实际源/导出核对。
旧索引如以无扩展名键引用 JSON，可显式指定固定后缀；索引校验测试 12/12，主线
threading 原报告索引 11/11 匹配。
首次本地扫描未创建输出目录而未能写回执；创建目录后重新扫描当前暂存差异通过。
