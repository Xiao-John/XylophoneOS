# 通用多通道等待基础

终端 fork 不能直接复制带 PID 授权的通道 token：新 PID 无权使用原端点；把多个
进程塞进同一应答槽还会产生错收。后续需独立子进程端点和共享前台会话，服务现有
线程预算不足以为每个端点再建等待线程。本组先为 sys81 增加通用、有界的原子多通道
等待；完整身份校验、就绪位掩码、截止、关闭及伪唤醒语义见通道契约。

内核为阻塞线程保存至多四个 token 的快照；端点事件唤醒后调用方重查，超时使用统一
单调时钟。未授予新身份、没有多进程终端实现。定向探针增加空队列、超时、重复项、
无权项及两个端点之一到达后的等待；须构建、提交后在真实客体执行。fork 会话分配、
并发读取/写入仲裁、退出回收和完整 W1/W2 仍待完成。
