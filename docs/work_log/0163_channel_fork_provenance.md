# fork 通道来源核验

终端服务登记子进程时，仅凭通道枚举中的控制者和对端 PID，不能证明请求中给出的
新端点确由当前请求者的原会话派生。新增 sys81 action 6，让原对端在子进程仍处于
fork building 状态时，使用内核保留的原端点句柄核验两个派生端点、方向、父子关系
和控制者。来源由内核记录，句柄不复用；验证不自动完成业务登记，也不能消除验证后
关闭或 abort 的竞争。通道契约说明了拒绝和生命周期边界。

定向探针拟验证对端正向核验、颠倒派生端点和伪报子进程身份被拒绝；常规构建与
交叉编译已通过，须在提交后重建并在客体执行。服务接入、撤销竞争、其他越权主体
与资源压力仍未覆盖，不能将本机制视为完整 W1。
