# ncursesw 目标库成员来源检查

2026-11-02。W2 的许可验收需要分别审视静态库成员、生成代码、头文件和 terminfo，
不能以顶层 COPYING 通过即代替逐成员审查。先针对已验证的单线程目标库建立可重跑的
来源清单，再核生成输入、实际交付数据与 newlib；未能确认的项目保留未完成状态。

新增 `scripts/audit_ncurses_members.py`：核对固定源码压缩包哈希和目标库构建回执，
枚举归档成员并将成员字节与构建对象比对，从实际编译日志取得直接编译源文件；上游
源文件逐一与压缩包内容比对，生成源列出非递归的上游生成器及直接输入，记录哈希和
许可提示是否存在。它是来源与提示筛查，不是法律结论，也不自动判断许可证兼容性。

对 `build/w2_width_ncurses_6f2be7d/` 的结果：162 个成员均有唯一编译来源，153 个
直接源与锁定压缩包一致，9 个为生成源；对象和归档成员一致。直接源及所列生成输入
除 `misc/terminfo.src` 外均有指定许可提示。报告保存在构建目录
`build/ncurses_members_6f2be7d.json`，SHA-256
`2149778de2a9319c38141f420cdc373e040a160bfcee198543a6c6ec0baef3df`。此报告绑定该次
已编译库，不自动适用于新库；脚本和报告也未证明生成输入的全部传递依赖。

上游 `terminfo.src` 文件头明确区分维护更改与部分作者不明的历史内容，也提到部分
来源于 xterm；不得将整个文件简单标记为顶层 ncurses COPYING 的同一许可。本次库的
`fallback.c` 实际生成结果是空 fallback 列表，但交付的 xterm terminfo 由该源生成，
其 `use=` 继承链和对应来源仍需单独追踪；不得据空 fallback 推断 terminfo 数据已审查。
生成头文件、编译头文件的传递来源、newlib 归档成员及发行要求也尚未完成审查。
