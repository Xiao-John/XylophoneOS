# 单通道等待中的对端关闭

2026-11-02。现有客体探针覆盖 `wait_many` 中的对端关闭和句柄重验，尚未覆盖
单通道等待。内核检查通道当前状态并登记等待均在同一内核路径；对端关闭会唤醒等待者，
等待返回 0，随后重新查询已失效句柄返回 `process_error_denied`。返回 0 不是继续使用
句柄的保证，消费者必须重验。

在既有双进程通道客体探针中保留第二个备用通道：接收端先发请求，发送端确认后延迟
关闭；接收端对该空通道执行有截止时间的单通道等待，必须先得到唤醒 0，再得到句柄
失效错误。通道从未写入数据，因此有效空通道上的该返回覆盖了等待中关闭的路径；若
关闭发生在等待登记前，首次调用会被拒绝，测试不会误报通过。维持后续 fork/exec 及
清理检查。此项不覆盖发送端因队列满而等待时的关闭，也不证明所有调度与故障组合。
提交后从对应源码重建系统与 SDK，在实际客体运行并记录证据。
