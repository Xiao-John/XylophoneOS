# libc：timespec_get、文件元数据符号与端口反馈账本

2026-11-12。来源：xxHash 与 LZ4 移植时连续撞到同一类问题——标准代码能编译却链接失败。
按“端口只反馈、OS 侧修复”的约定，本组修 libc 并把发现记入
[端口反馈账本](../ports_ledger.md)。

## 改动

| 位置 | 内容 |
|---|---|
| `src/user/libc/newlib_syscalls.cpp` | 新增 C11 `timespec_get`（sys64 纳秒、`TIME_UTC`）；新增 `utime`/`chmod`/`chown`，路径为空报 `EFAULT`，其余返回 `ENOSYS`（文件服务还没有时间戳/权限/所有权写 ABI，不伪造成功） |
| `src/user/include/utime.h` | 新增覆盖头：newlib 的 `sys/utime.h` 只定义 `struct utimbuf`，不声明 `utime()`；补上声明 |
| `docs/ports_ledger.md` | 新建统一账本，登记 `PL-0001`–`PL-0005` |
| `docs/ports.md` | 增加 8.1 节：移植发现必须登记账本 |
| `docs/e06_libc.md` | 记录 `times/clock/timespec_get` 语义与元数据符号的 `ENOSYS` 边界 |
| `tests/libc_posix_time.py` + fixture | 客体链接并行为验证：`clock/times/timespec_get` 正常，`utime/chmod/chown` 返回 `ENOSYS`，资源计数回到基线 |

`times()` 本身在基线里已经存在（`newlib_syscalls.cpp`），所以 `PL-0001` 直接标
`fixed`，由新用例覆盖。

## 边界与后续

- `clock_gettime`/`timer_*` 的声明受 `_POSIX_TIMERS` 控制，本组没有开启
  （`PL-0004` open）：开启就得同时决定 POSIX timer 的语义，不能只放声明。
- 文件时间戳与权限只有符号、没有语义（`PL-0005` open）：需要 file ABI 增加
  `set_metadata` 才能真做，按契约流程另行登记。
- 本组只覆盖 ordinary single 线程 SDK；线程 SDK 的同名符号继承同一实现，未单独跑
  线程用例。
