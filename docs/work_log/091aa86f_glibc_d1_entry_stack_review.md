# 091aa86f · D1 解释器栈边界复核

基于 #260 的 `64aa2180`。XOS 的原生主线程栈有 128 KiB。GNU x86-64
解释器从初始 `%rsp` 向下使用栈，第一条 `call` 就需要在该地址下保存返回地址。
D1 的原生准备器和共享 rtld 入口检查器使用同一个私有下界，保留 64 KiB
向下空间。最早允许的地址是此前原生测试已使用的栈中点。保留现有 16 字节
对齐、启动记录位置及其上界。实际共享解释器的完整栈使用仍待后续验收。

原生客体使用同一批受检合法 ELF，先请求在栈底以及有效下界前 16 字节准备入口。
两处均立即以 `layout` 拒绝，保留空映射、空启动记录和同一文件会话编号。
在下界地址实际切换栈并运行真实 GNU `rtld` 规则编译的 XOS 入口检查器，随后
通过真实 glibc auxv 与文件读取验收。该资格只覆盖本轮的入口准备和检查。

Python 验收入口在运行任何断言前检查 `__debug__`。`python -O` 与
`python -OO` 都实测立即退出 1。正常模式继续执行所有原绑定与客体检查。
