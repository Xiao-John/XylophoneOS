# 10da254a · glibc 工作目录与路径权限查询

`getcwd` 和 `chdir` 通过现有受认证的 XOS files 会话读取和更新工作目录。当前目录
由服务保存，已有的启动继承与相对路径解析继续使用同一状态。`getcwd` 支持调用方缓冲
区和 glibc 的分配形式。路径解析和长度检查由当前服务处理，失败沿用文件服务的错误映射。

`access` 使用真实文件元数据验证存在性、读取及 FAT 写保护。虚拟 `/dev` 不可写，
`/dev/null` 可读写。目录搜索通过服务解析路径。普通文件的 `X_OK` 在同一次
files stat 请求内完成 XOS 静态 ELF 结构检查。进程创建、描述符继承和资源配额仍由
对应的启动操作判定。

本次沿用现有的文件消息布局、加载器检查与系统调用，新增 stat 查询位与成功确认位。
FAT 采用既有的权限投影。
`faccessat`、POSIX 用户组权限和动态 ELF 属于后续工作。

## 初次实现的验证

[静态 glibc 来宾门禁](../../tests/glibc_static_guest.py) 的 `cwd` 套件接受同一系统
生成的 newlib dash 回执、常规系统镜像和经过源码签名校验的 glibc C SDK。夹具先用
现行 newlib `chmod` 写入真实 FAT 只读标记，再用 xsh 和 dash 运行同一 glibc ELF。
dash 在启动前切入子目录，用于检查初始工作目录的真实继承。两条入口都检查退出码、
路径及权限错误、UTF-8 目录和资源恢复。

Linux arm64 宿主上重新构建静态 C SDK 和正常 BIOS 系统。glibc 源码为签名验证通过的
2.44 归档。新 SDK 的 `gnu/stubs.h` 无这三个接口的 stub 声明。

## 审查后的资源生命周期

初次实现跨多次客户端 RPC 持有执行检查 pin。客户端标记会话失败后会停止发送后续
RPC。服务在客户端进程退出时回收挂在会话中的远端记录，所以检查所用 pin 可能延迟
释放。只去掉 pin 位仍会留下普通远端打开记录。

审查修复把查询限制在单次 stat 请求。服务复用纯 ELF 检查器，在回复前完成读取与关闭，
整个查询无需建立远端打开记录。实际加载仍走原生加载器的独立验证。请求与确认位分配见
[文件身份契约](../contracts/file_identity.md#可执行文件查询)。

修复后的常规 BIOS 客体上，xsh 和现行 dash 各通过两轮。检查包括对打开的写方保留
逻辑 offset、随后仍可写，以及占满服务打开配额时仍能区分原生 ELF 和纯文本。
旧服务兼容性检查验证无确认位返回 `ENOTSUP`，普通 access 仍可使用。该检查只发送
两次 stat，没有发送 open 或 close。实际 files ELF 只链接纯检查器，符号检查确认
启动入口未进入文件服务。
