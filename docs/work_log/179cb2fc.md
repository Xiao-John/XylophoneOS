# 端口规范、校验器与第一个外部样例（NASM）

2026-11-12。背景：`src/ports/` 长期只有“目录 + 各端口自述”，`source_lock.json` 存在
10 种不同形状，没有 schema、没有校验器，也没有一个可按图施工的新增端口流程。此前用
NASM 做纯客体包能力测试时，只能靠模仿旧目录和读脚本反推。本记录把这条流程写成规范，
给出机器校验，并用 NASM 做第一个符合规范的 guest-only 样例。

## 交付

| 文件 | 作用 |
|---|---|
| `docs/ports.md` | 端口规范 v1：目录契约、`port.json` 字段、`source_lock.json` 三种 kind、补丁格式、状态阶梯、配方契约（离线 + 环境变量）、证据要求、迁移表 |
| `scripts/ports.py` | 校验器：`check <dir>` / `check --all` / `--json`；只做结构检查，不构建、不联网 |
| `src/ports/README.md`、`src/ports/_template/` | 上手步骤与可复制模板（模板目录被校验器拒绝直接校验） |
| `src/ports/nasm/` | 首个样例：`port.json`、`source_lock.json`、离线配方 `build.py`、自带汇编样例、空 `patches/` |
| `docs/reports/nasm_2_16_03_20261112/README.md` | 客体证据：安装事务、`nasm -v/-h/-f bin/-f elf64`、错误路径、产物字节与哈希 |
| `tests/ports_manifest.py` | 14 项：全树通过、模板拒绝、9 个字段级反例、合法 git 补丁接受 |

## 关键决定

- **只约束带 `port.json` 的目录。** 13 个历史端口不批量改写；迁移表登记，
  `nasm` 是第一个迁移完成的目录。这样规范可以立即生效，又不制造旧证据改写。
- **状态词固定为八个**（`planned` … `retired`），升级条件与证据门槛绑定，避免
  “已通过”式无证据声明。`guest_verified` 要求客体命令、原始输出与产物哈希。
- **配方离线且输入显式**（`XOS_SDK` / `XOS_SOURCE_ARCHIVE` / `XOS_OUT`），
  产物固定为 `<package>-<version>.xpk` + `build_receipt.json`，配方不得联网。
- **`source_lock.json` 按 kind 分三种形状**：`tarball`、`git`、`component_set`；
  只从镜像取得哈希时用 `sha256_scope: mirror_fetch` 显式标注，不允许装作已与
  上游发布页比对。
- **`guest_only` 强制为空 `bootstrap_images` / `iso_members`**：端口默认不改 OS。

## 验证（本机实测）

```text
python3 scripts/ports.py check --all --json   # passed，1 个端口
python3 scripts/ports.py check src/ports/_template
  -> 退出 1：模板目录不参与校验
python3 tests/ports_manifest.py               # 14/14 PASS，报告 build/ports_manifest.json
```

样例的客体证据来自 2026-11-12 的 NASM 能力测试：零源码补丁（上游 1190 个文件逐字节
一致），`thirdparty.nasm-2.16.03.xpk` sha256
`0b7940222df8c08fe76ccb289b7117b35fd7690afe52cbf05825416a54a88d11`，
在系统 build `0d9e4e844e51f7b5` 上 `verify-installed = verified`，客体产出
`b8 34 12 cd 10 f4` 与合法 `REL` 目标文件。

## 未做 / 边界

- 13 个历史端口未迁移；规范对它们不生效，仍需各自 README 维护。
- `scripts/ports.py` 只校验结构与一致性，不验证 `xpk_sha256` 是否真等于某次构建；
  那需要重跑配方。
- 配方在 CI 上没有入口（需要外部 SDK 与归档）；本记录只保证按 README 手工可复现。
- NASM 样例未跑上游测试套件、未构建 `ndisasm`、未测 dash 路径；见端口 README
  的“已知限制”。

## 后续

1. 把 `python3 scripts/ports.py check --all` 接进常规检查（与 `abi_doc_consistency`
   同级），防止新端口漏字段。
2. 逐个迁移历史端口时不改旧证据：先补 `port.json` 与锁文件 kind，再逐步补证据。
3. 若要支持“外部开发者自助”，还需修公开交付面（SDK 缺宿主事务后端、
   `adopt_sdk.py` 只产 local profile）；这两项与端口规范分开处理。
