# 控制台 `read()` 阻塞与 CR→NL

2026-11-13。来源：bc 端口反馈（账本 `PL-0015`）。交互式 bc 在 xsh 的 `exec-file`
下读 stdin 时报 `read() in flex scanner failed` 并以 2 退出。

## 根因

- 内核 `stdio_read`（`src/kernel/arch/x86_64/tasks.cpp`）在控制台无字节时返回
  `process_error_would_block`；旧 `sys_read` 则返回 0（EOF）。
- 内核没有控制台等待原语，`sys_pipe_wait` 只对 pipe 有效。
- libc `read()`（`src/user/libc/newlib_syscalls.cpp`）把控制台的 `would_block`
  映射为 `EAGAIN`，注释明确写着保留非阻塞行为。
- 因此 `read()` 返回 -1/EAGAIN，flex 视为致命错误。

## 改动

`src/user/libc/newlib_syscalls.cpp` 的 `read()`：

- 控制台（kernel 句柄）在 `would_block` 时：`O_NONBLOCK` 直接 `EAGAIN`；否则用
  `sys_sleep_until(now + 1ms)` 让出并重试，直到有字节（阻塞语义）。
- 读到字节后把 `\r` 映射为 `\n`（旧控制台没有行规程；shell 自己处理 CR，不走这里）。
- 管道路径保持原有 `sys_pipe_wait` 逻辑。

## 验证

- 新测试 `tests/console_read_guest.py`（hardened 基线 build `28fdb08274416167`）：
  发送按键前 `read()` 不返回；发送 `ab\r` 后得到 `read=3 61 62 0a`。
- bc 1.08.2 用修复后的 SDK 重建：交互 `2+3` 输出 `5`，`quit` 正常退出。
- 未改内核 ABI；`O_NONBLOCK` 行为保留。

## 边界

- 1 ms 轮询意味着最多 1 ms 输入延迟、空闲时每秒约 1000 次唤醒；后续可换成
  串口 IRQ 事件驱动的内核阻塞读取。
- 控制台没有回显（终端服务 `tty-run` 才有行规程）。
