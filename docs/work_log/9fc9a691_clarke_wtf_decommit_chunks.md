# ClarkE WTF 分段撤回已提交页

基线 `7a3bab82`，修改 `9fc9a6918aba98770c198611b6e83ed5c18c121c`，
带实际提交打点的夹具 `e181b87c`。现有匿名 VM v1 单次 decommit 接受最多
4096 页。WTF 的 `PageReservation` 可通过多次较小提交达到更大的已提交区间，
然后在一次 `decommit` 中撤回整段。此前把整段交给单次 syscall，内核拒绝后进入
发布断言。

当前分配器在首个变更前检查完整地址区间和舍入，使用 SDK 的原生页大小，
按现有 4096 页限制分次发出真实 decommit。合并调用由调用方维持所需的区间
同步。每段仍由内核维持自身的失败原子性。出现原生拒绝时沿用发布断言，
避免将部分完成伪装成整次成功。虚拟保留持续存在，重新提交仍由内核提供零页。

## 实际对照

同一已绑定 WPE、ICU 和 glibc C/C++ SDK 分别链接两份静态 ELF。首先重建目标
`OSAllocatorPOSIX.cpp` 并核验 ELF 对象，随后在独立 173 成员归档中仅替换
该成员。控制使用原归档。两个 ELF 的源夹具及其它输入相同。
QEMU 11.1.2 的常规 Xsh 系统 `27b469b7e3c35968` 运行两份 ELF。

两个程序都成功提交 4096 页再提交 1 页，实际读写两端及边界，核对逐次计费，
输出 `CLARKE_WTF_VM_SPLIT_COMMITTED`。控制随后进入 `abort`，客体报告
`kind=faulted`（vector 13），故完整夹具按预期失败。修复版一次 WTF
decommit 撤回全部 4097 页，计费恢复基线。首尾页重新提交后均为零，释放后可
精确保留原完整区间。最终退出 0，资源前后均为 `[129698, 3, 1]`。
