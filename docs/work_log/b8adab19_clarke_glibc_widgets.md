# ClarkE with glibc Qt Widgets

Source commit `b8adab19f50009ef0c4db0ea04102e2b8240de15`. The build uses
the existing ClarkE application, Aurora styling, XOS QPA, liteHTML/Gumbo and
native v2 HTTP provider. The official application and package entries remain
`/usr/bin/clarke.elf` and `xos.clarke`. Build and package commands are in the
[ClarkE contract](../contracts/aurora_browser.md#explicit-glibc-candidate-build).

## Local file compatibility

An initial glibc guest reached the real Qt window and rejected the admitted
start page. An independent QtCore probe on the same image measured
`access(F_OK)=-1/ENOSYS` and `QFile::exists()=false`. POSIX stat, open, fstat
and read succeeded on the 699-byte page. Qt opened and read the file directly,
but its size query reported zero. The diagnostic serial SHA-256 is
`02d69fd1f218b03d395410ab6d620187ef6f2ff6d27164f791d97325606f243b`.

ClarkE now tries the requested path first, checks stat for ENOENT before
using an installed built-in, and uses fstat on the open regular file before
reading. The bounded read continues to detect growth. The updated source
also built from a fresh directory using the existing newlib browser build
entry and its previous C++/Widgets toolchain. The resulting ELF has SHA-256
`94ff99ad5d184c846988d161ae85539167ece433b71cb7209cf56c189c9ea87d`
and the build receipt has SHA-256
`d4374b3941a7711fcfea3d74f642f3d621308b365a956549ffe04445f5f6b1c9`.

## Controlled native HTTP guest

The network run used QEMU 11.1.3 on the lwIP-enabled system
`7ff8eba2295e9bf9`. The supplied source tree and artifact set matched the
system manifest. The three native network ABI headers matched the app build
receipt and the system's recorded source digests. The lwIP 2.2.1 source
archive SHA-256 was
`83729c274c499d3348e9fbbe043a3113f3fa8953e7efddc7c21c7fcbb1f2b7b1`.

The same glibc ELF passed nine HTTP check groups. A local host server
observed 13 GETs with the expected authority and connection close. Three
launch cycles returned fresh HTML, CSS and BMP bytes with verified digests.
The scanout contained the expected stylesheet colors, text color and BMP.
The browser rejected a cross-origin stylesheet, a local-file stylesheet
from an HTTP document, HTTP 404 and a truncated response. The guest
returned to the same resources after each launch and reported normal
network-service close.
