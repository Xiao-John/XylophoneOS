# ClarkE WebCore 跨进程软件位图

在 #322 的单进程原生共享页基础上，加入一条受监督进程间的位图借用。生产者使用
`allocate_for_xos_transfer` 和真实 `SharedMemoryHandle`。持有者映射同一块内存，
用软件 Skia 读写 `ShareableBitmap`。端点的对端身份来自内核。委派按读或按读写缩权，
管理关闭依旧由生产者执行。协议与释放边界见[专项说明](../../src/ports/webkit/page/shared_memory_transfer_xos.md)。

普通 QEMU 11.1.2 BIOS 镜像 `4ee994892cab2a88` 上，xsh 普通入口三轮分别通过只读像素、
写者更新后生产者读到同一像素、持有者先退出，以及生产者先退出四种用例。每轮的四个真实
子进程分别有独立 PID。内核日志确认各子进程与对应生产者的地址空间不同。双方分别检查
错误对端和残留本地视图。结束时的空闲页、任务和完成项均为 `129696 / 3 / 1`。
`exec-file` 对照按既有零创建权规则返回 `EPERM`，资源恢复至相同基线。用相同后端和
镜像重链 #322 的本地位图用例，另过三轮。

最先两次诊断使用受限入口，分别在 `fork` 和 `posix_spawn` 处提前退出。转到普通入口后，
首轮通过了持有者的只读位图读像素，但在映射及释放回执处终止。原生端点每个方向只
容纳一条待取记录，持有者完成后可在前一条回执仍在队列时尝试发出释放。当前实现遇到
满队列时按单调时限重试。早期客体串口和最终通过结果均已归档。

实测源码 `286054d7` 组合了主线 `f09f2f7f`、#319 图形构建配置 `6cce7095` 和
#322 `7e3a6ade`。#319 后续 `e176327f` 禁用 CMake 中的 WebGL 和 WebGPU 绑定。该
预期组合继承 #322 与 #319 的汇总说明合并冲突，保留两份说明即可合成。同一锁定发布档
在零 fuzz 检查时拒绝新图形补丁里 `OptionsJSCOnly.cmake` 的第 2 个区块。预期树和
该依赖失败另有记录。依赖修正后仍需在新组合上实际重建与验收。

本轮检查单 grant 的受信进程对。通用 WebKit2 消息、长驻持有者的独立撤回和多 grant
视口属于后续验收。所有通过及早期失败回执见[证据索引](../reports/clarke_webcore_shared_memory_transfer_20261127/manifest.json)。
