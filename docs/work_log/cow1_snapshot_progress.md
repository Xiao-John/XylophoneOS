# COW1 隔离 fork 探针（定向验收通过）

基于 COW0 `462d4fe`。`--vm1-probe --cow1-probe` 在隔离构建中提供私有
opt-in：fork 分批暂存引用和独立子页表，完成继承后发布父子 COW 映射并刷新
TLB；用户写故障按引用数原地恢复或复制。R/RX 和已提交的 NONE 页保留内容；
普通构建仍使用 eager fork，不新增公开 syscall 或 SDK 能力声明。

隔离镜像 `5dedee8cfa03987a` 的真实用户态测试通过两轮：父子孙写隔离、栈和匿名
映射、NONE 恢复、128 页共享的唯一物理页统计、fork 页表分配逐点失败及资源回归、
COW 写故障 OOM 和真实只读写故障。镜像 `f4d27c266b3107c5` 补充验证了 TLS/堆
父子双向隔离，以及父在 prepare 后写入、子尚未提交时 abort 的内容和资源回滚；
同时通过准备、发布两阶段的取消和资源回收。内核自检覆盖 R/RX/NONE、三代引用、父地址空间先销毁、
ref=1 恢复、分配失败和资源归零；父地址空间销毁并不等同真实父进程先退出。
镜像 `853edc9eca95b3a4` 进一步通过 fork 子进程 `execve` 后父进程数据保持和资源
归基线的测试；首次尝试 `execl` 因当前 libc 未导出该符号而链接失败，改用已有的
`execve` 后通过。
镜像 `2afa9a42a80c383f` 进一步验证 files 服务已 retain 描述后 ACK 失败、libc
abort 和父文件描述可用及重试；引用获取前分别在第 0、1、8、32、64 项注入失败；
未找到可执行文件时 exec 失败保留旧图；单条用户写指令跨越两个 COW 页。每项均在
真实客体运行，退出后物理页、任务和完成记录回基线。128 页共享样例中，等待子进程时
唯一用户物理页从 655 增至 659；这个样例不是性能基准。
镜像 `494b9c2d4434a290` 完成每个引用获取位置的失败扫描，两轮均在第 130 项首次
成功；真实 CPU RX 执行和 NONE、NX、未映射 guard 的异常也通过。默认镜像和同源码
eager 对照分别通过启动隔离及 VM3 libc 回归。

探针定向验收不代表 COW 已可向普通 fork 发布。现有 `finish_task` 递归终止子进程，而 COW0 验收
矩阵要求父先退出后的子进程场景；路线已增设 COW-L1/L2，保留现有行为直至完成生命周期
和任务域迁移，真实父先退出场景作为 COW-L2/COW3 的出口。
其他 files/FD 耗尽位置、内核跨页写回及完整 exec 失败矩阵仍未逐项验收。
探针内核写回当前逐页分离：后续页只读或 OOM 时前面页可能已经分离，错误分类亦
未达到 COW2 契约；多线程 profile 在 opt-in 后被拒绝，pin 和其他写回入口仍需完整
设计与验证。不得以此探针开放普通 COW fork。

COW0 基线源码扫描 `--check` 会因本阶段修改受审计源码报告漂移；需为新版本重新
审计所有写回路径，不能覆盖历史基线报告。
