# e55d60c9 · ClarkE Skia 的 FAT 文件流

在 `4706cc77` 基线隔离开发。之前的 Skia `makeFromFile` 无法装入锁定 DejaVu 字体，
改用整段内存数据曾通过。按同一普通镜像与同一份 FAT 文件复核，`fileno` 正常得到
描述符 `3`，`fstat` 和 `SEEK_END` 均为 `757076` 字节。请求 `8192` 字节的一次
`pread` 返回 `3798`，三次定位读取补齐 `8192` 字节，与 `fread` 逐字节相同。
stdio 的位置保持在 `11`。当时原版 `SkFILEStream::read` 只返回 `3798`，原版
`makeFromFile` 仍拒绝此字体。EOF 返回 `0`，超过原生位置边界返回 `EOVERFLOW`。
原始失败与上述复核报告保留在本目录的证据索引中。

在锁定 WPE WebKit 2.54.2 归档的 Skia POSIX 文件层中加入 XOS 专属补读。每次以
已经读取的字节数推进定位值，遇到 EOF 停止。首次错误返回原有失败标记，已经取得
部分数据后返回进度。切换下一偏移前检查加法和 `off_t` 表示范围。实际读取仍通过
现有 glibc 和文件服务。锁定构建将补丁先复制到私有生成目录，按精确上下文应用，并
记录编译后的 POSIX 源摘要。普通软件色块及文件流探针均链接相同的 Skia 归档。

锁定 Linux arm64 工具实际重建了 520 个 Skia 源，核对 17 个工件。以 `e55d60c9`
重建普通镜像 `6d8100cd8904de18`，再以 #292 合成树 `a56113f2` 重建普通镜像
`c8848035d68a24c2`。两张镜像均以 QEMU 11.1.2 验证软件色块、原装
`makeFromFile` 路径、字形 `59 / 50 / 54` 和 275 个非白像素。定位测试核对完整
`8192` 字节、读到尾部仅返回 `17` 字节、EOF 和零长读、原生允许及拒绝的上界，
还核对 stdio 与原生描述符的位置未改变。缺失字体退出 `3`。两张镜像均回到
`129709 / 3 / 1`，10 项许可材料与 ABI 表通过。旧归档仍能以原命令只运行色块。

以含 #288 和 #289 的主线 `d7c56292` 合成 `02a2ee25` 后，重新构建普通镜像
`0b924a05c940fbe0` 并以 QEMU 11.1.3 复验。色块、真实 FAT 字体、定位读边界、
缺失文件和资源回收均通过，ABI 表一致。目标 Skia 和字体工件仍采用同一份锁定记录。

波及范围是 Skia 软件文件流和字体绘制。完整 WebCore 页面、字体目录策略及 Qt
视口各自验收。由 [证据索引](../reports/clarke_skia_file_stream_20261126/manifest.json)
核对目标回执、guest 原始日志摘要和已验证的源码树。构建和重放命令见
[Skia 软件栅格入口](../../src/ports/webkit/raster/README.md)。
