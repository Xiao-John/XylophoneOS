## 第一部分：设计原则

### 1. 效力与冲突裁决

| 内容 | 效力 | 与实现冲突时的处理 |
|---|---|---|
| 本部分已确认的C类原则 | 约束架构、产品方向与证据表达 | 按原则裁定违规，修正实现；若确需改变原则，先取得用户明确确认并记录修订，不用登记表豁免 |
| 已批准的专项契约 | 在原则边界内规定接口与行为 | 先识别契约违约或兼容变化；按契约修正实现，变更契约需记录影响/版本/验收，不能悄悄追认旧错误 |
| 第二部分及state/ABI登记 | 描述当前实现、状态、分配和证据 | 核对源码与冻结证据后更新过期登记；实现存在不等于正确或已验收 |
| P建议 / O开放 / D暂缓 | 尚未批准的实现选择/待决项/当前不推进 | 不得单凭P/O/D裁定实现违反已确认架构，也不得因写入计划宣布已实现 |
| history/reports | 历史摘要/冻结输入与结果 | 不支配当前架构，不改写原证据以迁就当前实现 |

同一问题可同时存在实现违反原则、登记描述过期两种错误，应分别处理。仅凭文档旧状态
不能撤销真实运行结果；仅凭源码有函数不能登记通过。无法裁决时记录具体冲突与证据，
继续不受影响工作；只有涉及未获授权的原则变化才请用户决定。

### 2. 已确认方向

| ID | 已确认原则 |
|---|---|
| C01 | 微内核方向。内核提供隔离、线程/地址空间、受保护IPC、等待/中断和资源生命周期机制；文件/终端/装载与应用策略原则上在用户态。引导调试临时设施明确边界，不借机扩大内核业务。 |
| C02 | x86-64为当前目标，不并行建设第二ISA运行端口。第二ISA编译检查仅用于发现耦合，不能称为移植成功。 |
| C03 | NASM处理必要架构边界，普通核心逻辑使用受限C++。固件/ISA/平台/通用内核分别组织；应用运行库不套用内核语言限制。 |
| C04 | 主线是non-AI OSdev；AI、Linux对照、论文、商业化不进入版本关键路径。 |
| C05 | 分别证明独立启动、用户隔离、工具运行、原生编译、系统重建和编译器自举；任何一项不能冒充另一项。 |
| C06 | 工具链主线为GCC/G++：宿主交叉→XOS原生Seed→系统内开发/重建→按实际条件自举和升级。仅要求C/C++及必要配套。 |
| C07 | TinyCC不是主线；XCC非必需，不阻塞现有GCC/G++或其他移植。 |
| C08 | 为自己和朋友建设可玩、可用的系统；研究失败、Linux更快或没有论文都不构成停止条件。 |
| C09 | 复用成熟工具和用户态组件，不为原创性重写编译器或提前搭建通用大框架。 |
| C10 | 新自研代码Apache-2.0；历史MIT与第三方原条款保留。固定来源/哈希/补丁，发行保留声明；材料检查不冒称逐成员法律审计。 |
| C11 | 随实际模块落实版本、可信身份、授权边界、生命周期、资源归属、故障与可观测性，保留未来研究空间；不提前实现AI平台。 |
| C13 | Qt为GUI主线，SDL为次选；QtCore、QtGui/QPA、Widgets、QML、Quick分阶段、分证据推进。SDL不作为Qt前置。C12的SDL优先方向已由本条替代。 |
| C14 | xsh/Xshell保留原生默认入口与交互定义权；dash是可选程序，不替换xsh，不自动安装为/bin/sh。标准Shell兼容面与xsh产品设计分开。 |
| C15 | 公共线程为1:1内核线程、首版单核抢占；生命周期、隔离等待、pthread/线程安全运行库与应用接入分别验收，不以单线程假锁替代。 |
| C16 | 第三方应用使用版本化SDK独立开发/安装，不以修改内核或启动清单为常规入口；包安装、ELF可装载性、执行权限和程序启动分开。 |
| C17 | 包管理器定名xypm；不保留xpm/xpkg入口，容器仍为.xpk。 |
| C18 | 原则与事实登记分离。审计按本节裁定架构违规，按实现及证据修正登记，不以改状态消除违规。 |
| C19 | 新开发通过独立分支和PR交付，不直接推main；保留真实作者、旧冻结结果与可追溯来源。 |
| C20 | 新机制进入内核前，说明现有机制或用户态实现为何不足，以及调用主体、权限、资源生命周期、失败行为和架构假设；移植方便或syscall数量多少不能单独决定入核。该要求是设计理由，不增加既有授权范围内的逐接口用户审批。 |
| C21 | IPC、调度与进程管理提供通用机制，不解释显示、文件、包管理等服务的业务协议/状态。服务策略留用户态；中断、设备隔离与必要硬件访问及安全校验可以在内核，不能机械要求所有驱动用户态。 |
| C22 | 授权依据内核认证的调用主体与受控授予的对象/操作权利；程序名、路径、自报身份或请求内容本身不授予权利。委派不能扩大原权利，撤销/退出后的旧身份与句柄不得误指后来对象；不因此预设完整capability框架。 |
| C23 | 通用语义与ISA表示分开：寄存器、页表、异常现场、调用指令由架构适配；共享ABI明确宽度、布局、地址含义、版本及架构范围，不泄漏内核内部对象表示。允许当前ISA专属二进制profile，不承诺跨ISA二进制兼容或立即建设第二ISA。 |
| C24 | 分层按实际依赖裁决，不按目录名或是否含汇编裁决。通用机制不能仅因当前目标是x86而长期归入arch；core只依赖实际使用的窄语义接口，ISA操作与平台设备经明确边界组合。审查类型、构建依赖和隐含架构假设，只为现实需要增加抽象，不预建空HAL。 |
| C25 | 服务退出/故障后，内核按契约处理隔离、资源与失效引用；客户端能观察失败或结果未知，不伪造成功或擅自推定请求未执行。重启、重连、业务事务/状态恢复属于用户态策略，是否支持须独立声明与验收，不自动承诺透明恢复。 |
| C26 | 引导、调试及过渡例外须登记必要性、范围、负责人和退出条件。例外只能在既有原则允许范围内使用，登记不等于豁免；实质改变原则须用户事先明确确认。现有实现的耦合按证据审查并登记整改，不因新条款追改旧验收结果，也不默认其已符合新原则。 |
| C27 | 系统内可由Shell启动的工具，应尽可能分别在xsh和dash下进行真实客体验收，覆盖适用的主要用法及受影响的错误和退出行为；分别记录入口、环境、结果和证据，一方通过不代表另一方通过。Shell内建命令、宿主工具或因接口限制无法在某一Shell运行的情况，明确记录不适用或未验及原因，不伪称双验收。新原则不追改历史证据，后续新增或变更工具按适用范围落实。 |
| C28 | 驱动纯洁性。设备驱动（设备初始化、队列与数据通路管理、传输收发）实现为用户态驱动服务；内核只保留中断递送与应答、授权MMIO、DMA资源授予、IPC与权利撤销等通用机制。不向用户态暴露接口、内核暂缺所需机制，均不构成把驱动放入内核的理由；缺少的机制应按C20论证后正确创建，不得以错误实现位置回避创建。授权MMIO为逐设备、窄窗口、显式、可撤销的授予，仅面向已认证驱动服务；普通进程默认无MMIO/PCI IO/DMA访问的隔离不变。内核态驱动实现为架构违规；引导、调试及过渡例外按C26登记范围与退出条件，不得作为新增或扩展内核态业务驱动的交付依据。修订前已在主线的存量违规按C26登记整改，不追改旧证据，也不因此成为合规先例。维持内核隔离、调度和时间管理所必需的最小中断控制器、时源读取与时钟事件配置属于内核基础设施，其必要性和边界按C20论证；不据此容纳通用设备数据通路或把RTC外围功能整体纳入内核。C21末句"不能机械要求所有驱动用户态"的让步由本条替代。 |
| C29 | 时间域与中断机制分离。系统单调时间及其deadline由统一时间管理机制定义和提供；各模块不得私自维护或校准另一套替代系统时间的基准。允许多个硬件计时来源及显式定义的时间域，其单位、起点、单调性、调整与暂停行为，以及必要的转换关系须有契约；不同时间域不得未经转换直接比较或混用。墙钟校时不得破坏单调时间及其等待语义。应用逻辑时间、设备计数与诊断测量可以独立存在，但不得冒充系统时间或擅自替代系统等待期限。中断应答、屏蔽等机制与时间推进分离，不得隐式更新系统时基或夹带业务策略；诊断观测不得改变其功能语义。实现边界见[时间域契约](contracts/time_domains.md)。 |
| C30 | 命名归属与严格snake_case。上游迁移代码按上游命名惯例保留，不改名。自有代码命名必须严格snake_case；唯一例外是上游接口强制兼容的名称——上游代码迫使自有代码改变命名方式时（例如QPA插件可能覆盖的虚函数方法，上游签名要求Camel形式时可沿用）。除此之外不得以生态一致性、风格偏好等任何理由偏离snake_case。 |
| C31 | 建设基础，而非制造已经完成的假象（Build the foundation, not the illusion of completion）。完成工作的过程中，致力于铺好所需要的、坚实的、可长期复用的底座；不为图省事只选一条最简单、却对未来工作价值有限的实现路径，再把表象当完成交付。完成以可复用的基础能力和真实证据为准。与C09互补：C09反对无谓重写，C31反对以捷径冒充完成。 |

### 3. 实现与验收底线

- ELF解析、PATH搜索、脚本/装载策略在用户态；内核不识别Qt/dash/编译器名称来授予权利。
- BIOS/UEFI原始结构和调用留在引导器；ISA寄存器/页表/汇编留arch，板级端口/设备留platform。
- 指针、长度/溢出、权限、所有者和资源生命周期必须校验；失败真实返回，未实现不能永远成功。
- 文件描述符是对象引用，不靠重开路径模拟共享打开描述；正常同步持久化与任意断电安全分开。
- 新ABI先登记分配、责任与状态，再同步共享头/SDK/服务/manifest/定向测试；已发布或已验编号
  不静默复用。Qt等用户态消费者复用通用机制，不建设应用专属内核ABI。
- 验收绑定实际源码、SDK、镜像、工具、环境和夹具；pass/partial/fail/not_run分别记录。
  旧报告不改绑，新组合不借用旧全量资格；不因文档重组重跑无关测试，压力专项另行负责。
- `localpilot/`独立，不修改、递归扫描、清理或纳入构建；只操作专用测试镜像。
- 保持轻松开发，允许小而可关的无害彩蛋；不吞错误、随机破坏、制造延迟或篡改权限/数据。
